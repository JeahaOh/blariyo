# 기능 명세 산출물 계약

기본 산출물은 `<feature-slug>.dev.md` 하나다. 파일명은 lowercase kebab-case를 사용하고
`docs/development-specs/<milestone>/<feature-slug>/`의 기존 파일을 갱신한다.

## 공통 정보

문서 상태(`초안`, `작성 완료`, `차단`), milestone, 기능, 갱신일, 입력 근거 링크와 미검증 증거를 기록한다.
`작성 완료`는 문서 완료이며 구현·배포 완료가 아니다. 절별 차단이 있으면 문서 전체의 완료로 덮지 않는다.

## 내용 구성

1. 목적·범위·행위자·진입 조건과 정본 링크.
2. 확정 요구사항과 기능 내 API·흐름·화면 절의 연결.
3. API 고유 계약: consumer/provider, method/path, 업무 검증·정규화, 상태·transaction, 권한·오류·부분 실패·재시도.
4. 처리 흐름: 정상 순서와 대안·실패, 호출 API, 완료 조건. API가 없으면 그 이유를 명시한다.
5. 화면/프로그램: route, 진입/이탈, 구성·이벤트, loading/empty/error/권한/부분 실패, 반응형·접근성·메시지.
6. 수용 검증과 미정·차단·미검증 항목.

해당 없는 절은 생략한다. 원본 API 정의에 없는 계약은 생략하지 않는다. OpenAPI가 있는 기능은
타입·필수 여부·필드 전체 표를 복제하지 않고 해당 계약을 참조하며, 데이터 매핑·업무 제약만 보충한다.
M1/M1.5처럼 아직 전용 OpenAPI가 없는 기능은 요청·응답·필드·오류 계약을 기술 정본 또는 기능 절에 보존한다.
M0 Core와 M0 수집 보조는 각각 기존 OpenAPI를 참조한다.

문서 내 anchor는 `api-<operation>`, `d01-<process>`, `d08-<screen>`처럼 안정적인 값을 유지할 수 있다.
이 이름을 별도 파일 경로로 해석하지 않는다. 예시는 설명에 필요한 경우만 두고 credential·개인정보를 쓰지 않는다.
공통 정의·법무 본문은 담당 정본으로 링크한다. Mermaid와 별도 산출물을 형식적으로 추가하지 않는다.
