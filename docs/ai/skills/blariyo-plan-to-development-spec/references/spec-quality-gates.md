# Blariyo 개발 Spec 품질 게이트

## 1. 산출물 구성

- 개발 보강서가 있고 기능의 milestone·범위·출처·결정 상태가 기록되어 있다.
- API가 있는 작업은 작업별 API Spec이 있고, API가 없으면 빈 파일 대신 `API 해당 없음` 근거가 있다.
- 업무 흐름별 D01과 화면·프로그램별 D08이 분리되어 있다.
- 파일과 디렉터리 이름이 산출물 계약의 lowercase kebab-case 규칙을 따른다.
- 모든 문서의 상태가 `초안`, `작성 완료`, `차단` 중 하나이며 공란이 없다.

## 2. 제품 범위와 추적성

- 기능과 milestone이 planning의 범위를 확대하거나 축소하지 않는다.
- `M0 Core`, `M0 수집 보조`, `M0 자동 수집`, `M1`, `M1.5`와 후속 기능이 한 Spec에 섞이지 않는다.
- 개발 보강서의 확정 요구사항이 API·D01·D08의 적절한 항목으로 추적된다.
- D08의 사용자 동작이 D01 단계와 API 작업 또는 `API 해당 없음`에 연결된다.
- `(미정)`, `__PLACEHOLDER__`, `[입력 필요]`, `[출시 차단: ...]`을 근거 없이 제거하지 않는다.

## 3. 기술 계약 정합성

- D01의 호출 순서와 API consumer·provider 경계가 system-design의 컴포넌트 책임과 일치한다.
- D01·API의 데이터 상태 전이와 `docs/system-design/02-data-model.md`의 상태·제약이 일치한다.
- API field·validation·오류·인증·멱등 계약이 공통 API와 보안·운영 규칙에 맞는다.
- D08의 field, 이벤트, 메시지와 API request·response가 서로 대응한다.
- 공통 envelope, 인증, 상태와 운영 계약을 기능별 Spec에 불필요하게 복제하지 않고 상대 링크로 참조한다.
- 정본에 없는 endpoint, field, table, 상태값, 오류 코드와 제한값을 생성하지 않는다.

## 4. 실패와 사용자 상태

- 정상 흐름뿐 아니라 validation, 권한, 충돌, timeout, 부분 실패와 재시도를 정의한다.
- D08에 loading, empty, error, 권한 없음과 부분 실패 중 적용되는 상태가 있다.
- 되돌리기 어려운 삭제·상태 전환에는 확인, 중단과 복구 조건이 있다.
- 외부 서비스 장애가 공개 읽기나 다른 독립 기능에 미치는 영향을 구분한다.
- 로그·예시에 raw body, credential, token, 개인정보와 권리자 소명 원문이 없다.

## 5. 실행 증거

- Spec 작성과 source·migration·OpenAPI·test·build·runtime·배포 상태를 분리한다.
- 현재 실행 산출물을 확인하지 않았으면 구현 준비 완료나 테스트 통과로 쓰지 않는다.
- contract·integration·UI·접근성 테스트 항목은 검증 시나리오로 남기되 실행하지 않은 항목을 통과로 표시하지 않는다.
- 과거 worklog, 링크 정상, 정적 HTML과 문서상 PASS를 현재 실행 증거로 재사용하지 않는다.

## 6. 문서 안전성

- 같은 사실은 planning, legal, system-design, development-specs 중 한 책임 문서가 소유하고 다른 문서는 링크한다.
- 상대 링크가 실제 파일을 가리키며 Markdown 표·코드 블록·Mermaid가 깨지지 않는다.
- 기존 사용자 변경과 범위 밖 파일을 보존한다.
- `git diff --check`가 통과하고 의도한 파일만 변경됐다.

## 보고 판정

| 상태 | 의미 |
| --- | --- |
| 작성 완료 | 요청한 Markdown Spec과 문서 검증이 끝났다. |
| 초안 | 일부 계약·결정·동기화 또는 문서 검증이 남았다. |
| 미검증 | Spec은 있으나 source·test·runtime·외부 상태를 확인하지 않았다. |
| 차단 | 제품 결정, 실값, 권한, 법무 또는 상위 기술 계약이 필요하다. |

`미검증`은 실행 증거에 대한 판정으로 문서 상태 `초안`·`작성 완료`·`차단`과 함께 보고할 수 있다.
`작성 완료`는 구현 완료나 배포 준비 완료를 뜻하지 않는다.
