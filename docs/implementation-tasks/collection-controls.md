# 수집 통제 task

수집 기능을 운영 활성화하기 전 필요한 direct 경로의 요청 통제와 실증이다. legacy 경로의 기존 제한은 direct 경로의 증거로 재사용하지 않는다.

## COL-01 robots·Crawl-delay·일일 한도 연결

- **우선순위:** P1, 수집 활성화 차단 조건.
- **목표:** 단건·목록·queue direct 실행 모두에서 robots 금지/확인 불가 요청을 보내지 않고, Crawl-delay와 지속 일일 budget을 적용한다.
- **선행:** 공통 요청 통제 설계 및 source별 정책 입력 확정. QD-07 활성화 정책 준수.
- **범위:** direct 요청 진입점 공통 gate, 날짜 경계·프로세스 재시작을 견디는 budget 저장과 관측.
- **완료 증거:** 금지/미확인 robots의 네트워크 무요청, delay 간격, 재시작·날짜 경계 누적 한도 테스트와 로그.

## COL-02 redirect 제한 일치

- **우선순위:** P1, 수집 활성화 차단 조건.
- **목표:** 설계 계약인 최대 3회 redirect를 초과하지 않는다.
- **선행:** 요청 client 설정 및 redirect 세는 기준을 설계와 일치시킨다.
- **범위:** 성공·순환·4회 초과 redirect 응답, 다른 source 요청 경로.
- **완료 증거:** 0/3/4회 경계 및 실패 테스트에서 4번째 목적지로 요청하지 않았음을 확인.

## COL-03 source별 표본·차단 조건 검증

- **우선순위:** P1.
- **목표:** 미검증 17개 출처의 실제 허용 표본과 차단/미확인 4개 출처의 재개 조건을 구분한다.
- **선행:** 비운영 시험 대상·실행 PC 결정(QD-05/06), 공개 접근과 robots 정책 확인.
- **범위:** 본문/첨부 표본, since/skip, 오류·차단·빈 본문 및 source별 현재 지원 상태.
- **완료 증거:** 출처별 원문·미디어 대조표와 통과/실패/미검증 결과. 차단 출처를 우회하지 않음.

## COL-04 direct 보존·회수 구현 및 실증

- **우선순위:** P1, 상시 수집 활성화 차단 조건.
- **목표:** raw/media/report/queue 보존과 orphan 정리를 안전하게 재실행 가능하게 한다.
- **선행:** QD-04 기간·승격 후 원본·실패 유예·감사 기준 확정, migration 및 삭제 권한 검토.
- **범위:** dry-run manifest, 보호 대상, batch 소유 삭제, 부분 실패 복구와 멱등성.
- **완료 증거:** 비운영 대상 dry-run→승인된 제한 삭제→DB/object readback, 참조·진행·검수 자료 보호 음성 시험.

QD-04의 값은 `(미정)`이다. 결정을 대신 추정해 구현하지 않는다.
