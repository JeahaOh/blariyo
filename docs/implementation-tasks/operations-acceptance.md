# 운영 인수 및 실연동 task

코드 테스트와 별개로 실제 접근 권한·인프라·운영자 조작이 필요한 항목이다. 운영 상태 재조회는 읽기 전용으로 시작하고 승인된 시나리오만 실행한다.

## OPS-01 Core 운영자 반복 업무 인수

- **우선순위:** P0.
- **목표:** 운영자가 격리 환경에서 검색·작성·편집·이미지·발행·예약·취소·숨김·재공개를 수행한다.
- **선행:** 준비된 격리 인수 환경 가동 상태 확인, 인수 절차 확인.
- **완료 증거:** 10~20건 작업의 성공/실패, 소요·혼동·재작업·복구 관찰; 미해결 사용성 이슈 추적. 실제 Access 인수와 구분.

## OPS-02 현재 운영 상태와 실제 Access 인수

- **우선순위:** P0.
- **목표:** 현재 release·flag·DB ledger·timer·최근 백업 및 운영자 MFA 권한을 확인하고 승인된 Core 흐름을 인수한다.
- **선행:** 운영 담당의 접근 가능 시간 및 승인된 콘텐츠 범위.
- **범위:** 읽기 전용 상태 재조회 후 허용/거부 로그인, 작성·업로드·발행·숨김 점검.
- **완료 증거:** 시각·SHA/digest·관측값·허용/거부 결과·공개/비공개 확인 기록. 비밀/쿠키 값은 기록하지 않음.

## OPS-03 예약·알림·백업 복귀 확인

- **우선순위:** P0, Core 운영 개시 조건.
- **목표:** 예약/취소, timer/outbox 실패 복구, 장애 알림 수신, 최신 백업 복원과 복귀 경로를 확인한다.
- **선행:** OPS-02 상태 확인 및 테스트 콘텐츠/복구 대상 승인.
- **완료 증거:** 예약 실행과 취소, 중복 없는 복구, 운영자 알림 실수신, 배포 직전 18시간 이내 백업/복원 및 호환 rollback 기록.

## OPS-04 다른 PC·원격 자원·Discord 인수

- **우선순위:** P1.
- **목표:** 실제 batch 실행 PC에서 비운영 DB/object 역할 경계와 Discord Gateway 흐름을 확인한다.
- **선행:** QD-05 실행 OS/장비 및 QD-06 제한 계정·bucket/prefix·guild/channel 준비, P1 입력 계약.
- **완료 증거:** batch→DB/object→API 검수/readback, 역할 간 쓰기 거부·dry-run 무쓰기·worker 재시작·미승인 공개0, Discord 취소/만료/권한/중복 interaction 기록.

## OPS-05 초기 7일 운영 관찰

- **우선순위:** P2.
- **목표:** 실제 Core 운영 뒤 예약 실패·알림·백업·용량·오류·권리 요청 처리 기록을 남긴다.
- **선행:** Core 운영 개시 및 담당자 지정.
- **완료 증거:** 실제 7일 관찰표와 후속 개선 task. fixture 시간 전진은 대체 근거가 아님.
