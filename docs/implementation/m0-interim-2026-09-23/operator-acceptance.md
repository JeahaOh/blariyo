# Core 관리자 수동 인수 기록

상태: **준비됨 / 운영자 수동 수행 미실행**. [잔여 과정 E](remaining-process.md#e-실제-운영자-수동-인수)의
기록 양식이다. 자동 브라우저 실행의 시간·PASS를 아래에 대신 입력하지 않는다.

## 실행 환경

[격리 환경 실행 방법](../../../scripts/local/README.md#관리자-격리-인수-환경과-예약이미지-회수-worker)에 따라
새 sandbox를 만들고 `start-development.mjs --sandbox=<디렉터리> --workers`를 실행한다.
다른 터미널의 `open-admin.mjs --sandbox=<동일 디렉터리>`로 시험 인증 브라우저를 연다.
Node 24.18.0과 가동 중인 loopback 시험용 PostgreSQL이 필요하다. 기존 개발 DB에는 worker를 켜지 않는다.

2026-09-23 준비·읽기 smoke를 끝낸 디렉터리는 `.local-data/admin-sandbox-eecd0319a964`다.
현재 서버는 종료 상태이며 위 두 명령으로 재개할 수 있다. 비공개 session/config 내용을 문서로 복사하지 않는다.

- 대상: localhost:3000, 별도 DB·미디어, 합성 연락처, 수집 OFF.
- 실제 Access 로그인/MFA·권한 허용/거부와 운영 콘텐츠 공개는 이 인수 범위가 아니다.
- 3000/3100 사용 중이면 해당 서버 소유자와 용도를 확인하고 충돌을 해소한다.
- sandbox DB·이미지는 종료 후 유지한다. 정상 재시작 뒤 브라우저를 다시 열어 이어서 인수할 수 있다.
- 운영자 식별은 개인 정보 원문 대신 내부 역할명으로 기록한다. 토큰·쿠키·인증 코드는 기록하지 않는다.

## 수행 묶음

운영자가 직접 12건을 작성한다. 실패를 숨기거나 성공한 건만 남기지 않고 수정·재시도를 같은 행에 기록한다.

1. 새 초안에서 제목·본문·출처·이미지 2개를 입력한다. 이미지 대체 텍스트를 넣고 순서를 바꾼다.
2. 저장 후 제목을 검색하여 다시 선택한다. 본문·출처·이미지 순서가 유지되는지 확인하고 편집 저장한다.
3. 1~8번은 즉시 발행→공개 화면 확인→숨김→이미지 회수 대기→최신 내용 확인→재공개한다.
4. 9~10번은 현재보다 충분히 뒤의 KST 시각으로 예약하고 해당 실제 시각 이후 정확히 한 번 공개되는지 확인한다.
5. 11~12번은 예약 후 취소한다. 원래 예약 시각이 지나도 초안으로 남는지 확인한다.
6. 미저장 상태에서 다른 글 선택/새 초안/페이지 이동 경고를 확인한다. 취소한 입력은 남아야 한다.
7. 작은 화면에서 목록 복귀와 편집 복귀를 수행하고, 반복 클릭·긴 대기·혼동을 기록한다.

예약 worker는 기본 60초 간격이다. 숨김 후 회수 대기와 예약 발행 지연을 실제 측정하며,

## 인수 판단

- 운영자 역할/확인 시각: 미입력
- 총 소요 시간/재작업 수/복구 실패 수: 미입력
- 내용 유실/중복 발행/잘못된 공개: 미검증(목표 각각 0)
- 수정이 필요한 불편사항: 미입력
- 수정 후 재확인 또는 명시적으로 수용한 잔여사항: 미입력
- 인수 판단: 미실행

운영자 확인과 불편사항 처리 또는 잔여 수용이 기록된 뒤 E를 완료로 바꾼다.
원격 CI·배포·운영 인증·7일 관찰은 [전체 잔여 과정](remaining-process.md)의 별도 항목으로 남긴다.
