1. 현재 판정과 증거를 문서에 반영하고 GitHub 실패 실행의 실제 단계·원인을 확인한다.

3. 저장 복구 결함과 로컬 예약·outbox 실행 연결을 보완한다.
4. 실제 로컬 실행 구성에서 격리 10~20건을 재검증하고 변경 범위의 회귀를 통과한다.
5. 실제 운영자가 관리자 반복 업무를 수동으로 수행하고 사용성을 인수한다.
6. P0-05 release·migration·백업·복귀 계획을 준비한다. **배포할 최종 SHA의 CI·이미지 게시 성공이 필수다.**
7. 별도 승인된 변경을 배포하고 실제 Access·미디어·timer·알림·백업을 검증한다.
8. Core 콘텐츠 운영을 시작한다. 미검증 수집·선택 기능은 OFF로 유지한다.
9. 운영과 병행해 P1 수집 작업을 완료하고 개별 활성화 조건을 통과한다.
10. P2 실제 기간 관찰·복구 훈련·개선을 진행한다.

1~5는 관리자 마감과 CI 오류 해결 작업이다. CI 로컬 수정은 먼저 수행할 수 있으며 원격 검증은
승인된 commit/push 후 진행한다. 6~10은 전체 잔여 로드맵이며 이 계획서 작성이 실행 권한이나
완료를 뜻하지 않는다. commit·push·배포·운영 콘텐츠 공개는 각각 명시된 권한으로 수행한다.
