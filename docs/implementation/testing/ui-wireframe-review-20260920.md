# M0 공개 화면 대조·수정 기록

2026-09-20 로컬 구현 기준. 운영 사이트에 이번 수정본을 배포하지 않았다.
정본은 [화면 설계](../../planning/03-screen-design.md), 시각 비교 자료는
[반응형 퍼블리싱](../../publishing/responsive/README.md)과
[와이어프레임](../../wireframes/responsive/index.html)이다.
프로토타입의 M1 로그인·광고·회원 화면을 M0 운영에 추가하지 않는다.

## 대조 결과와 반영

| 항목 | 수정 전 차이 | 반영한 동작·형태 |
| --- | --- | --- |
| 공통 헤더 | 왼쪽 정렬과 밝은 헤더로 시각 기준과 다름 | 54px 어두운 헤더, 가운데 B 마크·서비스명 |
| 목록 | 제목·metadata 배치와 간격 차이 | 760px 본문 폭, 제목 첫 줄/metadata 둘째 줄, 64px 이상 행 |
| 공지·현재 글 | 상태 구별이 약함 | 공지 배지·골드 배경, 현재 글 청록 배경·왼쪽 선·링크 제외 |
| 상세 | 제목·본문·목록이 한 덩어리 | 고정 탐색 헤더, 전체 제목과 metadata, 본문/출처, 게시판 목록 구획 |
| 공유 | 일반 dialog 모양 | 데스크톱 우측 panel, 767px 이하 하단 sheet, Escape·포커스 복귀 |
| 목록 상태 | 단순 로딩 문구·끝 페이지 화살표 사라짐 | 행 skeleton, 오류/재시도, 양쪽 화살표의 비활성 상태 |
| 404 | 일반 오류 화면 | 상세 상태 헤더·목록 복귀, 원문/공유 숨김 |
| 푸터 | 이메일 원문 표시 | 권리 문의 mailto + 주소 복사, 현재 페이지 URL 포함, 긴 주소 숨김 |
| 정책 | dialog·fallback 정리 필요 | 배경 스크롤 잠금, 닫기·Escape, modal 미지원 시 직접 경로, 실패 재시도 |

헤더 색은 화면 설계의 기존 밝은 배경 설명과 palette/퍼블리싱의 어두운 배경이 충돌해,
이번 요청대로 화면 설계도 어두운 헤더로 맞췄다. 카피·M0 기능 범위를 임의 확장하지 않았다.

## 검증

- Web 타입 검사·Web/Core production build 통과.
- 실제 Chromium + 격리 PostgreSQL 브라우저 전체 9건 통과.
- 320/390/768/1280px 목록, 320/360/390/768/1280px 상세에서 가로 넘침 없음.
- 헤더 높이/색, 최대 본문 폭, 행 높이, 비활성 페이지 버튼, 이메일 원문 비노출을 assertion으로 확인.
- 503 응답을 주입한 목록 페이지 이동에서 오류를 표시하고 재시도 후 정상 목록 복구 확인.
- 작성·이미지 실패 처리·발행·숨김·재공개·예약·공유·정책 이력·동의 철회 회귀 검사 통과.
- 로컬 Chrome에서 실제 수집 제목을 넣은 목록·상세·긴 제목을 시각 확인.
  시각 검사용 게시글은 격리 임시 DB 사본이며 저장한 로컬 검토 초안 25건과 별개다.
- 화면 근거 PNG는 `test-results/m0-browser/`에 생성한다. 이 경로는 Git 제외이며 CI artifact로 7일 보관한다.

픽셀 단위로 원본 HTML과 자동 비교한 검사는 아니다. 원본 정적 파일의 구조/CSS와 제품 정본을
대조한 뒤 새 앱의 실제 화면·크기·동작을 검증했다. 운영 배포·실제 Access 쓰기 검증은 별도다.

## 사용자 재검토 후 보완 — 실제 개발 DB와 디자인 구분

초기 완료 보고는 디자인 일치 범위를 넓게 표현했다. 데스크톱 다열 표인 wireframe과 두 줄 목록인
publishing이 서로 다르며, 현재 구현은 후자를 기준으로 한다. 목록 제목/보조 문구 배치, 게시판 탭,
정책 popup의 시각 구획, 실제 문의 설정이 빠져 있어 보완했다.

- 목록: 제목 아래 보조 문구, 오른쪽 실제 페이지 정보, 헤더 아래 `짤` 탭.
- 정책: 청록 상단 선, 정책 제목/버전/적용일 영역, 본문과 버전/적용 기간 이력 표, 현재 버전 표시.
- 문의: 기존 비공개 연락처 설정으로 권리 문의와 이메일 복사 노출. 실값은 문서에 기록하지 않음.
- 검사 fixture와 개발 서버를 분리했다. 기존 `59689` 임시 fixture 주소는 실제 정책 검수에 사용하지 않는다.
  [지속적인 로컬 서버](../../../scripts/local/README.md)는 `localhost:3000`, 개발 DB `55439/blariyo_local`을 사용한다.
- 약관/개인정보 `v0.1` 두 건을 실제 PoliciesService로 개발 DB에 등록했다. API 본문과 DB 본문의
  SHA-256 일치를 확인했고, 두 번째 실행은 신규 0/기존 2건을 유지했다. 게시글 25건은 DRAFT 유지.
- Web typecheck/build, tests typecheck/lint, 전체 Chromium 9건 통과. 제목의 수직 배치와 게시판 탭,
  정책 popup 1280/390/320px 화면 안 배치/가로 넘침 검사를 추가했다.
- 별도로 실제 `localhost:3000`에서 1280/390/320px 정책 본문·문의·Escape 포커스 복귀와
  `/terms`, `/privacy` 직접 경로를 확인했다. 검사 fixture의 가짜 정책 PASS로 대신하지 않았다.

정적 디자인의 로그인·광고는 M0에 추가하지 않으며, 고정 발행 횟수 문구 대신 실제 목록 페이지 정보를
표시한다. 본문 이미지가 없는 초안을 이미지가 있는 완성 콘텐츠로 만들었다고 보지 않는다.
