## GTM 설치 후 공개 안내 대조 — 2026-09-25

사용자 요청으로 GTM `GTM-5BRTQ5T3`의 공통 script·noscript 삽입을 구현한다.
컨테이너 로드는 분석 동의·GA4 비활성 여부와 독립적이므로 기존 문서의 Google 요청 0건 표현을
사이트 전체에 적용할 수 없다. [분석 계획의 설치 범위](../planning/04-analytics-ad-plan.md#gtm-컨테이너-설치--2026-09-25-사용자-요청)를 따른다.
운영 배포 전에 실제 컨테이너의 태그·요청·쿠키와 공개 개인정보·쿠키 안내를 대조한다.
실제 GTM 계약 법인·처리 국가·보관기간은 `(미정)`이다. 기존 발행 정책과 활성화 placeholder를
소급 수정하거나 정책 재발행·법무 검토 완료로 처리하지 않는다.

## 법무·문의 실값 관리

법무·문의 공개값은 문서나 source에 실값을 하드코딩하지 않고 배포 환경 properties/config에서
주입한다. 운영자 표시명, 일반 문의 이메일, 권리 침해 신고·요청 이메일, 개인정보 문의 이메일,
개인정보 보호책임자 또는 담당자는 M0 Core production 공개 전에 실값이 필요하다. 실값은 운영자의
비공개 설정 파일에서 관리하며 문서에는 넣지 않는다. 입력 형식 검사를 통과해도 실제 수신·담당자
적정성과 정책 발행까지 확인한 것은 아니므로 기존 placeholder와 관련 공개 조건을 유지한다.

사업자명, 사업자등록번호, 통신판매업신고번호, 대표자명, 주소와 전화번호는 사업자등록 또는 거래
기능 확정 전까지 `(미정)`으로 보류하며 추정값을 만들지 않는다. 이 보류값만으로 M0 Core 공개를
차단하지 않지만, 관계 법령이나 법무 검토에서 공개가 필요하다고 확인되면 출시 전에 다시 판단한다.

## 공통 정책 계약

M0 Core에는 공개 열람·운영자 발행·정책·권리 문의와 참고용 게시글 조회 수를 포함한다. 수집 후보
검수는 `M0 수집 보조`, 허용 출처 목록 수집은 `M0 자동 수집`에서 각각 적용한다. GA4 연동 코드는
M0 Core에 포함하지만 아래 GA4 조항은 운영 활성화 gate를 통과해 실제 기능을 켠 뒤 적용한다.
소셜 회원과 광고·제휴 조항도 각 후속 기능을 활성화할 때만 적용한다.

- 초기에는 `짤/meme` 게시판 하나만 운영하고 `/`는 `/meme`으로 리다이렉트한다. 추후 `익게/community`, `뉴스/news`와 다른 게시판을 추가할 수 있다.
- 공개 목록은 광고 행을 제외한 게시글 20개, 상세 하단은 같은 게시판의 현재 글 주변 게시글 20개를 사용한다.
- 초기 게시글은 관리자가 보기에 웃긴 것을 직접 선별해 발행하고 외부 콘텐츠에는 출처를 표시한다. 출처 표시는 권리 확보를 뜻하지 않는다.
- 푸터 이메일로 받은 권리자 요청을 운영자가 확인하면 대상 게시글을 먼저 숨기고 재공개·수정·삭제를 판단한다.
- 수집 보조와 자동 수집은 M0 Core 공개 뒤 각각의 gate를 통과한 출처에서만 활성화한다. 수집 결과는 후보 큐에만 저장하고 운영자 확인과 수동 발행 없이 공개할 수 없다. 로그인·기술적 접근 제한·수집 거부 범위를 우회하지 않는다.
- 현행 direct 구현은 metadata 외 raw HTML·본문·이미지/첨부·외부 SNS 링크와 실행 기록을 저장한다. 공개 원문에도 개인정보가 포함될 수 있으므로 개인정보 미수집으로 단정하지 않는다. 실제 목적·보존/파기·고지 정합성과 robots/일일 budget 통제는 [QD-04·P1-06](../roadmap.md)의 잔여 조건이다. 9월 23일 데이터 승격·검수 활성 기록은 이 검토를 대체하지 않는다.
- 자체 이용 이벤트 API·방문자 식별자·원시 이벤트·일별 분석 집계를 만들지 않는다. 게시글 조회 수는 개인·세션 식별자나 조회 이력 없이 참고용 누적값만 유지한다.
- M1부터 네이버, 카카오, Google, Apple 소셜 회원가입·로그인을 제공한다. 소셜 제공자의 동의와 블라리요 이용약관 동의·회원가입 개인정보 수집이용 동의는 분리한다.
- 소셜 비밀번호는 수신·저장하지 않고 provider 고유 식별자를 계정 연동 키로 사용한다. 이메일은 로그인 계정의 고유 키로 사용하지 않는다.
- GA4는 분석 동의 후에만 로드하며 회원 번호, 이메일, 닉네임과 provider 식별자를 GA4로 보내지 않는다.
- 상세 광고는 본문·출처 다음, 하단 목록 중간, 목록 아래만 허용한다.
- 광고 호출 실패는 광고 차단으로 간주하지 않는다. 확정 차단 때는 닫을 수 있는 전면 dim modal을 표시하며 닫은 뒤 콘텐츠 열람을 제한하지 않는다.
- 제휴 링크에는 링크와 가까운 위치에 제휴 관계와 수수료 수취 사실을 분명히 고지한다.

## 출시 차단 항목

2026-09-20 M0 Core의 연락처 주입·시행일·정식 발행·사업자 고지·7일 진단 로그 삭제·암호화 백업 복원을 확인했다. 아래 M0 행은 지켜야 할 운영 조건이며 전부 미입력이라는 뜻이 아니다. 요청자의 이메일 처리·법정 보존 예외는 운영자가 사건별로 실행해야 한다. 후속 기능의 미확정 값은 계속 공개 차단 조건이다.


미확정 placeholder는 근거 없이 삭제하지 않는다. 2026-09-20 사용자 결정으로 M0 최초 시행일은 2026년 9월 20일로 확정했다. 9월 26일 예정은 철회했다. 날짜 확정과 실제 DB 발행·공개는 구분한다. 운영자 표시명, 시행일, 공통 문의·권리·개인정보 접수 이메일,
개인정보 보호책임자 또는 담당자와 M0 Core에서 실제로 사용하는 수탁자 값이 미입력이면 M0 Core production
공개를 차단한다. 현행 M0의 해당 값과 공개 artifact는 위 발행 기록에서 확인한다. 사업자등록 전 사업자 정보는 보류한다. 소셜, GA4, 광고·제휴와 익게의
기능별 placeholder는 M0 Core 공개 전체가 아니라 해당 기능의 활성화만 차단한다.

이 표는 각 본문의 placeholder와 차단 문구를 단계별 점검 위치에 연결하는 색인이다. 표에 적었다고
법무 검토가 끝난 것은 아니며, 본문 조건을 임의의 결론으로 바꾸지 않는다.

다시 결정하는 대신 위 M1.5 약관·보존·실제 접수값·운영 수용 조건을 확인한 뒤 공개한다.

## M1·M1.5 설계 반영 상태 (2026-09-08)

[제품 계약](../planning/08-member-community-plan.md)과 [기술 계약](../system-design/06-member-community-design.md)에
회원·익게 기본안을 작성했다. 이는 법무 확정이나 운영 공개 승인이 아니다. 위 기존 출시 차단 항목은 유지한다.
[현행 설계 준비 상태](../system-design/design-readiness.md)는 설계 기준선·구현 수용·production 공개 승인을 분리한다.

- 계정 연결·탈퇴, 글 단위 랜덤 이름, 탈퇴 시 회원 콘텐츠 유지·계정 연결 제거, 신고·제재 절차를 약관 초안에 연결했다.
- M1은 제공자 선택 프로필 미수집, 서비스 표시명 직접 입력으로 최소화한다. Google은 `openid`만 요청한다.
- Apple refresh credential의 제한된 보관·철회 예외, 인증 cookie 설계값, 탈퇴 worker·복원 삭제 ledger를 고지 초안에 추가했다.
- 추가 공개 차단: [SIGNUP_PRIVACY 전문 초안](signup-privacy-consent.md)의 법무 검토·운영 버전·시행일, 직접 입력 생년월일에 따른 만 14세 이상 판정의 적정성,
  신고 보존 90일·복원 삭제 ledger 8주의 법적 근거, 실제 제공자·국외이전·알림·철회 설정 검증.
- 설계값은 구현을 위한 입력이다. 실제 browser 저장소 이름과 만료를 확인하기 전 cookie placeholder를 완료 처리하지 않는다.

### 연동 해제 경합 보완의 공개 조건

회원 삭제와 독립된 최소 연동 해제 guard의 최대 30일 보존 근거·파기 및 제공자별 결과 확인 절차를
개인정보처리방침 추가안에 연결했다. 실제 근거·기간 검토 전 해당 provider 공개는 차단한다.
편집 인증은 부모 화면을 유지하는 팝업으로 설계하며 신규 브라우저 영구 저장소를 추가하지 않는다.
