# 블라리요 쿠키 설정 안내 초안

> 현행 M0 공개본: [2026-09-20 v0.1](m0-core/README.md). 이 전체 초안은 후속 기능도 포함한다. 연락처 placeholder는 비공개 설정 주입 자리이며 실제 M0 공개본에는 남아 있지 않다.

- 문서 상태: 현재 저장소와 후속 기능의 공개 조건을 분리한 편집 초안
- 정합성 검토일: 2026-09-24 (Nuxt 동의 구현·M0 공개본 대조)
- 시행일: `2026년 9월 20일`
- 서비스명: `블라리요`

M0 Core에는 자체 방문 통계용 쿠키·로컬 저장소·세션 저장소를 만들지 않는다. 회원 인증 저장소는
M1, GA4와 광고 저장소 및 선택 동의 UI는 각 기능을 운영에서 활성화한 뒤에만 생성·노출한다.
기능별 출시 차단값은 해당 기능을 차단하며, 비활성 기능의 미정값만으로 M0 Core 공개 전체를 차단하지
않는다.

## 1. 분리 원칙

- 게시글 참고용 조회 수를 위해 방문자·세션 식별자, IP 원문, User-Agent와 조회 이력을 저장하지 않는다.
- 선택 GA4와 선택 광고는 각각 동의한 뒤에만 관련 태그와 저장소를 사용한다.
- 네이버·카카오·Google·Apple 로그인에 필요한 인증 세션과 위조 방지 값은 필수 저장소로 분류한다. 소셜 로그인은 분석·광고 동의와 연결하지 않는다.
- 분석 또는 광고를 거부해도 게시글과 같은 게시판의 주변 목록을 열람할 수 있다.

## 2. 쿠키·로컬·세션 저장소

현재 M0 공개본은 관리자 Cloudflare Access의 `CF_Authorization`과 9월 20일 확인한 6시간 세션을 고지한다. 아래 회원·광고 저장소는 후속 설계이며 실제 생성 확인이 아니다. Nuxt 분석 동의 구현은 `analytics-v1`에서 `blariyo_consent` version3·분석 선택·광고 false·1년 만료를 처리한다. 운영 GA4는 별도 활성화 전까지 비활성이다. 비활성화만으로 과거 localStorage 선택이 삭제된다고 보장하지 않는다.

2026-09-25 첫 확장 `analytics-v1`의 개발 계약은 `version=3`, `scope=analytics_v1`로 재선택을 받는다.
기존 version2를 확장 동의로 승계하지 않는다. 화면·노출·공유 시도 구분값은 동의 후 브라우저 메모리에만
두고 철회·문서 종료에 폐기하며 자체 방문자 쿠키·sessionStorage를 추가하지 않는다. 이는 미발행
개정 대상이다. [개발 명세 §13.2](../development-specs/m0-core/analytics-consent/analytics-consent.dev.md#analytics-v1-consent)를 따른다.

| 저장소                     | 이름 후보                                         | 구분      | 목적                                                  | 생성 조건                              | 만료·삭제                                             |

실제 이름과 기간이 표와 다르면 이 문서를 먼저 갱신한다. 출시 차단값이 남은 도구나 기능은
production에서 로드하지 않는다.

## 3. 기능 활성화 경계

이하 Google 요청 0건은 직접 GA4 수집 경로의 기준이다. 별도 GTM 컨테이너는 동의와 독립적으로
요청되므로 사이트 전체에 확대해 설명하지 않는다. [GTM 설치 후 공개 안내 대조](README.md#gtm-설치-후-공개-안내-대조--2026-09-25)의 실제 요청·고지 검증은 남아 있다.

- `NUXT_PUBLIC_GA4_ENABLED=false`인 환경에서는 Google tag, `_ga*`, 분석 선택 항목과 선택 배너를 노출하지
  않고 `NUXT_PUBLIC_GA4_MEASUREMENT_ID`를 public runtime config에서 unset한다.
- 현행 앱은 `NUXT_PUBLIC_ANALYTICS_APPROVED`도 true여야 분석을 켠다. 읽기/쿠키 삭제 실패 안내의 미충족 사항과 실제 Google 전송 검증은 [분석 동의 명세](../development-specs/m0-core/analytics-consent/analytics-consent.dev.md)의 활성화 잔여 조건이다.
- GA4 Measurement ID·속성 보관 설정·국외이전 고지·실제 Google 계약 법인·Google tag/CSP domain이
  모두 확정된 환경에서만 분석 선택을 활성화한다. 하나라도 미확정이면
  `NUXT_PUBLIC_GA4_ENABLED=false`를 유지하며 이 gate는 M0 Core 공개 자체를 막지 않는다.
- 광고 기능이 비활성이면 광고 저장소와 광고 선택 항목을 노출하지 않고 사전 동의를 받지 않는다.
- 선택 기능이 하나도 활성화되지 않은 환경에서는 `blariyo_consent`를 생성하기 위한 선택을 요구하지 않는다.

## 4. 선택과 철회

GA4 또는 광고 같은 선택 기능이 모두 비활성이면 선택 동의 배너를 표시하지 않는다. 둘 중 하나라도
활성화할 때 설정 화면은 실제 활성 기능에 한해
`필수만 사용`, `분석 허용`, `광고 허용`, `모두 허용`, `선택 저장`을 제공한다.

- 선택 기능 활성화 후 저장된 선택이 없는 최초 접속에는 화면 하단에 비차단형 쿠키 배너를 표시한다.
- 배너는 `필수만 사용`, `설정`, `모두 허용`을 제공하며 `설정`은 전체 쿠키 설정 modal을 연다.
- 선택을 저장하면 modal과 배너를 닫고 이후 접속에는 다시 자동 표시하지 않는다.
- 새 선택 기능이 추가되면 기존 선택을 새 기능 동의로 간주하지 않고 변경된 선택 범위를 다시 안내한다.
- 이용자는 푸터의 쿠키 설정에서 저장값을 언제든 변경하거나 철회할 수 있다. 비활성 기능의
  선택 항목은 노출하지 않고 사전 동의를 받지 않는다.

- 분석 철회: GA 태그 전송을 즉시 중단하고 `_ga*` 쿠키와 관련 선택 분석 값을 삭제한다.
- 광고 철회: 광고 태그 전송을 중단하고 광고 쿠키와 `blariyo_ad_frequency`를 삭제한다.
- 분석·광고 철회는 로그인 세션을 종료하지 않는다. 로그아웃 또는 회원 탈퇴는 별도 계정 기능에서 처리한다.

## 5. GA4 적용 계약

- Google tag와 GA4 설정은 저장된 `analytics=true`를 확인한 뒤 browser에서 한 번 동적 로드한다.
- 동의 전에는 방문자 수·page open을 포함한 Google tag/request와 cookieless ping을 0건으로 유지한다.
- 현행 legacy의 허용 custom parameter는 `page_view`의 `page_type`,`route_template`, `select_content`의
  `board_slug`,`content_type`,`list_position_bucket`, `share`의 `share_method`,`board_slug`,
  `scroll`의 `page_type`,`scroll_depth_bucket`뿐이다.
- 첫 확장 v1은 [분석 계획 §4.1](../planning/04-analytics-ad-plan.md#41-첫-확장-구현-확정--analytics-v1)과
  [개발 명세의 9개 이벤트·필드](../development-specs/m0-core/analytics-consent/analytics-consent.dev.md#analytics-v1-events)로 교체한다.
  공개 콘텐츠 분석 키·메모리 연결값·위치·본문·공유 결과·제한된 진입 분류를 고지하고 version3 재선택을
  받은 뒤 활성화한다. 실제 제목·본문·URL·내부 postId 금지는 유지한다. 앱 직접 전송만 사용하며 GTM의
  동일 목적지 태그는 중지·검증한다. 현재 콘솔이 그렇게 설정됐다는 주장은 아니다.
- v1의 BigQuery 일별 원시 저장은 첫 구현에서 제외한 후속 외부 보관이다. GA4 및 후속 BigQuery 각각의
  보관·삭제·권한·실제 계약·고지를 구분해야 하며, 동의 철회 시 이미 전송된 자료까지 즉시 삭제된다고
  안내하지 않는다. 후속 저장은 확정 전 활성화하지 않는다.
- GA4에는 이메일, 이름, 닉네임, 프로필 이미지, 블라리요 회원 번호, 네이버·카카오·Google·Apple 제공자 식별자를 전송하지 않는다.
- 게시글 제목·본문·원문 URL·내부 `postId`, IP와 수집 후보 정보도 전송하지 않는다.
- GA4 User-ID는 초기에는 사용하지 않는다. 추후 사용하려면 소셜 식별자와 직접 연결되지 않는 별도 가명값, 처리 목적과 보유 기간을 개인정보처리방침에 먼저 반영한다.
- consent mode를 사용하더라도 분석 동의 전 cookieless ping을 보내지 않는 차단형 기본값을 적용한다.
- tag 로드나 event 전송이 실패하면 event를 drop하고 공개 기능을 유지하며 자체 분석 DB나 재시도
  queue로 대체하지 않는다.
- 분석 동의를 철회하면 추가 전송을 즉시 중지하고 현재 도메인의 `_ga`, `_ga_*`를 삭제한다. 이미 Google에 전송된 정보의 삭제·보유 범위는 확정된 GA4 설정과 처리방침에 따른다.

## 6. 광고 실패와 확정 차단

timeout, no-fill, 네트워크·스크립트 오류는 광고 실패다. 광고 사업자의 명시적 차단 응답 또는 두 가지 독립 신호가 함께 확인된 경우만 확정 차단으로 처리한다. 판정이 모호하면 실패로 처리하며 차단 안내를 띄우지 않는다. 확정 차단 안내는 닫을 수 있는 전면 dim modal로 표시하고, 닫은 뒤 콘텐츠 열람을 제한하지 않는다.

## 7. 브라우저 설정과 변경 고지

브라우저에서 저장소를 삭제하거나 차단할 수 있다. 이 경우 선택 기억과 로그인 세션이 초기화될 수
있지만 공개 콘텐츠 열람은 유지한다. 저장 목적, 이름, 기간, 도구가 바뀌면 이 문서와
개인정보처리방침을 함께 갱신한다.

## M1 인증 저장소 설계값과 운영 확인

기존 표의 `[출시 차단: 실제 회원 인증 쿠키명 확정 필요]`와
`[출시 차단: OAuth transaction 저장명 확정 필요]`는 실제 구현·브라우저 확인 전까지 유지한다.
설계 이름은 다음과 같으며 구현이 확인되면 공개본의 후보 표를 이 값으로 갱신한다.

| 설계 이름                | 범위·수명                                       | 확인할 조건                                                                |
| ------------------------ | ----------------------------------------------- | -------------------------------------------------------------------------- |
| `__Host-blariyo-session` | 회원 session, 절대 7일·유휴 24시간 중 빠른 만료 | Secure·HttpOnly·Path=/·Domain 없음·SameSite=Lax, 종료 즉시 폐기            |
| `__Host-blariyo-auth`    | 로그인 시도·가입 임시 binding, 최대 10분        | Secure·HttpOnly·Path=/·Domain 없음·SameSite=None; Apple POST callback 확인 |

OAuth state·nonce·PKCE 원문은 server 임시 저장소에서 처리하고 localStorage에 넣지 않는다.
필수 인증 저장소 추가를 이유로 분석 동의 배너를 켜지 않는다. 분석 거부 상태에서도 로그인은 가능하다.
