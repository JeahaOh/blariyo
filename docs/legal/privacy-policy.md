# 블라리요 개인정보처리방침 초안

- 문서 상태: 출시 전 확정 필요
- 정합성 검토일: 2026-09-03
- 버전: `v0.1`
- 시행일: `[출시 차단: 시행일 입력 필요]`
- 서비스명: `블라리요`
- 개인정보처리자: `[출시 차단: 운영자 표시명 입력 필요]`
- 개인정보 보호책임자 또는 담당자: `[출시 차단: 성명·직책 또는 담당 부서 입력 필요]`
- 개인정보 문의: `[출시 차단: 개인정보 문의 이메일 입력 필요]`
- 사업자명·사업자등록번호·통신판매업신고번호·대표자명·주소·전화번호: `(미정, 사업자등록 또는 거래 기능 확정 전까지 보류)`

운영자 표시명, 개인정보 문의 이메일, 개인정보 보호책임자 또는 담당자와 M0 Core에서 실제 사용하는
수탁자가 확정되기 전에는 M0 Core를 production에 공개하지 않는다. 공개 실값은 배포 환경
properties/config에서 주입하고 문서나 source에 하드코딩하지 않는다. 보류한 사업자 정보는 추정값을
만들지 않는다. 소셜 로그인, GA4와 광고의 미확정 값은 M0 Core 공개 전체가 아니라 해당 기능의 운영
활성화를 차단한다.

이 초안은 M0와 후속 기능의 처리 항목을 함께 설계한다. 실제 공개본에는 배포 시점에 활성화된
기능만 현재형으로 남긴다. 회원·소셜 로그인은 M1, GA4·광고는 각 기능을 활성화하기 전까지
수집·처리하지 않는다. GA4 연동은 M0 Core에 구현해도 운영 gate가 끝나기 전에는 비활성으로
유지한다. 콘텐츠 수집 후보 처리는 `M0 수집 보조`부터 적용한다. 수집은 공개된 게시물의 URL·
제목·이미지 후보 metadata만 다루고 대상 사이트 이용자의 개인정보를 수집하는 기능이 아니다.

개인정보처리자는 개인정보 보호법 제30조에 따라 정보주체의 개인정보를 보호하고 관련 고충을 처리하기 위해 다음과 같이 개인정보처리방침을 수립·공개한다.

처리 목적을 변경하는 경우 법령상 허용 여부를 확인하고 필요한 경우 별도 동의를 받는다.

## 제2조 처리하는 개인정보의 항목과 수집 방법

`짤/meme` 게시판은 로그인하지 않아도 열람할 수 있다. M1부터 네이버·카카오·Google·Apple
계정으로 회원가입과 로그인을 제공한다. 소셜 제공자의 동의 화면과 별도로 블라리요 이용약관
동의 및 회원가입 개인정보 수집·이용 동의를 받아야 가입이 완료된다. 가입 화면에서 이
개인정보처리방침 전문을 확인할 수 있게 한다. 소셜 계정 비밀번호는 블라리요가 전달받거나
저장하지 않는다.

| 구분 | 항목 | 필수·선택 | 수집 방법 |
| --- | --- | --- | --- |
| 접속·보안 | IP 주소, User-Agent, 접속 일시, 요청 URL, referer, 응답 상태, 오류 로그 | 필수 처리 | 서비스 요청 시 자동 생성 |
| 회원 계정 | 블라리요 회원 번호, 서비스 표시명, 계정 상태, 가입·최근 로그인·탈퇴 시각, 이용약관·회원가입 수집이용 동의 버전과 시각 | 가입 필수 | 가입 완료·로그인·동의 시 생성 |
| 소셜 연동 공통 | 제공자 코드, 제공자별 고유 식별자, 연동·최근 인증 시각 | 가입 필수 | 이용자가 선택한 소셜 제공자로부터 수신 |
| 서비스 표시명 | 회원이 직접 입력한 표시명 | 가입 필수 | 가입·계정 화면에서 입력; 소셜 프로필은 추가 요청·저장하지 않음 |
| 가입 연령 판정 | 직접 입력한 생년월일, 연령 판정 통과 시각 | 가입 필수 | 생년월일은 판정에만 일시 사용하고 보관하지 않음; 통과 시각만 가입 완료 시 기록 |
| 로그인 보안 | OAuth `state`·`nonce`·PKCE 검증값, 인증 성공·실패 기록, 세션 식별자 | 필수 처리 | 인증 요청·callback·세션 발급 시 생성 |
| 쿠키 선택 | 분석·광고 동의 여부, 정책 버전, 선택 시각 | 선택 기능 활성화 시 필수 설정 | 활성 기능의 쿠키 배너·설정 modal에서 저장 |
| 선택 분석 | GA client ID, 페이지 조회·목록 선택·스크롤·공유 이벤트, 각 이벤트에 허용된 최소 custom parameter, 제한된 기기·유입 정보 | 선택 | 저장된 분석 동의 후 browser가 Google tag를 동적 로드해 수집 |
| 선택 광고 | 광고 식별자·쿠키, 광고 노출·클릭·빈도·성과 정보 | 선택 | 광고 동의와 광고 실험 시작 후 수집 |
| 권리자 요청 | 대상 URL, 요청 유형, 이메일, 요청 내용, 이름·단체명과 권리·대리 소명 자료(제출하는 경우) | 요청 처리 필수 | 요청자가 푸터의 확정된 이메일 채널로 제출 |
| 일반 문의 | 이메일, 문의 내용, 첨부 자료 | 문의 시 필수 | 문의자가 확정된 접수 채널로 제출 |
| 수집 후보 큐 | 출처 URL·도메인, 공개 제목, 이미지 후보 URL metadata, 수집 경로, 수집 시각 | 운영 검수 필수 | 운영자가 URL을 지정하거나 허용 출처의 공개 목록을 수집할 때 저장 |

### 소셜 제공자별 수신 항목

| 제공자 | 가입 식별에 사용하는 항목 | 추가로 요청할 수 있는 최소 항목 | 운영 기준 |
| --- | --- | --- | --- |
| 네이버 | 애플리케이션별 고유 회원 식별자 `id` | M1에서 요청하지 않음 | 이메일·별명·사진·성별·생일·연령대·출생연도·전화번호 미요청 |
| 카카오 | 서비스별 회원번호 | M1에서 요청하지 않음 | 이메일·닉네임·프로필 사진 미요청 |
| Google | OpenID Connect `sub` | M1에서 요청하지 않음 | M1은 `openid`만 요청 |
| Apple | Sign in with Apple `sub` | M1에서 요청하지 않음 | 이름·이메일 없이 가입하며 반환된 선택 정보는 저장하지 않음 |

- 제공자가 선택 항목을 주지 않거나 이용자가 동의하지 않으면 해당 항목 없이 가입 가능한 구조를 우선한다. 서비스에 꼭 필요한 항목이 생기면 가입 화면에서 이유를 별도로 설명하고 동의를 받는다.
- 소셜 제공자 식별자, 이메일, 닉네임, 프로필 이미지는 GA4 이벤트·GA4 User-ID·광고 식별값으로 전송하지 않는다.
- GA4 custom parameter는 `page_view`의 `page_type`,`route_template`, `select_content`의
  `board_slug`,`content_type`,`list_position_bucket`, `share`의 `share_method`,`board_slug`,
  `scroll`의 `page_type`,`scroll_depth_bucket`만 허용한다. 게시글 제목·본문·원문 URL·내부
  `postId`, 회원·소셜 식별자, IP, GA4 User-ID와 수집 후보 정보는 전송하지 않는다.
- M1은 제공자 이메일·닉네임·사진을 추가 요청·저장하지 않고 서비스 표시명을 직접 입력받는다. 반환된 선택 정보는 로그에도 남기지 않는다. 로그인 access token과 Apple 이외 refresh token은 callback 처리 뒤 폐기한다. Apple refresh credential은 자격 상태 확인·연동 철회를 위해 암호화해 보관하고 연동 종료 시 삭제한다. 외부 철회 실패에 필요한 분리 작업 secret은 최대 24시간 뒤 파기한다. 이 예외의 실제 처리·보유 고지는 M1 공개 전에 검토한다.

- 주민등록번호, 여권번호, 운전면허번호, 외국인등록번호 같은 고유식별정보는 수집하지 않는다.
- 사상·신념, 건강, 성생활, 유전·범죄경력 같은 민감정보는 의도적으로 수집하지 않는다.
- 권리자 요청자가 소명에 불필요한 민감정보나 고유식별정보를 제출하지 않도록 안내하고 확인 즉시 마스킹 또는 삭제한다.

## 제3조 게시글 조회 수와 최소 수집 기준

1. 공개 게시글 상세 화면이 정상 표시되면 참고용 누적 조회 수를 1 증가시킬 수 있다.
2. 조회 수 처리를 위해 방문자·세션 식별자, IP 원문, User-Agent, 조회 시각과 개별 조회 이력을
   저장하지 않으며 자체 원시 이벤트·일별 분석 집계를 만들지 않는다.
3. 이 값은 새로고침·자동화 요청·여러 탭을 사람 단위로 구분하지 않으므로 이용자 수, 광고 정산,
   권리 판단이나 개인 행동 분석의 근거로 사용하지 않는다.
4. 접속·보안 로그는 장애 대응과 비정상 요청 차단 목적에 한해 별도로 처리하며 조회 수와 결합해
   방문 이력을 만들지 않는다.

법령상 별도 보존 의무가 있으면 근거, 항목과 기간을 공개하고 다른 정보와 분리 보관한다.

## 제5조 개인정보의 제3자 제공

개인정보를 제3자에게 상시 제공하지 않는다. 정보주체의 별도 동의 또는 법률의 특별한 규정 등 개인정보 보호법 제17조·제18조에 해당하는 경우에만 제공하며, 제공이 시작되면 제공받는 자, 목적, 항목과 보유 기간을 이 방침에 공개한다.

소셜 로그인 과정에서는 이용자가 선택한 제공자에게 인증 요청을 보내고, 제공자가 이용자 동의에 따라 블라리요에 회원 식별자를 전달한다. M1은 선택 프로필을 요청·저장하지 않는다. 블라리요는 인증 protocol 수행에 필요한 callback URL, client ID, `state`·`nonce`와 authorization code/token 교환 요청만 전송하며, 블라리요 서비스 이용 내역이나 다른 소셜 계정 정보를 제공하지 않는다.

| 개인정보를 제공하는 출처 | 수신 목적 | 수신 항목 | 보유 기간 |
| --- | --- | --- | --- |
| 네이버 | 회원가입·로그인·계정 연동 | 제공자 고유 식별자 | 회원 탈퇴 또는 연동 해제 시까지 |

| Google | 회원가입·로그인·계정 연동 | `sub` | 회원 탈퇴 또는 연동 해제 시까지 |

광고·분석 사업자가 독립된 개인정보처리자로 정보를 처리하는 구조라면 제3자 제공 해당 여부를 계약과 실제 데이터 흐름 기준으로 확정한 뒤 동의를 받는다.

## 제8조 개인정보의 파기 절차 및 방법

1. 보유 기간 경과, 처리 목적 달성, 동의 철회 등 파기 사유가 발생하면 지체 없이 파기한다.
2. 운영 담당자가 파기 대상을 확인하고 개인정보 보호책임자의 기준에 따라 파기 결과를 기록한다.
3. 전자 파일과 데이터베이스 값은 복구·재생하기 어렵도록 삭제하고 백업본은 백업 순환 주기에 따라 삭제한다.
4. 종이 또는 출력물이 생긴 경우 분쇄하거나 소각한다.
5. 법령상 보존 의무가 있는 정보는 별도 논리 영역으로 분리하고 정해진 목적 외에 이용하지 않는다.

## 제9조 정보주체와 법정대리인의 권리 및 행사 방법

1. 정보주체는 개인정보 열람, 정정·삭제, 처리정지, 동의 철회와 법령상 적용되는 경우 개인정보 전송을 요구할 수 있다.
2. 권리 행사는 `[출시 차단: 개인정보 문의 이메일 입력 필요]`로 본인 또는 적법한 대리인이 요청할 수 있다. 우편 주소와 전화번호는 사업자등록 또는 거래 기능 확정 전까지 `(미정)`으로 보류한다.
3. 요청자는 대상 정보와 요청 내용을 확인할 수 있는 최소 정보를 제출하며, 대리인은 위임 관계를 확인할 수 있는 자료를 제출한다.
4. 개인정보처리자는 본인·대리인 여부를 확인한 뒤 법정 기한 안에 처리 결과 또는 제한·거절 사유와 이의제기 방법을 알린다.
5. 법령에서 열람·삭제·처리정지를 제한하는 경우 그 근거를 안내한다.
6. 쿠키 설정에서는 분석·광고 동의를 즉시 철회할 수 있다.
7. 회원은 계정 설정에서 탈퇴하거나 확정된 개인정보 문의 채널로 탈퇴를 요청할 수 있다. 탈퇴 시 블라리요 계정과 소셜 연동 정보를 삭제하고 제공자가 지원하는 범위에서 연동 해제·토큰 폐기를 요청한다.
8. 소셜 제공자에서 블라리요 연동만 해제한 경우 서비스 세션을 종료하고 재로그인 또는 계정 복구 방법을 안내한다.
9. `[출시 차단: 직접 입력 생년월일을 이용한 만 14세 이상 판정 방식의 법무 적정성 검토 필요]` 법정대리인 동의 절차를 마련하기 전에는 14세 미만 가입을 허용하지 않는다.

### 전송요구권

블라리요 초기 서비스는 정보주체가 제공한 대규모 구조화 개인정보를 보유하지 않는다. 법령상 전송요구권 적용 대상과 전송 가능한 정보가 생기면 전송 범위, JSON·CSV 등 형식, 수신자 지정 방법, 진행 현황과 이력 확인 방법을 이 방침과 서비스 화면에 추가한다.

## 제10조 자동 수집 장치와 행태정보

1. M0 Core는 자체 방문 통계용 쿠키·로컬 저장소·세션 저장소를 만들지 않는다.
2. 소셜 로그인 과정의 세션 쿠키, OAuth `state`·`nonce`·PKCE 검증값은 로그인 위조와 재전송 공격 방지를 위한 필수 저장소이며 분석·광고 선택과 관계없이 사용한다.
3. GA4의 `_ga`, `_ga_*` 쿠키와 관련 Google tag는 저장된 분석 동의가 없는 접속에서 생성·호출하지
   않는다. 방문자 수·page open을 포함한 Google tag/request와 cookieless ping도 0건으로 유지한다.
4. 광고 쿠키는 광고 동의를 받은 뒤에만 활성화한다.
5. GA4와 광고가 모두 비활성인 환경에서는 선택 동의 배너와 비활성 기능의 선택 항목을 표시하지 않는다.
6. GA4 또는 광고 중 하나라도 활성화한 뒤 저장된 선택이 없는 최초 접속에는 하단 배너에서 `필수만 사용`, `설정`, `모두 허용`을 선택할 수 있다.
7. 선택 저장 뒤 modal과 배너를 닫고, 푸터의 쿠키 설정에서 언제든 변경하거나 철회할 수 있다.
8. 실제 저장소 이름, 목적, 생성 조건과 만료는 [쿠키 설정 안내](./cookie-settings.md)에 공개한다.
9. Measurement ID, GA4 속성 보관 설정, 실제 Google 계약 법인, 국외이전 고지와 Google tag/CSP
   domain이 모두 확정된 환경에서만 GA4를 활성화한다. 이 값이 미확정이어도 M0 Core 공개 자체는
   막지 않으며 `NUXT_PUBLIC_GA4_ENABLED=false`를 유지한다.

### 브라우저에서 거부·삭제하는 방법

- Chrome: 설정 → 개인정보 및 보안 → 서드 파티 쿠키 또는 인터넷 사용 기록 삭제
- Safari: 설정 → 개인정보 보호 → 웹사이트 데이터 관리
- Edge: 설정 → 쿠키 및 사이트 권한 → 쿠키 및 사이트 데이터 관리
- Firefox: 설정 → 개인정보 및 보안 → 쿠키와 사이트 데이터
- 시크릿·개인정보 보호 창을 사용하거나 브라우저 저장소를 직접 삭제할 수 있다.

모든 저장소를 차단하면 선택 기억과 로그인 세션이 초기화될 수 있지만 공개 콘텐츠 열람은 유지한다.

### 맞춤형 광고와 행태정보

맞춤형 광고를 시작하기 전까지 광고 사업자에게 행태정보를 전송하지 않는다. 시작하려면 수집 주체, 목적, 항목, 보유 기간, 수집 방법, 거부 방법과 국외이전을 확정해 이 방침에 공개하고 광고 동의를 받아야 한다.

## 제11조 자동화된 결정과 AI 학습

블라리요는 소셜 로그인 성공 여부를 제공자의 인증 결과와 자체 보안 검증에 따라 처리하지만, 개인에게 법적 또는 중대한 영향을 주는 자동화된 결정을 하지 않는다. 이용자 개인정보를 생성형 AI 학습 데이터로 제공하지 않는다. 향후 해당 처리가 생기면 결정 기준·절차·방식, 결과 설명·거부·인적 재처리 요구 방법 또는 학습 데이터 출처·보호조치·삭제 요구 방법을 기능 공개 전에 이 방침에 추가한다.

## 제12조 개인정보의 안전성 확보 조치

1. 관리적 조치: 개인정보 처리 권한 최소화, 운영자 계정 분리, 처리 기록 점검, 권리 소명 자료 접근 제한과 정기적인 보유 정보 정리
2. 기술적 조치: 전송 구간 암호화, OAuth authorization code flow와 `state`·`nonce`·PKCE 검증, 세션 쿠키 `HttpOnly`·`Secure`·적절한 `SameSite`, 접근통제, 접속기록 보관·점검, 취약점·악성코드 대응과 provider client secret 분리
3. 물리적 조치: 서버·자료 보관 장소에 대한 제공 사업자의 물리적 접근통제 확인
4. 사고 대응: 유출·위조·변조·훼손 또는 그 가능성을 인지하면 영향 범위를 확인하고 법령상 통지·신고와 재발 방지 조치를 수행

## 제14조 정보주체의 권익침해 구제 방법

정보주체는 개인정보 침해에 관한 상담이나 분쟁 해결을 다음 기관에 신청할 수 있다.

- 개인정보분쟁조정위원회: 국번 없이 `1833-6972`, `www.kopico.go.kr`
- 개인정보침해신고센터: 국번 없이 `118`, `privacy.kisa.or.kr`
- 대검찰청: 국번 없이 `1301`, `www.spo.go.kr`
- 경찰청: 국번 없이 `182`, `ecrm.police.go.kr`

## 제15조 개인정보처리방침의 변경과 개정 이력

1. 이 방침은 시행일부터 적용한다.
2. 변경 시 적용일과 주요 변경 내용을 원칙적으로 7일 전에 공지하고, 정보주체 권리에 중대한 영향을 주는 변경은 30일 전에 알린다.
3. 현재 적용 본문과 시행된 이전 버전의 전문을 `/privacy` modal 하단 개정 이력에서 확인할 수 있게 보관한다.
4. 개정 이력은 `버전, 적용 기간`만 표시하고 행 전체를 선택하면 해당 버전 전문을 연다. 현재 버전은 `yyyy.mm.dd ~ 시행 중`, 이전 버전은 `yyyy.mm.dd ~ yyyy.mm.dd` 형식을 사용한다.
5. 최초 버전은 `v0.1`이며 시행일은 `[출시 차단: 시행일 입력 필요]`이다.
