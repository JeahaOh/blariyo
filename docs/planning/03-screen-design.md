## 1. 화면 원칙

- 블로그형 카드보다 커뮤니티 게시판형 목록을 사용한다.
- 같은 URL과 컴포넌트를 화면 폭에 따라 재배치한다.
- 초기에는 `짤` 게시판 하나만 공개한다.
- `/`는 `/meme`으로 리다이렉트한다.
- 게시판 추가를 고려하되 아직 공개하지 않는 메뉴는 보여주지 않는다.
- 목록에서 상세로 들어가고 상세 하단 목록에서 다음 글을 고르는 흐름을 유지한다.

```text
/ -> /meme -> /meme/posts/:postId -> 같은 meme 게시판 하단 목록 -> /meme/posts/:postId
```

### 관리자 게시글 화면

| 화면 | 경로 | 상태 |
| --- | --- | --- |
| 게시글 검색·작성·상태 관리 | `/admin` | M0 Core |
| 수집 후보 검수 | `/admin/collect` | M0 수집 보조 이후 |
| 수집 출처 관리 | `/admin/collect/sources` | M0 수집 보조 이후, 목록 수집 설정은 M0 자동 수집 |

- Cloudflare Access 인증을 통과한 운영자만 접근한다.
- 데스크톱은 왼쪽 검색 목록과 오른쪽 편집 영역을 함께 표시하고, 모바일은 목록과 편집 영역을 위아래로 배치한다.
- 상태·게시판·제목 앞부분으로 검색하고 게시글 상태와 `lockVersion`을 함께 표시한다.
- 새 초안과 기존 게시글은 같은 편집기를 사용한다. TEXT·IMAGE block 추가·제거·순서 변경, 이미지 preview, 대체 텍스트, 출처와 공지 순서를 편집한다.
- 상태별로 가능한 `즉시 발행`, `예약`, `예약 취소`, `숨김`, `재공개`, `최종 삭제`만 표시한다. 저장하지 않은 내용이 있으면 상태 변경을 막고 먼저 저장하도록 안내한다.
- 숨김 직후 public image 삭제가 진행 중이면 재공개·최종 삭제를 비활성화하고 새로고침 후 다시 확인하게 한다.
- 최종 삭제는 되돌릴 수 없는 `REMOVED` 전환임을 확인창에 명시한다.
- 동시 수정 충돌은 `다른 변경이 반영되었습니다. 최신 내용을 확인한 뒤 다시 저장해 주세요.`로 안내하고 사용자의 입력을 자동 덮어쓰지 않는다.

### 수집 후보 검수 화면

- 상단에 원문 URL 입력란과 `후보 만들기`를 두고, 처리 중에는 중복 요청을 막는다. Discord `/collect url`
  명령으로 생성된 후보도 같은 목록에 표시한다.
- 후보 목록에는 출처명, 제목, 원문 링크, 이미지 후보 수, 수집 시각, 상태, 중복 표시를 보여준다.
- 상태는 `PENDING`(수집 대기), `RUNNING`(수집 중), `NEW`(검수 대기), `FETCH_FAILED`(수집 실패), `APPROVED`(초안 승격), `REJECTED`(반려)로 표시한다. preview 만료는 파일 상태이며 별도 후보 상태가 아니다.
- 후보 상세에서는 제목과 이미지 후보 미리보기를 확인하고 사용할 이미지를 선택한 뒤 `초안으로 승격` 또는 `반려`를 선택한다.
- 승격은 collector가 제출한 preview 또는 운영자 업로드 이미지를 검증·재인코딩해 블라리요 저장소에 저장하고
  초안 편집기를 그 게시글로 연다. 서버는 원격 URL을 직접 fetch하지 않는다. 출처명과 원문 URL은 후보 값으로 미리 채우되 운영자가 수정할 수 있다.
- 중복으로 표시된 후보는 승격 전에 기존 게시글을 함께 보여주고, 그래도 승격하려면 한 번 더 확인받는다.
- 단일 상세 페이지에서 이미지 후보를 가져올 수 없거나 원문이 사라진 후보는 실패 사유를 표시하고 재시도 또는 반려만 허용한다.
- 후보 화면에는 요청 원문 HTML 전체, Python 임시 파일 내부 경로, 내부 오류 상세를 노출하지 않는다.

### 수집 출처 관리 화면

- 출처명, 기준 URL, 수집 방식, 목록 주소, 활성 여부, 요청 간격, 일일 상한, robots 확인 결과·확인일, 최근 수집 시각·최근 오류를 표시한다.
- 목록 수집은 robots 확인 결과가 허용이고 목록 주소가 있을 때만 활성화할 수 있다.
- 자동 비활성된 출처는 사유와 최근 수정 시각을 표시하고 운영자가 확인한 뒤에만 다시 활성화한다. 최근 수정 시각을 정확한 차단 발생 시각으로 표시하지 않는다.

## 3. 반응형 레이아웃

| 구간 | 폭 | 레이아웃 |
| --- | --- | --- |
| Mobile | `360~767px` | 전체 폭, 단일 열 |
| Tablet | `768~1023px` | 최대 760px, 단일 열 |
| Desktop | `1024px 이상` | 최대 760px, 단일 열과 외곽 여백 |

- 모바일에서 가로 스크롤이 생기지 않게 한다.
- 상세 본문은 데스크톱에서도 읽기 폭을 과도하게 늘리지 않는다.
- 광고와 보조 정보는 본문보다 먼저 나오지 않는다.
- 모바일에서는 게시판명, 작성자, 조회 수처럼 우선순위가 낮은 열을 숨길 수 있다.
- 최대 760px 콘텐츠 면 밖의 외곽과 헤더 자식 영역 밖의 여백은 `#3A4A5A`로 통일한다.
- 목록·본문·헤더 내부·게시판 내비게이션은 밝은 표면을 유지한다.

## 4. 헤더

### 초기

- 로고 `블라리요`를 표시한다.
- 로고를 누르면 `/meme`으로 이동한다.
- 게시판이 하나뿐이므로 메뉴를 생략하거나 `짤` 하나만 표시한다.
- M0 상세 화면에서는 게시판 메뉴를 숨기고 `← / 한 줄 제목 / 공유 아이콘` 고정 헤더를 표시한다. `←`와 공유 아이콘의 접근성 이름은 각각 `목록으로`, `공유하기`로 제공한다.
- M1부터 비로그인 상태에는 `로그인`, 로그인 상태에는 최소 크기의 프로필·계정 메뉴를 추가한다.
- 검색, 글쓰기, 알림은 표시하지 않는다.

### 게시판 확장 후

활성화된 게시판 데이터만 메뉴로 표시한다.

| 표시명 | 코드 | 경로 |
| --- | --- | --- |
| 짤 | `meme` | `/meme` |
| 익게 | `community` | `/community` |
| 뉴스 | `news` | `/news` |

새 게시판은 같은 규칙으로 추가한다. 화면 코드에 게시판 개수를 고정하지 않는다.

## 5. 짤 목록 `/meme`

### 구성

1. 헤더
2. 페이지 제목 `짤`
3. 고정 공지 0~3건
4. 최신순 일반 게시글 20건
5. 후속 목록 중간 광고 행 후보. M0에서는 렌더링하지 않음
6. 페이지네이션
7. 정책 링크 푸터

### 목록 규칙

- 페이지당 게시글 20개를 표시한다.
- 고정 공지는 최대 3건이며 일반 게시글 20개와 광고 위치 계산에서 제외한다.
- 공지 순서는 `pinnedPosition ASC`, 일반 글은 `publishedAt DESC, postId DESC`다.
- 후속 광고 기능을 활성화해도 광고 행은 게시글 20개에 포함하지 않는다.
- 정렬은 `publishedAt DESC, postId DESC`다.
- 행 전체를 상세 링크로 사용한다.
- 무한 스크롤은 사용하지 않는다.

| 항목 | 데스크톱 | 모바일 |
| --- | --- | --- |
| 번호 | 표시 | 표시 |
| 게시판 | 초기에는 생략 가능 | 생략 |
| 제목 | 한 줄 | 한 줄 또는 두 줄 |
| 조회 수 | 표시 | 필요 시 숨김 |
| 작성자 | `운영자` | 숨김 가능 |
| 게시 시각 | 표시 | 표시 |

공지는 번호 대신 `공지` 배지를 제목 앞에 표시하고 일반 글보다 옅은 골드 배경으로 구분한다.

### 후속 목록 광고

- M0에서는 광고 행을 렌더링하지 않는다.
- 목록 중간에 광고 행 1개를 배치할 수 있다.
- 첫 게시글 앞에는 넣지 않는다.
- 광고 표기, 배경, 높이로 게시글과 구분한다.
- 광고 로드 실패 시 행을 접고 게시글 목록은 그대로 유지한다.

### 상태

| 상태 | 화면 |
| --- | --- |
| 로딩 | 목록 행 형태 skeleton |
| 빈 목록 | `아직 올라온 짤이 없습니다` |
| 오류 | 오류 안내와 `다시 시도` |
| 마지막 페이지 | `다음` 비활성화 |

## 6. 게시글 상세 `/:boardSlug/posts/:postId`

### 구성 순서

1. `← / 한 줄 제목 / 공유 아이콘` 고정 헤더. M1부터 로그인·계정 진입 추가
2. 전체 제목
3. 번호, 게시 시각, 조회 수
4. 본문 이미지와 텍스트
5. 출처
6. `AD-POST-BODY-BOTTOM`
7. 같은 게시판의 현재 글 주변 목록 20개
8. 목록 중간 `AD-DETAIL-LIST-INLINE`
9. 목록 아래 `AD-DETAIL-LIST-AFTER`
10. 정책 링크 푸터

### 본문과 이미지

- 이미지는 블라리요 서버 측 저장소의 URL을 사용한다.
- 외부 원본 이미지 URL을 직접 핫링크하지 않는다.
- 원본 비율을 유지하고 콘텐츠 폭을 넘지 않는다.
- 이미지 대체 텍스트를 제공한다.
- 이미지 로딩 전 비율 공간을 확보한다.
- M0 저장 사업자는 Cloudflare R2 Standard로 결정했다. 실제 production account, bucket 이름과
  public media custom domain은 배포 전에 확정한다.

### 출처

- 본문이 끝난 뒤 한 번만 표시한다.
- 출처명 전체를 원문 URL 링크로 표시하고 별도 `원문 보기` 버튼은 두지 않는다.
- 출처 표시는 권리 보유나 사용 허가를 뜻하지 않는다.
- 내부 검토 메모는 공개하지 않는다.

### 상세 하단 목록

- 현재 글과 같은 게시판의 게시글을 최대 20개 표시한다.
- 현재 글을 목록에 포함하고 선택할 수 없는 강조 행으로 표시한다.
- 현재 글 행에 `aria-current="true"`를 부여하고 링크와 tab stop을 만들지 않는다.
- 이전 글·다음 글 버튼은 두지 않는다.
- 홈 목록과 같은 이전·페이지 번호·다음 페이지네이션을 목록 아래에 둔다.
- 최초에는 현재 글이 포함된 페이지를 선택하고, 페이지 이동 시 상세 본문과 스크롤 위치는 유지한 채 하단 목록만 교체한다.
- 목록으로 링크는 현재 게시판 경로로 이동한다. 초기에는 `/meme`이다.
- 목록 아래 광고의 하단 여백은 최소화하고 상세 하단 목록과 푸터가 한 흐름으로 이어지게 한다.

### 없음·숨김

- 없는 글, 숨김 검토 중인 글, URL 게시판과 소속 게시판이 다른 글은 공개 화면에서 같은 404 상태로 처리한다.
- 제목, 본문, 이미지, 출처와 요청 사유를 노출하지 않는다.
- `볼 수 없는 게시글입니다`와 `/meme` 이동 링크를 표시한다.
- 게시글 로딩·오류·숨김 상태의 고정 헤더에는 M0에서 `← / 상태 제목`을 표시하고 게시판 메뉴와 공유 아이콘은 숨긴다. M1부터 로그인·계정 진입을 추가한다.
- 빈 목록은 게시판 목록 상태이므로 뒤로가기 없이 기존 목록 헤더를 유지한다.

## 7. 공유와 OG

### 공유 동작

- 모바일은 `navigator.share`를 먼저 시도한다.
- 모든 환경에서 링크 복사를 제공한다.
- 카카오톡 공유는 Kakao JavaScript SDK로 제공한다. 실제 JavaScript key와 카카오 개발자 콘솔 Web
  domain 등록을 확인한 환경에서만 활성화한다. SDK script URL·SRI integrity·JavaScript key·CSP host는
  배포 환경 properties/config로 관리하며, 비활성 또는 script 로드 실패 시 카카오톡 항목만 숨기고
  링크 복사와 브라우저 기본 공유를 유지한다. 세부 계약은 [보안·운영 설계](../system-design/05-security-operations.md)를 따른다.
- X/Twitter 공유를 제공한다.
- 공유 성공·실패 결과를 화면에 알린다.
- 공유 진입점은 상세 고정 헤더 오른쪽 한 곳에만 둔다.
- 공유 버튼을 누르면 본문 안에 영역을 펼치지 않고 떠 있는 popup으로 표시한다.
- 데스크톱은 헤더 공유 버튼 아래 floating panel, 모바일은 화면 하단 share sheet를 사용한다.
- 바깥 클릭, 닫기, `Escape`로 popup을 닫는다.

### URL

- 서비스 공개 기준 URL: `https://blariyo.com/`
- 목록 canonical: `https://blariyo.com/meme`
- 상세 canonical: `https://blariyo.com/{boardSlug}/posts/{postId}`
- `/`는 `/meme` 리다이렉트이므로 별도 canonical 페이지로 만들지 않는다.
- 숨김·삭제 글은 `noindex` 처리한다.

### 필수 meta

- `title`
- `description`
- `canonical`
- `og:site_name`, `og:type`, `og:url`, `og:title`, `og:description`, `og:image`
- `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`

정상 상세 metadata는 다음 우선순위를 따른다.

- `og:image`와 `twitter:image`는 첫 공개 IMAGE block의 절대 HTTPS URL을 사용한다. 공개 IMAGE block이
  없으면 `/og/blariyo-default.png`를 서비스 기준 URL과 결합한 절대 URL을 사용한다.
- `description`, `og:description`, `twitter:description`은 모두 첫 공개 TEXT block의 plain text에서
  앞뒤 Unicode whitespace를 제거하고, 내부의 하나 이상 연속된 Unicode whitespace를 단일 U+0020
  space로 치환한 같은 값을 사용한다. 이 정리 뒤 grapheme 수를 센다. 120자 이하면 길이가 80자
  미만이어도 문구를 덧붙이지 않고 그대로 사용한다. 120자를 초과하면 Unicode grapheme cluster 기준
  앞 119자 뒤에 단일 `…`를 붙여 총 120자 이하로 만든다. UTF-16 code unit이나 byte 수로 자르지
  않는다. 공개 TEXT block도 없으면 확정 서비스 기본 문구 `블라리요에서 블라블라블라`를 사용한다.

홈·OG·푸터 카피와 properties/config key는 [06-copy-contract.md](./06-copy-contract.md)의 확정 계약을 따른다.

## 8. 후속 광고

이 절은 광고 기능을 활성화하는 후속 단계의 화면 계약이며 M0 검수 대상이 아니다.

상세 광고는 다음 세 개만 사용한다.

| 슬롯 | 위치 |
| --- | --- |
| `AD-POST-BODY-BOTTOM` | 본문과 출처 다음 |
| `AD-DETAIL-LIST-INLINE` | 하단 목록 중간 |
| `AD-DETAIL-LIST-AFTER` | 하단 목록 아래 |

- 상세 상단, 우측, 앵커, 전면형 광고는 두지 않는다. 광고 차단 해제 요청 modal은 광고 슬롯과 별도로 취급한다.
- 광고 크기만큼 공간을 예약해 레이아웃 이동을 줄인다.
- timeout, no-fill, 네트워크 오류에는 슬롯만 접는다.
- 광고 차단이 확인된 경우에만 전면 dim modal을 표시한다.
- modal이 열린 동안 배경 클릭과 스크롤을 막는다.
- 닫기, `계속 보기`, `Escape`로 닫을 수 있고 닫은 뒤 본문·공유·목록 이동을 제한하지 않는다.
- 닫은 modal은 같은 세션에서 다시 자동 표시하지 않는다.

## 9. M1 소셜 회원가입·로그인

### 로그인 `/login`

- 네이버, 카카오, Google, Apple 버튼을 같은 중요도로 세로 배치한다. 각 제공자의 공식 브랜드 색·문구·아이콘 지침을 따른다.
- 소셜 버튼 위에는 `짤은 로그인 없이 볼 수 있어요`를 표시해 로그인 강제를 오해하지 않게 한다.
- 로그인 시작 전 개인정보 처리방침과 이용약관 링크를 제공하지만, 링크 확인만으로 가입 동의를 받은 것으로 처리하지 않는다.
- OAuth 오류는 `사용자가 취소함`, `제공자 응답 오류`, `이미 다른 계정에 연결됨`, `일시적 장애`를 구분하고 재시도와 `/meme` 돌아가기를 제공한다.

### 가입 동의 `/signup/consent`

- 소셜 인증에 성공했지만 기존 연동 계정이 없을 때만 표시한다.
- 제공자 이름과 서비스 표시명 입력란을 보여준다. 이메일·프로필 사진은 요청·저장하지 않으며 표시명은 NFC 정규화·trim 후 2~20 Unicode code point다.
- 생년월일을 필수로 직접 입력받아 서버에서 만 14세 이상인지 판정한다. 체크박스로 대체하지 않으며 생년월일은 저장하지 않는다.
  잘못된 날짜·미래 날짜는 입력 오류, 만 14세 미만은 가입 불가를 표시한다. 화면에는 연령 확인 후 생년월일을 보관하지 않음을 안내한다. 확인 방식의 적정성 검토 전 가입 공개는 차단한다.
- 이용약관 동의와 [회원가입 개인정보 수집·이용 전문](../legal/signup-privacy-consent.md)에 대한 동의를 각각 필수 checkbox로 받고 개인정보처리방침 전문 링크를 제공한다. 마케팅·분석·광고 동의는 회원가입 필수 동의에 합치지 않는다.
- 분석·광고 선택은 쿠키 설정에서 별도로 받으며 거부해도 가입과 공개 콘텐츠 열람이 가능하다.
- `가입 완료` 전에는 정식 회원 레코드와 로그인 세션을 확정하지 않는다. 취소하면 임시 인증 정보를 즉시 폐기하고 `/meme`으로 이동한다.

### 계정 `/account`

- 현재 연결된 제공자와 최근 인증 시각, 로그아웃, 회원 탈퇴를 제공한다.
- 이메일·프로필 사진은 표시하지 않는다. 서비스 표시명 수정, 현재 기기·모든 기기 로그아웃을 제공한다.
- 계정 연결·해제는 provider 재인증 뒤 수행한다. 마지막 로그인 수단을 해제하려면 다른 제공자 연결 또는 탈퇴를 먼저 요구한다.
- 탈퇴 확인 화면에는 삭제 대상, 법령상 분리 보존 항목, 제공자 연동 해제와 [콘텐츠 처리](08-member-community-plan.md#3-m1-계정-연결세션탈퇴)를 표시한다.
- 가입 중단 상태에서도 기존 회원 로그인·재인증·삭제·탈퇴 진입을 표시한다. 새 가입·계정 연결 버튼만 중단 안내로 전환한다.
- 연동 해제 진행/확인 대기 중 동일 소셜 계정 재연결은 처리 중 안내를 제공한다.
- 연결·해제는 최근 재인증이 없으면 인증 화면으로 이동한다. 연결 충돌·마지막 로그인 수단 오류는 계정 상태를 새로 읽고 안내한다.
- 현재 유효한 제재만 제한 중으로 표시한다. 수동 해제 또는 기간 종료 뒤에는 정리 작업을 기다리지 않고
  참여 동작을 다시 보여준다. 제한 중인 회원에게 공개 가능한 사유·종료 시각과 이의제기 이메일을 표시한다.
  신고자·내부 메모는 보이지 않는다.

### 재동의 `/account/consent`

- 변경된 약관·수집이용 동의 전문과 버전, 각각의 필수 checkbox를 표시한다. 개인정보처리방침은 별도 전문 링크다.
- 동의 전에는 작성·댓글·신고를 막지만 읽기·로그아웃·탈퇴는 허용한다. 저장 중 정책이 바뀌면 최신 본문을 다시 표시하고 체크를 초기화한다.

### 탈퇴 `/account/withdraw`

- 최근 재인증 뒤 본인 글·댓글 수, 계정 삭제 항목, 외부 연동 해제 결과가 별개임을 안내한다.
- 글·댓글은 탈퇴 후에도 유지되고 계정 연결만 제거되며 일반 수정·삭제가 불가능함을 안내한다. 삭제/유지 선택은 제공하지 않는다.
- 최종 확인에는 되돌릴 수 없음을 명시하고 실행 중 중복 제출을 막는다. 접수 뒤 로그인 cookie와 편집 메모리를 제거한다.
- 접수/처리 중/완료/일부 외부 해제 실패를 구분한다. 제공자 해제 실패를 회원 탈퇴 실패로 표시하지 않는다.
- 24시간 결과 조회 만료·응답 유실 시 지원 이메일을 안내하며 자동 재가입시키지 않는다.

## 10. 정책 modal과 직접 경로

- 푸터의 이용약관, 개인정보처리방침, 쿠키 설정은 현재 화면 위 modal로 연다.
- modal은 화면 전체 dim, 배경 `inert`, 스크롤 잠금을 적용한다.
- 우측 상단 닫기, `Escape`, dialog 바깥 dim 영역 클릭을 지원하고 닫힌 뒤 원래 포커스로 돌아간다.
- `/terms`, `/privacy`, `/cookie-settings` 직접 접근 경로는 유지한다.
- JavaScript가 없거나 modal을 열 수 없는 환경에서는 직접 경로로 이동한다.

### 이용약관·개인정보처리방침

- modal을 열면 현재 적용 버전의 전체 본문을 바로 표시한다.
- 본문 하단에 `버전, 적용 기간`만 가진 개정 이력을 둔다.
- 적용 기간은 현재 버전은 `yyyy.mm.dd ~ 시행 중`, 이전 버전은 `yyyy.mm.dd ~ yyyy.mm.dd`로 표시한다.
- 개정 이력 행 전체를 선택하면 같은 modal의 전체 본문을 해당 버전으로 교체하고 문서 상단으로 이동한다.
- 현재 버전과 과거 버전은 별도 레코드로 보관한다.

### 권리 침해·게시 중단 이메일

- 푸터 링크를 누르면 권리자 요청 이메일 작성 화면을 연다.
- 제목에는 서비스명과 문의 유형, 본문에는 현재 화면 URL과 요청 내용 입력란을 미리 넣는다.
- 푸터에는 이메일 주소를 길게 노출하지 않고 `권리 문의`와 `이메일 주소 복사`를 각각 표시한다.
- `권리 문의`는 `mailto`를 열고, `이메일 주소 복사`는
  `BLARIYO_RIGHTS_CONTACT_EMAIL`의 이메일 주소만 복사한다. 제목·본문은 복사하지 않는다.
- 두 동작은 항상 함께 접근할 수 있어야 하며 browser에서 mail client 실행 성공·실패를 감지해
  복사 동작을 뒤늦게 표시하는 분기를 만들지 않는다.
- 주소 복사 성공·실패는 `aria-live`로 알리되 mail client 실행·메일 전송 성공 여부는 추측하지 않는다.
- 운영자가 메일을 확인한 뒤 대상 게시글을 우선 숨기고 재공개, 수정, 삭제 또는 비노출 유지를 결정한다.
- 처리 결과는 요청자에게 이메일로 회신한다.

### 쿠키 설정 `/cookie-settings`

- M0 Core에는 GA4 선택 UI를 구현하되 기본 비활성으로 둔다. GA4 또는 광고처럼 동의가 필요한
  선택 기능을 실제 활성화한 환경에서만, 저장된 선택이 없는 최초 접속에 화면 하단 쿠키 배너를
  표시하되 콘텐츠 클릭과 스크롤은 막지 않는다.
- 배너는 `필수만 사용`, `설정`, `모두 허용`을 제공하고 `설정`을 누르면 쿠키 설정 modal을 연다.
- 쿠키 설정에는 실제 사용하는 필수·설정 저장소만 표시한다. 활성 저장소가 없으면 `현재 활성화된
  저장소가 없습니다` 상태를 표시하고, 실제 활성화한 분석·광고 항목만 선택할 수 있게 한다.
- 선택 저장 후 modal과 배너를 닫고 같은 선택 범위에서는 다시 자동 표시하지 않는다. GA4·광고
  활성 상태가 바뀌어 선택 범위가 달라지면 새 범위를 다시 선택받는다.
- 분석에 동의하기 전에는 Google tag를 로드하지 않으며 GA4 요청과 `_ga*` 저장값이 없어야 한다.

## 11. 추후 게시판 화면

### 익게 `/community`

- 사용자 작성 게시판이다.
- 소셜 회원 계정을 사용하며 [회원·익게 제품 계약](08-member-community-plan.md)을 따른다.
- 목록은 제목·댓글 수·게시 시각·조회 수를 표시하는 20행 페이지 방식이다. 비회원도 읽을 수 있다.
- 목록 `글쓰기`는 회원이면 `/community/new`, 비회원이면 검증된 돌아올 경로와 함께 로그인으로 이동한다.
- 상세에는 제목·글별 랜덤 이름·`글쓴이` 배지·시각·텍스트 본문, 본인 수정/삭제, 신고, 댓글, 같은 게시판 하단 목록 순으로 표시한다.
  댓글 삽입은 M0 짤 상세 구성에 영향을 주지 않는 M1.5 확장이다. 광고·추천 버튼은 없다.
- 댓글은 글별 랜덤 이름을 표시하고 원글 작성자의 댓글에는 별도 `글쓴이` 배지를 함께 표시하며 한 단계·20개 페이지다. 수정·삭제 버튼은 본인에게만 표시한다.
  숨김/삭제 댓글에는 일반 안내만 남기고 원문·랜덤 이름을 숨긴다.
- 신고 버튼은 로그인 후 사유·설명 modal을 연다. 기타는 설명 필수, NFC 정규화·trim 후 최대 500 Unicode code point, 첨부 입력은 없다.
  성공 후 접수 완료를 알리고 닫는다. 중복 신고는 이미 접수됨을 안내한다.
- 본인 글 삭제 확인 후 목록으로 이동한다. 숨김·없는 글의 상세는 일반 404와 `/community` 링크를 표시한다.

### 익게 편집 `/community/new`, `/community/posts/:postId/edit`

- 제목 200자, 본문 10,000자 plain text 입력과 NFC 정규화·trim 후 Unicode code point 기준 글자 수·오류를 표시한다.
  제목에는 CR·LF·U+2028·U+2029 줄바꿈을 허용하지 않고 본문의 CRLF·CR·U+2028·U+2029는 LF로
  통일해 LF를 1 code point로 센다. 이미지·Markdown·예약·초안 저장은 없다.
- 수정 진입 시 공개 상세와 본인 권한을 모두 확인한다. 타인 글은 404, 숨김 글은 내 활동에서 삭제만 가능하다.
- 저장 중 버튼을 잠그고 성공하면 상세로 이동한다. 409 충돌은 입력을 덮어쓰지 않고 최신 글 확인을 제공한다.
- 401은 부모 편집 화면을 유지한 별도 인증 창으로 재로그인한다. 인증 뒤 `인증 완료 확인`에서 세션·CSRF·소유권을 다시 확인한다. 팝업 차단은 입력 유지·재시도·내용 복사를 제공하며 부모 화면을 자동 이동하지 않는다. 403 재동의는 편집 화면 dialog, 제재는 사유 안내, 429는 재시도 시각을 표시한다.
- 미저장 상태 이탈은 확인창을 제공한다. 브라우저를 닫은 뒤 초안 복구를 보장하지 않는다.

### 내 활동 `/account/activity`

- 글·댓글·신고 탭을 각각 페이지 방식으로 조회한다. 숨김 상태에서도 본인 콘텐츠 삭제 진입을 제공한다.
- 글이 숨겨져도 본인 댓글 삭제를 허용한다. 타인 원문이나 신고자 정보는 반환하지 않는다.
- 빈 목록은 `작성한 글이 없습니다`, `작성한 댓글이 없습니다`, `접수한 신고가 없습니다`로 구분한다.

### 운영 관리 `/admin/moderation`

- 외부 관리자 인증 뒤 대기/종결 필터·신고 목록·상세를 제공한다. 모바일은 목록→상세, 데스크톱은 두 영역이다.
- 상세에는 대상 현재 콘텐츠·상태·신고 사유, 무조치/숨김/삭제, 공개 사유와 내부 메모 입력이 있다.
- 신고 없는 직접 검토는 `/admin/moderation/posts/:postId`와 그 하위 `/comments/:commentId`로 진입한다. 글별 관리자 댓글 목록에서 숨김·삭제 상태도 조회하며 댓글 상세의 현재 버전과 제재 대상 참조를 사용한다. 신고를 대신 생성하지 않는다.
- 제재는 해당 대상 회원 참조로만 진입하고 기간·공개 사유를 입력한다. 소셜 식별자와 신고자 개인정보는 표시하지 않는다.
- 복원은 별도 확인 동작이며 삭제 콘텐츠는 복원 버튼이 없다. 이미 다른 운영 처리가 끝나면 충돌 안내와 새로고침을 제공한다.
- 모든 modal은 dialog 이름, focus 진입·복귀, Escape, 키보드 작동을 제공한다. 처리 중 종료는 서버 취소를 뜻하지 않는다.
- 초기 짤 화면에 미리 노출하지 않는다.

### 뉴스 `/news`

- 뉴스 게시판이다.
- 목록과 상세의 기본 골격은 짤 게시판을 재사용할 수 있다.
- 뉴스용 출처 표현과 게시 주체는 개발 전에 별도 결정한다.

## 13. 검수 기준

### M0 Core

- `/`가 `/meme`으로 이동한다.
- 초기 헤더와 목록에 `익게`, `뉴스`가 노출되지 않는다.
- 초기 헤더에 로그인·계정 진입이 없다. GA4 비활성 환경에서는 선택 배너가 없고, GA4 활성
  환경에서는 저장된 선택이 없을 때 비차단형 선택 배너가 표시된다.
- `/meme` 목록에 일반 게시글 20개와 고정 공지 0~3건이 분리돼 보인다.
- 상세 출처가 하단에 한 번만 나온다.
- 상세 하단 목록은 같은 게시판 20개이며 현재 글을 포함하고 페이지네이션을 제공한다.
- 푸터 이메일 링크에 현재 화면 URL이 포함되고 본문에는 별도 권리자 요청 링크가 없다.
- 운영자가 요청 메일을 확인한 뒤 게시글을 `HIDDEN_REVIEW`로 변경할 수 있다.
- 360px, 768px, 1280px에서 가로 스크롤이 없다.
- 키보드만으로 목록, 상세, 공유, 정책 링크를 사용할 수 있다.
- 숨김 글의 내용과 내부 검토 사유가 HTML에 남지 않는다.
- 카카오톡 공유 script를 차단한 환경에서도 공유 popup이 열리고 링크 복사가 동작한다.
- GA4 비활성 환경과 분석 거부 상태 모두에서 GA4 요청과 `_ga*` 생성이 없고 목록·상세가 정상 동작한다.

### M0 수집 보조

- 운영자가 원문 URL로 후보를 만들고 검수해 초안으로 승격할 수 있으며, 후보 화면은 공개 경로에서 접근할 수 없다.
- 허용하지 않은 대상이나 robots 금지 경로 요청은 후보를 만들지 않고 사유를 표시한다.

### M0 자동 수집

- 후속 자동 수집 단계에서만 사용한다. 사용 결정된 출처만 목록 수집을 활성화할 수 있고 차단·연속 실패 출처는 자동 비활성된다.

### M1

- 네 provider 인증 취소·실패가 회원 생성으로 이어지지 않는다.
- 최초 가입에서 Blariyo 이용약관·회원가입 개인정보 수집·이용 동의 이력이 각각 저장된다.
- 분석 거부 상태에서 GA4 요청과 `_ga*` 생성이 없고 소셜 로그인은 정상 동작한다.
- 탈퇴 시 세션, 회원·연동 정보와 provider unlink/revoke 결과를 확인할 수 있다.

### M1.5

- 비회원은 읽기만, 회원은 동의·제재 상태에 맞춰 참여한다.
- 다른 글 사이의 작성자 ID·랜덤 이름 연결 단서가 HTML·API·분석 요청에 없다.
- 동시 댓글, 409 수정 충돌, 429, 중복 신고, 숨김·삭제 후 원문 비노출을 확인한다.
- 탈퇴 시 콘텐츠 유지·계정 연결 제거와 타인 댓글 보존을 검증한다. 현재 HTML 프로토타입은 이 확장 계약을 검증한 증거가 아니다.

### 후속 광고

- 광고 행을 제외하고 일반 게시글 20개가 유지된다.
- 상세 광고는 지정된 세 위치에만 있다.
- 광고 실패·차단 상태에서도 콘텐츠 열람과 이동을 계속할 수 있다.

### 인증 완료와 복귀 화면 보충

`/auth/complete`는 팝업 인증 완료 전용이다. 부모 화면의 `인증 완료 확인`과 창 닫기를 안내하고
credential·회원 정보를 URL이나 창 메시지로 전달하지 않는다. `/account/withdraw`, `/account/consent`는
재인증 후 복귀를 허용하며 현재 상태를 다시 읽는다. 복귀만으로 탈퇴·동의·연결 해제를 실행하지 않는다.
