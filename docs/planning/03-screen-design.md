# 블라리요 반응형 웹 화면 설계서

- 문서 상태: 사용자 확정안 반영 정본
- 기준일: 2026-08-12
- 관련 문서: [01-service-plan.md](./01-service-plan.md), [02-infra-plan.md](./02-infra-plan.md), [04-analytics-ad-plan.md](./04-analytics-ad-plan.md), [05-benchmark-spec.md](./05-benchmark-spec.md)
- 구현 대상: 데스크톱·모바일 반응형 웹

## 1. 화면 원칙

- 블로그형 카드보다 커뮤니티 게시판형 목록을 사용한다.
- 같은 URL과 컴포넌트를 화면 폭에 따라 재배치한다.
- 초기에는 `짤` 게시판 하나만 공개한다.
- `/`는 `/meme`으로 리다이렉트한다.
- 게시판 추가를 고려하되 아직 공개하지 않는 메뉴는 보여주지 않는다.
- 목록에서 상세로 들어가고 상세 하단 목록에서 다음 글을 고르는 흐름을 유지한다.

```text
/ -> /meme -> /posts/:postNo -> 같은 meme 게시판 하단 목록 -> /posts/:postNo
```

## 2. 공개 화면과 경로

| 화면 | 경로 | 상태 |
| --- | --- | --- |
| 루트 | `/` | `/meme` 리다이렉트 |
| 짤 목록 | `/meme` | 초기 구현 |
| 게시글 상세 | `/posts/:postNo` | 초기 구현 |
| 이용약관 | `/terms` | 초기 구현 |
| 개인정보처리방침 | `/privacy` | 초기 구현 |
| 권리자 요청 | `/rights` | 초기 구현 |
| 쿠키 설정 | `/cookie-settings` | 초기 구현 |
| 익게 | `/community` | 추후 구현 |
| 뉴스 | `/news` | 추후 구현 |

## 3. 반응형 레이아웃

| 구간 | 폭 | 레이아웃 |
| --- | --- | --- |
| Mobile | `360~767px` | 좌우 16px, 단일 열 |
| Tablet | `768~1023px` | 최대 720px, 단일 열 |
| Desktop | `1024px 이상` | 최대 1120px, 본문 중심 |

- 모바일에서 가로 스크롤이 생기지 않게 한다.
- 상세 본문은 데스크톱에서도 읽기 폭을 과도하게 늘리지 않는다.
- 광고와 보조 정보는 본문보다 먼저 나오지 않는다.
- 모바일에서는 게시판명, 작성자, 조회 수처럼 우선순위가 낮은 열을 숨길 수 있다.

## 4. 헤더

### 초기

- 로고 `블라리요`를 표시한다.
- 로고를 누르면 `/meme`으로 이동한다.
- 게시판이 하나뿐이므로 메뉴를 생략하거나 `짤` 하나만 표시한다.
- 검색, 글쓰기, 알림, 사용자 메뉴는 표시하지 않는다.

### 게시판 확장 후

활성화된 `TB_BOARD` 데이터만 메뉴로 표시한다.

| 표시명 | 코드 | 경로 |
| --- | --- | --- |
| 짤 | `meme` | `/meme` |
| 익게 | `community` | `/community` |
| 뉴스 | `news` | `/news` |

새 게시판은 같은 규칙으로 추가한다. 화면 코드에 게시판 개수를 고정하지 않는다.

## 5. 짤 목록 `/meme`

### 구성

1. 헤더
2. 페이지 제목 `짤`
3. 최신순 게시글 목록
4. 목록 중간 광고 행 후보
5. 페이지네이션
6. 정책 링크 푸터

### 목록 규칙

- 페이지당 게시글 20개를 표시한다.
- 광고 행은 게시글 20개에 포함하지 않는다.
- 정렬은 `publishedAt DESC, postNo DESC`다.
- 행 전체를 상세 링크로 사용한다.
- 무한 스크롤은 사용하지 않는다.

| 항목 | 데스크톱 | 모바일 |
| --- | --- | --- |
| 번호 | 표시 | 표시 |
| 게시판 | 초기에는 생략 가능 | 생략 |
| 제목 | 한 줄 | 한 줄 또는 두 줄 |
| 조회 수 | 표시 | 필요 시 숨김 |
| 작성자 | `운영자` | 숨김 가능 |
| 게시 시각 | 표시 | 표시 |

### 목록 광고

- 목록 중간에 광고 행 1개를 배치할 수 있다.
- 첫 게시글 앞에는 넣지 않는다.
- 광고 표기, 배경, 높이로 게시글과 구분한다.
- 광고 로드 실패 시 행을 접고 게시글 목록은 그대로 유지한다.

### 상태

| 상태 | 화면 |
| --- | --- |
| 로딩 | 목록 행 형태 skeleton |
| 빈 목록 | `아직 올라온 짤이 없습니다` |
| 오류 | 오류 안내와 `다시 시도` |
| 마지막 페이지 | `다음` 비활성화 |

## 6. 게시글 상세 `/posts/:postNo`

### 구성 순서

1. 헤더와 공유 버튼
2. 제목
3. 번호, 게시 시각, 조회 수
4. 본문 이미지와 텍스트
5. 출처
6. `AD-POST-BODY-BOTTOM`
7. 같은 게시판의 현재 글 주변 목록 20개
8. 목록 중간 `AD-DETAIL-LIST-INLINE`
9. 목록 아래 `AD-DETAIL-LIST-AFTER`
10. 정책 링크 푸터

### 본문과 이미지

- 이미지는 블라리요 서버 측 저장소의 URL을 사용한다.
- 외부 원본 이미지 URL을 직접 핫링크하지 않는다.
- 원본 비율을 유지하고 콘텐츠 폭을 넘지 않는다.
- 이미지 대체 텍스트를 제공한다.
- 이미지 로딩 전 비율 공간을 확보한다.
- 실제 저장 사업자는 아직 확정하지 않는다.

### 출처

- 본문이 끝난 뒤 한 번만 표시한다.
- 출처명과 원문 URL을 표시한다.
- 출처 표시는 권리 보유나 사용 허가를 뜻하지 않는다.
- 내부 검토 메모는 공개하지 않는다.

### 상세 하단 목록

- 현재 글과 같은 게시판의 게시글을 최대 20개 표시한다.
- 현재 글을 목록에 포함하고 선택할 수 없는 강조 행으로 표시한다.
- 현재 글 행에 `aria-current="true"`를 부여하고 링크와 tab stop을 만들지 않는다.
- 이전 글·다음 글 버튼은 두지 않는다.
- 페이지네이션은 두지 않는다.
- 목록으로 링크는 현재 게시판 경로로 이동한다. 초기에는 `/meme`이다.

### 없음·숨김

- 없는 글과 숨김 검토 중인 글은 공개 화면에서 같은 404 상태로 처리한다.
- 제목, 본문, 이미지, 출처와 요청 사유를 노출하지 않는다.
- `볼 수 없는 게시글입니다`와 `/meme` 이동 링크를 표시한다.

## 7. 공유와 OG

### 공유 동작

- 모바일은 `navigator.share`를 먼저 시도한다.
- 모든 환경에서 링크 복사를 제공한다.
- 카카오톡 공유를 제공한다.
- X/Twitter 공유를 제공한다.
- 공유 성공·실패 결과를 화면에 알린다.

### URL

- 목록 canonical: `https://__SERVICE_DOMAIN__/meme`
- 상세 canonical: `https://__SERVICE_DOMAIN__/posts/{postNo}`
- `/`는 `/meme` 리다이렉트이므로 별도 canonical 페이지로 만들지 않는다.
- 숨김·삭제 글은 `noindex` 처리한다.

### 필수 meta

- `title`
- `description`
- `canonical`
- `og:site_name`, `og:type`, `og:url`, `og:title`, `og:description`, `og:image`
- `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`

카피는 [06-copy-candidates.md](./06-copy-candidates.md)에서 확정 전 상태로 관리한다.

## 8. 광고

상세 광고는 다음 세 개만 사용한다.

| 슬롯 | 위치 |
| --- | --- |
| `AD-POST-BODY-BOTTOM` | 본문과 출처 다음 |
| `AD-DETAIL-LIST-INLINE` | 하단 목록 중간 |
| `AD-DETAIL-LIST-AFTER` | 하단 목록 아래 |

- 상세 상단, 우측, 앵커, 전면형 광고는 두지 않는다.
- 광고 크기만큼 공간을 예약해 레이아웃 이동을 줄인다.
- timeout, no-fill, 네트워크 오류에는 슬롯만 접는다.
- 광고 차단이 확인된 경우에만 해제 요청을 표시한다.
- 차단 안내는 본문, 공유, 목록 이동을 막지 않는다.

## 9. 권리자 요청 화면 `/rights`

- 대상 게시글 URL, 요청자 연락처, 요청 내용과 소명 자료를 받는다.
- 요청 접수 완료와 동시에 대상 게시글을 우선 숨긴다는 점을 안내한다.
- 관리자가 확인 후 재공개, 수정, 삭제 또는 비노출 유지를 결정한다.
- 처리 상태와 결과를 요청자에게 안내한다.

## 10. 추후 게시판 화면

### 익게 `/community`

- 사용자 작성 게시판이다.
- 계정, 글쓰기, 댓글, 신고 화면은 익게 개발 시 별도 설계한다.
- 초기 짤 화면에 미리 노출하지 않는다.

### 뉴스 `/news`

- 뉴스 게시판이다.
- 목록과 상세의 기본 골격은 짤 게시판을 재사용할 수 있다.
- 뉴스용 출처 표현과 게시 주체는 개발 전에 별도 결정한다.

## 12. 검수 기준

- `/`가 `/meme`으로 이동한다.
- 초기 헤더와 목록에 `익게`, `뉴스`가 노출되지 않는다.
- `/meme` 목록에 게시글 20개와 광고 행이 분리돼 보인다.
- 상세 출처가 하단에 한 번만 나온다.
- 상세 하단 목록은 같은 게시판 20개이며 현재 글을 포함한다.
- 상세 광고는 지정된 세 위치에만 있다.
- 권리자 요청을 접수하면 게시글이 먼저 숨겨진다.
- 360px, 768px, 1280px에서 가로 스크롤이 없다.
- 키보드만으로 목록, 상세, 공유, 정책 링크를 사용할 수 있다.
- 숨김 글의 내용과 내부 검토 사유가 HTML에 남지 않는다.
