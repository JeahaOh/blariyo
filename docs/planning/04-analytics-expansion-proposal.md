# 블라리요 사용자 행동 분석 확장 제안

- 작성일: 2026-09-25
- 검토 반영일: 2026-09-25 — 1차 검토 D1-1·A1-1 문서 보완. 구현·운영 검증과 구분한다.
- 상태: 전체 후보 제안과 1차 개발 계약을 구분한다. 2026-09-25 [analytics-v1 명세](../development-specs/m0-core/analytics-consent/analytics-consent.dev.md#analytics-v1)를 확정했으며 확장 구현·외부 설정·활성화는 미실행.
- 목적: 방문자의 콘텐츠 선택부터 본문 소비, 다음 글 열람, 공유, 재방문까지 분석할 후보를 정리한다.
- 제품 정본: [분석·광고 계획](04-analytics-ad-plan.md). 첫 구현은 해당 문서 §4.1과 개발 명세 §13을 따른다. 이 문서의 나머지 후보가 자동으로 구현 범위에 포함되지는 않는다.
- 적용 시점·담당·예산: `(미정)`. 기존 M0 우선순위와 완료 조건은 [로드맵](../roadmap.md)을 따른다.

## 1. 추천 방향

**GA4 상세 이벤트와 Google Search Console을 기본으로 검토한다. 초기부터 상세 이력을 분석하려면
BigQuery 원시 이벤트 저장을 후속 단계에서 검토한다. 저장 여부·조건은
후속 도입 전에 결정하고, 고급 쿼리·대시보드 개발은 나중에 진행한다. Microsoft Clarity는 화면
사용 흐름을 조사할 필요가 있을 때 선택한다.**

첫 구현은 추천안 중 **앱 직접 GA4 전송·수동 이벤트 9개·동의 version3**으로 확정했다.
BigQuery 일별 저장과 핵심 집계는 제외하고 후속으로 분리했다. GTM은 동일 GA4 이벤트를 전송하지 않는다. 정확한 이벤트·필드·수용 조건은
[개발 명세 §13](../development-specs/m0-core/analytics-consent/analytics-consent.dev.md#analytics-v1)을 따른다.
성능·오류·미디어·Clarity·광고·회원 분석은 후속이며, 운영 실값·고지 확정과 구현 검증은 남아 있다.

핵심 질문은 다음과 같다.

1. 어떤 글이 노출 대비 많이 선택되는가?
2. 어떤 글을 끝까지 내려보고, 얼마나 머무르는가?
3. 어떤 글이 다음 글 열람·공유·재방문으로 이어지는가?
4. 어떤 유입 경로가 지속적으로 이용하는 방문자를 데려오는가?
5. 화면 구성·로딩·오류 중 어디에서 이용 흐름이 끊기는가?

각 지표에는 활용할 운영 결정과 측정 기준을 연결한다. 마우스 이동·스크롤의 모든 순간을
개별 GA4 이벤트로 보내는 방식보다, 의미 있는 노출·선택·도달·결과를 측정하는 방식을 권장한다.

## 2. 현재 기준과 확장에 필요한 변경

2026-09-25 문서와 로컬 소스를 대조한 기준이다. 운영 GA4 속성·수신 데이터·태그 설정을
이번 문서 작성에서 확인한 것은 아니다.

| ----------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------ |

사이트 전체의 Google 요청이 동의 전 0건이라고 설명하지 않는다. 컨테이너 안의 태그·트리거·동의
조건은 별도 검증 대상이며, GTM 설치를 이 문서의 확장 이벤트 활성화로 간주하지 않는다.

## 4. 핵심 지표의 측정 기준 초안

### 4.1 게시물 클릭률

- 정의: **측정된 노출 중 한 번 이상 클릭으로 이어진 노출 수 ÷ 측정된 노출 수**.
- 첫 구현 노출 기준: 게시물 항목의 50% 이상이 화면에 연속 1초 이상 보임.
- 같은 목록 화면 표시 안에서는 같은 항목의 반복 노출·클릭을 중복 집계하지 않는 기준을 정한다.
- 메인 목록과 상세 하단 목록, 고정 글과 일반 글, 위치 구간을 구분한다.
- 노출 기준 충족 전에 빠르게 클릭한 경우처럼 대응 노출이 없는 클릭은 별도로 확인한다.
  이를 분자에만 더해 클릭률을 부풀리지 않는다.
- 글의 노출 위치·발행 후 경과 시간이 다른 상태에서 단순 클릭 수만 비교하지 않는다.

### 4.2 본문 도달률·체류

- 정의: **해당 본문 구간에 도달한 상세 화면 조회 수 ÷ 측정된 상세 화면 조회 수**.
- 구간: 본문 25·50·75%와 본문 끝. 하단 목록·푸터는 본문에서 제외한다.
- 짧은 글은 처음부터 끝이 보일 수 있으므로 글 길이 구간과 체류를 함께 본다.
- 체류는 화면이 활성 상태인 시간을 기준으로 검토하고, 백그라운드 탭의 시간을 구분한다.
- 도달·체류는 읽었다는 간접 신호다. 내용 이해나 만족을 확정하지 않는다.

### 4.3 다음 글 열람률

- 첫 구현 지표명은 **SPA 연속 열람률**이다. 정의는 **같은 측정 문맥·GA4 세션의 다음 상세 화면 조회가
  다른 게시물인 조회 수 ÷ 측정된 상세 화면 조회 수**다.
- 측정 문맥은 동의 후 브라우저 메모리에서만 유지한다. 전체 새로고침·새 탭·BFCache 복원은 새 문맥이며
  물리적으로 같은 탭이어도 문서를 넘는 연결은 하지 않는다. 모든 방문 경로의 다음 글 열람률로 표시하지 않는다.
- 세션은 방문 행동을 일정 기준으로 묶은 단위다. GA4 세션 기준과 보고서의 계산 기준을 맞춘다.
- 같은 글의 새로고침은 새 상세 조회로 구분하되 직전 조회의 다음 글 열람 성공으로 세지 않는다.
  같은 글 조회를 건너뛰어 이전 조회까지 성공으로 소급 집계하지 않는다.
- 하단 목록의 직접 클릭으로 이어진 경우와 다른 탐색 경로를 통한 후속 열람을 구분한다.
- 다른 탭의 열람을 시각만으로 연결하지 않는다. 새 탭 열기 클릭은 별도 행동으로 보며,
  직접 연결이 검증되기 전에는 원래 탭의 다음 글 열람 성공으로 세지 않는다.
- 목록·정책 화면을 거쳐도 다음 상세 조회가 같은 측정 문맥·세션 안에 있으면 비교한다. 세션이 끝나거나
  동의가 철회되면 연결을 종료한다. 보고서 마감 때 종료 여부가 불명인 세션은 잠정값으로 표시한다.

### 4.4 공유 결과·공유 후 유입

- 공유창 열기, 공유 방식 선택, 관측 가능한 API 결과를 별도 단계로 구분한다.
- 클립보드 쓰기 성공은 복사 성공이다. 실제 메시지 발송·상대방 수신을 뜻하지 않는다.
- 브라우저·카카오·X의 버튼 실행이나 API 응답을 외부 서비스의 게시·전달 완료로 간주하지 않는다.
- 공유 링크에는 허용된 채널·캠페인 분류값만 붙이는 방안을 검토한다. 공유한 사람을 추적하는
  개인별 구분값이나 내부 식별자를 추가하지 않는다.
- 공유 후 유입은 링크 분류값 기준으로 집계한다. 재공유·분류값 제거·앱 내 브라우저로 인한
  누락이나 경로 오분류가 있을 수 있다.

### 4.5 첫 방문 그룹별 재방문율

- 같은 날 처음 관측된 방문자 묶음을 비교한다. 이러한 묶음을 코호트라고 한다.
- 예시 정의: D7 재방문율 = **첫 관측일로부터 7일째에 다시 관측된 사용자 수 ÷ 첫 관측일 사용자 수**.
- 위 정의는 정확히 7일째의 재방문이며, 7일 이내 한 번이라도 재방문한 비율과 구분한다.
- 보고서 시간대와 첫 관측일 기준을 맞추고, 7일째 하루와 정한 데이터 수신 대기 기간이 모두 끝난
  그룹만 확정 D7 값으로 비교한다. 그 전의 값은 잠정값으로 표시한다.
- 첫 유입 경로·콘텐츠 유형별로 비교한다. 첫 방문 게시물별 비교에는 콘텐츠 구분값이 필요하다.
- 쿠키 삭제·기기 변경·동의 여부로 사용자 구분이 달라진다. 정확한 사람 수나 최초 방문일로 단정하지 않는다.

### 4.6 지표별 집계 단위와 계산 수단

아래는 확장 구현 시 사용할 계산 설계다. 현재 전송 허용 목록에 자동으로 추가되는 필드가 아니다.
여기서 콘텐츠 키는 정책 확정 후 허용할 분석용 구분값이며, 내부 `postId`나 제목을 그대로 뜻하지 않는다.
화면 표시 구분값은 개별 화면 표시를 구분하고, 탭 내 순서는 동시에 열린 탭의 행동을 섞지 않기 위한
후보다. 첫 구현의 실제 이름·형식·수명과 문서 간 연결 제한은 개발 명세 §13.2~§13.5에서 확정했다.

| ---------------------- | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 게시물 클릭률          | 화면 표시·목록 영역·항목 위치·콘텐츠가 같은 적격 노출을 1건으로 계산. 연결된 클릭은 한 번만 성공 처리           | 콘텐츠 키, 화면 표시 구분값, 목록 영역·위치, 노출 기준 충족과 클릭 기록      | BigQuery에서 노출과 클릭을 연결해 노출 단위 집계                                   |

| D1·D7·D30 재방문율     | 같은 관측 사용자와 최초 관측일을 유지. 대상일에 여러 번 방문해도 한 번만 계산                                   | GA4 관측 사용자 구분 정보·최초 관측일, 방문일, 최초 유입·콘텐츠 분류         | GA4 코호트 탐색은 동일 조건의 사용자 요약에 사용. 첫 게시물별 분석은 BigQuery 집계 |

- GA4 사용자·세션 구분 정보를 이용하는 설계이며, 회원 번호나 별도 GA4 User-ID 도입을 뜻하지 않는다.
  구분 정보가 없거나 연결 기준이 충족되지 않은 기록은 임의로 결합하지 않고 미연결 건수로 표시한다.
- 화면·시도 구분값처럼 종류가 많이 생기는 값은 원시 데이터 연결용으로 검토한다. GA4 맞춤
  측정기준에 무조건 등록하지 않으며, 자체 방문자 식별 저장소를 새로 만드는 권한도 부여하지 않는다.
- GA4 퍼널 탐색은 사용자 기준이고, 같은 사용자가 기간 안에 흐름을 반복해도 첫 순서만 보고한다.
  따라서 그 전환율을 노출·조회 기준 비율로 대체하지 않는다. [Google 퍼널 집계 규칙](https://support.google.com/analytics/answer/9327974?hl=en)
- 모든 비율은 같은 기간·필터·동의 후 관측 범위를 사용한다. 분모가 0이면 `자료 없음`으로 표시한다.
  누락된 노출·결과를 실패나 0으로 강제 변환하지 않고 수집 품질 수치를 별도로 둔다.
- 첫 구현은 일별 원시 저장을 함께 시작한다. 시작 이전의 상세 이력은 제공하지 않으며 GA4 집계 보고서로
  과거의 노출·조회별 연결을 복원할 수 있다고 안내하지 않는다. 초기 제공 지표는 개발 명세 §13.7을 따른다.
- 최초 관측일·첫 콘텐츠는 재방문 때의 현재 값으로 덮어쓰지 않는다. 내보내기 이전 이력이 없으면
  첫 콘텐츠를 `미상`으로 두며, 저장 시작일을 해당 사용자의 최초 방문일로 대체하지 않는다.

### 5.1 원시 데이터 저장 시작과 분석 개발의 분리

GA4의 기본 BigQuery 원시 이벤트 내보내기는 연결 이전 기간의 원시 이벤트를 소급해서 채우지 않는다.
따라서 초기부터 게시물별 행동을 분석하려면 **데이터가 쌓이기 전에 저장 여부를 결정해야 한다**.
[Google의 기본 내보내기 비교 안내](https://support.google.com/analytics/answer/9358801?hl=en-nz)

| 선택                                                     | 얻는 것·제약                                                           | 계획에 남길 내용                                                                |
| -------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| GA4 활성화와 함께 일별 원시 내보내기 시작 — 첫 구현 채택 | 초기부터 상세 연결에 필요한 원시 이력을 확보. 저장·관리 비용 발생      | 실제 첫 수신일, 보관 기간·삭제 규칙, 접근 권한, 비용 상한과 수신 누락 확인 방법 |
| 원시 내보내기를 나중에 시작 — 비교 대안·미채택           | 초기 저장·운영 부담을 줄임. 이전 기간의 상세 행동 연결은 확보하지 못함 | 선택을 바꾸려면 초기 제공 지표와 이력 제한을 다시 정해야 함                     |

어느 선택이든 계약·처리 위치·보관·동의 등 필요한 조건을 확정하기 전에 외부 저장을 시작하지 않는다.
추천안은 **일별 원시 저장과 핵심 지표의 기본 집계를 먼저**, 복잡한 분석·자동 보고서는 이후에 개발하는
순서다. 시작 시점·보관 기간·비용 상한의 실제 값은 `(미정)`이며 운영 설정을 변경한 것은 아니다.

Google Cloud의 별도 [GA4 보고서 데이터 전송 기능](https://docs.cloud.google.com/bigquery/docs/google-analytics-4-transfer)은
Data API 보고서를 옮기는 방식이다. 그 기능의 과거 보고서 전송을 원시 이벤트 복원으로 해석하지 않는다.
원시 내보내기와 보고서 데이터 전송 중 어떤 방식인지 연결 구성과 검증 기록에 명시한다.

위 공식 자료는 2026-09-25 제안 검토에서 확인한 근거다. 실제 도입 시 기능·약관·비용·보관 조건을 재확인한다.

## 6. 데이터가 쌓인 뒤 수행할 분석

| 분석 과제           | 비교·확인 방법                                              | 운영에 활용할 결과                                        |
| ------------------- | ----------------------------------------------------------- | --------------------------------------------------------- |
| 콘텐츠 평가         | 노출·클릭·본문 도달·연속 열람을 함께 비교                   | 클릭 이후 반응이 약한 글, 추가 노출할 가치가 있는 글 후보 |
| 발행 패턴           | 요일·시간대·유형별 비교, 위치와 노출 기간 차이 고려         | 콘텐츠 편성·발행 시간 실험 후보                           |
| 유입 품질           | 유입 경로별 열람 깊이·공유·재방문 비교                      | 홍보 채널별 우선순위                                      |
| 이탈 진단           | 기기·브라우저·속도·오류 여부별 이용 단계 비교               | 화면 또는 성능 개선 후보                                  |
| 개선 실험           | 이용자를 무작위로 나눠 기존·변경 화면을 비교하는 A/B 테스트 | 목록 배치·공유 버튼 위치 등의 효과 평가                   |
| 정기 보고·변화 탐지 | 같은 기준의 기간 비교, 표본 수·수집 설정 변화 확인          | 주요 증감, 가능한 원인, 다음 확인 항목                    |

예를 들어 모바일의 다음 글 열람률이 낮다면 **하단 목록 노출률 → 노출 후 클릭률 → 클릭 후
정상 화면 표시 비율**로 나눠 원인을 좁힌다. 특정 콘텐츠를 본 이용자의 재방문율이 높아도
그 콘텐츠 때문에 재방문했다고 단정하지 않는다.

AI 분석 보고서는 수치·비교 기간·표본 수·집계 정의를 근거로 관측 사실과 원인 가설을 구분한다.
자동 보고에는 승인된 데이터 접근과 실행 주기 구성이 필요하다. A/B 테스트도 별도의 배정·측정
구현이 필요하며, 최소 표본과 관찰 기간을 정하기 전에는 작은 차이를 개선 효과로 확정하지 않는다.

## 7. 도입 순서와 완료 조건

| 순서                   | 범위                                                | 해당 단계의 완료 조건                                                         |
| ---------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------- |
| 1. 수집·계산 범위 확정 | 개발 명세 §13의 단일 전송·9개 이벤트·필드·v3        | 개발 계약 확정. 운영 계약·고지의 실제 값과 발행·설정 확인은 잔여              |
| 2. 핵심 수집·보고 시작 | 직접 GA4와 Search Console                           | 9개 이벤트 구현·검증, GTM 동일 목적지 중지, 동의·중복 대조, 첫 수신·누락 확인 |
| 3. 화면 개선 분석      | 필요한 공개 화면의 Clarity                          | 동의·가림·관리자 제외·철회 검증, 재생·히트맵에서 조사 질문 확인               |
| 4. 고급 분석·자동 보고 | 축적된 원시 이력의 복잡한 분석, 정기 보고·변화 탐지 | 제공 가능한 기간·집계 버전·표본 수 표시, 비용 확인, 원시 데이터와 보고서 대조 |
| 5. 후속 제품 분석      | 검색·회원·광고 등 실제로 도입한 기능                | 해당 기능의 동의·정책·측정 계약을 확정한 뒤 활성화                            |

단계 3~5는 필요에 따라 선택한다. 문서 작성이나 로컬 검증을 외부 계정 설정·운영 수신 확인으로
대신하지 않는다. 태그를 연결하는 기본 작업과 이 문서의 상세 계측 확장은 별도 범위이며,
개발 공수·일정은 선택한 항목을 명세화한 뒤 산정한다.

## 8. 구현 전 결정과 검증 항목

- 콘텐츠 구분값의 형식·매핑은 API 설계와 개발 명세 §13에서 확정했다. 실제 secret·보관·숨김/삭제 후
  과거 자료의 처리 기간은 `(미정)`이다. HMAC 변환을 익명 정보로 간주하지 않는다.
- 진입 도메인·공유 캠페인의 고정 허용값은 개발 명세 §13.6에서 확정했다. 실제 URL·검색어·임의 query는 보내지 않는다.
- Clarity는 후속 미채택이다. BigQuery 일별 저장은 첫 구현에서 제외하며 실제 시작일·계약 주체·처리 위치·
  원시/집계 보관·비용 상한은 `(미정)`이다. 확정 전에는 후속 저장을 활성화하지 않는다.
- 분석용 오류 정보는 허용된 오류 분류값으로 제한하는 방안을 검토한다. 오류 메시지·요청 본문·토큰·
  URL 원문을 보내거나, 기존 보안 로그를 방문자 행동 추적용으로 전용하지 않는다.
- 직접 GA4 adapter와 이 제안으로 추가할 선택 분석 태그는 동의 전·거부 상태의 수집 요청 0건,
  동의 후 허용 항목만 전송, 철회 후 전송 중단을 network로 확인한다. 동의 전 행동을 저장했다가
  동의 후 소급 전송하지 않는다. §2의 GTM 컨테이너 요청은 별도로 구분한다.
- GTM 컨테이너 안에서 같은 이벤트를 보내는 태그가 있는지 확인하고 이벤트별 전송 주체를 하나로
  정한다. 직접 GA4의 flag·철회 처리가 GTM 태그에도 자동 적용된다고 가정하지 않는다.
- SPA의 화면 이동, 새로고침·뒤로 가기·여러 탭, 짧은 글·긴 글, 동의 시점 변화에서 중복·누락을 검증한다.
- 관리자·비공개 콘텐츠·개인정보가 전송되지 않는지 이벤트뿐 아니라 기본 URL·제목 필드와 재생 데이터도 확인한다.
- 동의·차단·처리 지연의 영향을 보고서에 표시한다. 관측된 방문자를 전체 방문자나 정확한 사람 수로 간주하지 않는다.
- 분석 장애가 콘텐츠 열람을 막지 않게 한다. 비활성화 방법과 데이터 접근·보관·삭제 책임을 확정한다.

확장안을 구현할 때 함께 맞출 문서는 [분석·광고 계획](04-analytics-ad-plan.md),
[보안·운영 설계](../system-design/05-security-operations.md),
[분석 동의 명세](../development-specs/m0-core/analytics-consent/analytics-consent.dev.md),
[개인정보처리방침](../legal/privacy-policy.md), [쿠키 설정](../legal/cookie-settings.md)이다.
미정 운영값·출시 차단 조건은 유지하며, 전송 허용 목록의 정본은 분석 계획과 개발 명세다.

2026-09-25 첫 구현 범위는 사용자 요청에 따라 제품·기술·법무 편집 초안과 개발 명세에 반영했다.
전송 허용 계약의 변경은 해당 정본의 v1 절이 소유하며, 현재 코드와 공개 고지는 아직 구버전이다.
