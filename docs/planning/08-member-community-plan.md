- 문서 상태: 작성 완료 — 설계 기본안, 법무·운영 활성화 조건은 미해결

- 2026-09-24 재대조: 후속 설계 상태를 유지한다. 현재 구현 부재와 운영 활성화 조건은 [회원·익게 기술 계약](../system-design/06-member-community-design.md)을 따른다.
- 범위: M1 회원 생명주기, M1.5 글·댓글·신고·운영 관리
- 상위 범위: [서비스 기획](01-service-plan.md)
- 화면: [화면 설계](03-screen-design.md), 기술: [회원·익게 기술 계약](../system-design/06-member-community-design.md)
- 법무: [출시 차단](../legal/README.md). 구현·실행 테스트·출시 완료를 뜻하지 않는다.

## 1. 단계와 설계 기본값

M1은 회원 기능만 추가하며 짤 작성 권한은 계속 운영자에게 있다. M1.5는 M1을 선행 조건으로
익게 읽기·쓰기·댓글·신고·운영자 검토를 추가한다. 수집 자동화나 광고 활성화는 선행 조건이 아니다.
뉴스, 추천·비추천, 랭킹, 쪽지, 팔로우, 알림, 대댓글, 사용자 이미지 업로드는 이 단계에 넣지 않는다.
익게 첫 버전은 텍스트 게시판으로 설계한다. 이미지 기능은 업로드 권한·할당량·삭제 계약을 추가한 뒤 별도 확장한다.

아래에서 글별 랜덤 이름, 탈퇴 콘텐츠 유지와 생년월일 직접 입력은 2026-09-08 사용자 확정 정책이다. 나머지는 설계 기본안이다.

| 결정 | 기본안 | 선택 이유 |
| --- | --- | --- |
| 익명성 | 글마다 다른 랜덤 이름, 원글 작성자에게 `글쓴이` 배지 | 다른 글 사이의 작성자 추적 방지 |
| 탈퇴 콘텐츠 | 탈퇴 시 글·댓글 유지, 계정 연결 제거 | 사용자 확정: 탈퇴로 대화 콘텐츠를 삭제하지 않음 |
| 가입 연령 | 생년월일 직접 입력 후 서버에서 만 14세 이상 판정, 원문 미보관 | 기존 14세 미만 가입 금지 원칙 구체화; 적정성 법무 검토 전 가입 공개 차단 |
| 프로필 | 서비스 내 표시명만 필수, 제공자 이메일·사진은 저장하지 않음 | 익게에 불필요한 프로필 수집 방지 |
| 제재 | 운영자의 사유 있는 수동 판단 | 신고 건수만으로 자동 차단하지 않음 |

## 2. M1 가입·인증·동의

- 네이버·카카오·Google·Apple을 제공하되 운영 설정이 검증된 제공자만 활성화한다. 네 제공자 전체의 검증이 M1 전체 수용 조건이다.
- 제공자 식별자로 계정을 찾는다. 같은 이메일 또는 같은 표시명만으로 기존 회원과 합치지 않는다.
- 최초 인증 뒤 약관 동의, 회원가입 개인정보 수집·이용 동의, 생년월일 입력을 각각 받는다. 생년월일은 연령 판정에만 일시 사용하고 저장하지 않는다.
  서버가 만 14세 미만이면 가입을 거부한다. 직접 입력값에 따른 판정이며 본인확인으로 검증된 연령은 아니다.
  모두 선택하기는 편의 UI일 뿐 개별 항목을 가리지 않는다. 분석·광고 동의는 포함하지 않는다.
- 서비스 표시명은 NFC 정규화·trim 후 2~20 Unicode code point, 제어 문자·줄바꿈 금지다. 중복 허용이며
  계정 화면에만 쓰고 익게 작성자와 공개 프로필로 사용하지 않는다. 변경 횟수 제한은 별도 기능으로 추가하지 않는다.
- 이메일·사진·제공자 이름 없이 가입 가능해야 한다. 제공자가 불가피하게 반환한 선택 정보는 저장·로그하지 않는다.
- 가입 취소·만료 시 임시 식별정보를 제거한다. 가입 완료 전 정식 회원과 로그인 세션을 만들지 않는다.
- 필수 동의 문구가 바뀌면 필요한 회원에게 다음 참여 전에 재동의를 받는다. 공개 읽기·계정 확인·
  로그아웃·탈퇴는 계속 허용한다. 동의 철회는 탈퇴 흐름으로 연결하며 선택 분석 철회와 구분한다.

## 3. M1 계정 연결·세션·탈퇴

- 한 회원은 제공자별 최대 한 계정을 연결한다. 서로 다른 기존 회원을 합치는 기능은 없다.
- 연결에는 현재 계정의 최근 재인증과 새 제공자 인증이 모두 필요하다. 마지막 사용 가능한 로그인
  수단의 해제는 거부하고 다른 수단 추가 또는 탈퇴를 안내한다.
- 외부 연동 해제가 진행 중이거나 결과가 불명확하면 동일 소셜 계정의 재연결·재가입을 막고 처리 상태를 안내한다. 다른 연결 수단으로 기존 계정 관리·탈퇴는 가능하다.
- 신규 가입을 중단해도 기존 회원 로그인·재인증·본인 콘텐츠 삭제·탈퇴는 유지한다. 기존 계정이 남아 있는 동안 필요한 인증 제공자 설정을 제거하지 않는다.
- 로그아웃은 현재 세션, 모든 기기 로그아웃은 전체 세션을 종료한다. 비밀번호 복구 이메일은 없다.
- 마지막 수단을 외부에서 철회하면 계정을 재인증 필요 상태로 두고 모든 세션을 취소한다.
  동일 제공자 식별자의 재인증으로만 복구한다. 이메일을 통한 자동 연결이나 운영자 임의 계정 병합은 하지 않는다.
- 로그인 access token은 처리 후 폐기한다. Apple refresh token만 서버에서 암호화해 연동 종료까지
  보관하는 예외를 둔다. 이는 외부 API 활용을 위한 수집이 아니라 Apple 자격 상태 확인·철회용이다.
  다른 제공자는 연결 해제 시 새 인증으로 얻은 단기 토큰을 이용하고, 토큰이 없으면 수동 해제 방법을 안내한다.
- 탈퇴 접수와 동시에 모든 세션·쓰기 권한을 없앤다. 외부 제공자 장애가 로컬 탈퇴를 막지 않는다.
- 탈퇴 전 본인 글·댓글 수와 “탈퇴 후에도 글·댓글은 남으며 수정·삭제할 수 없습니다”를 안내한다.
  탈퇴에 따른 콘텐츠 전체 삭제 선택은 제공하지 않는다. 콘텐츠가 없는 M1 환경에도 같은 정책을 적용한다.
- 탈퇴는 글·댓글 본문과 기존 공개/숨김/삭제 상태를 유지하며 작성자 연결·표시명·공개 계정 식별자를 제거한다.
  기존 글 안의 랜덤 이름은 대화 구분용으로만 유지한다. 이미 삭제한 콘텐츠를 복원하지 않는다.
- 탈퇴 전 본인 콘텐츠 수정·삭제 기능과 탈퇴 후 개인정보·권리 침해 삭제 요청은 유지한다.
  본문에 직접 적은 개인정보는 자동 제거되지 않으므로 탈퇴 전에 확인하도록 안내한다.
- 탈퇴 후 서비스에서 소유권을 재확인할 수 없으므로 일반 편집은 불가하다. 개인정보·권리 침해 삭제 요청은 기존 이메일로 접수한다.
- 별도 법적 보존이 실제 필요한 데이터의 근거·대상·기간은 `(미정)`이다. 이를 이유로 모든 탈퇴 정보를 무기한 보관하지 않는다.

## 4. M1.5 공개 읽기와 작성

- `/community`와 `/community/posts/:postId`는 비회원도 읽는다. 참여에는 유효 회원·필수 동의·제재 확인이 필요하다.
- 목록은 최신 최초 발행순, 20개 페이지 방식이다. 익게에는 첫 버전 공지·검색·이미지·예약·초안 저장을 넣지 않는다.
- 제목 1~200, 본문 1~10,000, 댓글 1~1,000 Unicode code point다. NFC 정규화·trim 후 code point 수를 계산하고 HTML·Markdown을 해석하지 않는다.
  제목은 CR·LF·U+2028·U+2029 줄바꿈을 허용하지 않는다. 본문·댓글의 CRLF·CR·U+2028·U+2029는
  LF로 통일하고 LF는 1 code point로 센다.
- 글은 작성 완료 시 즉시 공개한다. 본인만 공개 글을 수정·삭제할 수 있고 수정은 최초 발행 순서를 바꾸지 않는다.
- 숨김 상태의 글·댓글은 본인도 수정·재공개할 수 없다. 본인 삭제와 운영자 검토만 허용한다.
- 댓글은 한 단계이며 오래된 순으로 20개씩 표시한다. 삭제·숨김 댓글은 내용·작성자를 감춘 자리 표시로 대화 순서를 유지한다.
- 원글과 댓글 모두 서버가 부여한 랜덤 이름을 표시하고 원글 작성자의 댓글에는 `글쓴이` 배지를 붙인다.
  같은 회원은 같은 글에서 같은 이름을 쓰며 다른 글에서는 이전에 사용하지 않은 이름을 부여한다.
  탈퇴·댓글 삭제 후에도 해당 글의 이름을 재사용하지 않는다. 다른 회원끼리 다른 글에서 이름이 같을 수 있으며 동일인이라는 뜻이 아니다.
- 사용자 ID, 서비스 표시명, IP, 제공자 식별자는 공개 HTML·API·메타데이터에 포함하지 않는다.
  운영 목적 내부 연결이 있으므로 서비스 운영자에게까지 완전한 익명인 서비스라고 안내하지 않는다.
- 작성 중 인증 만료는 별도 인증 창을 사용해 부모 편집 화면을 유지한다. 팝업 차단 시 입력을 유지하고 재시도·내용 복사를 제공하며 같은 탭 외부 이동 후 복구를 보장하지 않는다. 재동의는 편집 화면의 dialog에서 처리한다.
- 본인 글·댓글과 제재 상태는 `/account/activity`에서 확인한다. 다른 사람의 활동 목록은 제공하지 않는다.
- 기본 상한: 회원별 글 5건/10분·30건/일, 댓글 30건/10분·300건/일, 신고 10건/일.
  일 기준은 Asia/Seoul이다. 삭제·실패 재전송으로 상한을 우회하지 못하게 한다. 성공한 신규 생성만 일 사용량에 센다.

## 5. 신고·운영 관리

- 로그인 회원은 공개 글·댓글을 신고할 수 있다. 본인 콘텐츠 신고는 막고 직접 삭제를 안내한다.
- 사유는 `스팸`, `괴롭힘·혐오`, `개인정보 노출`, `권리 침해`, `불법·유해`, `기타`이며 설명은 NFC 정규화·trim 후 최대 500 Unicode code point다.
  기타는 설명 필수다. 민감한 증빙 파일은 받지 않고 필요한 권리 증빙은 기존 이메일 경로로 분리한다.
- 같은 회원·같은 대상의 신고는 한 번만 접수한다. 신고자가 화면을 새로고침해도 중복 생성하지 않는다.
- 신고 접수만으로 콘텐츠를 자동 숨기지 않는다. 운영자는 검토 대기 목록에서 대상 현재 상태·사유를 확인한다.
- 처리 선택은 무조치 종결, 숨김, 최종 삭제다. 숨김은 되돌릴 수 있고 최종 삭제는 복원할 수 없다.
  공개 재개는 독립 확인 동작으로 남기고, 회원이 삭제한 콘텐츠는 복원하지 않는다.
- 회원 제재는 글·댓글·신고 참여 제한이며 공개 읽기·내 활동·삭제·탈퇴는 허용한다.
  1일·7일·30일·무기한 중 운영자가 사유와 함께 선택한다. 신고 건수로 제재 기간을 자동 계산하지 않는다.
- 제재 해제·기간 변경도 이력을 남긴다. 대상 회원에게 공개 가능한 사유와 종료 시각·이의제기 이메일을
  계정 화면에 보여주되 신고자 정보와 내부 검토 메모를 보여주지 않는다.
- 수동 해제되거나 기간이 끝난 제재는 즉시 참여 제한에서 제외한다. 정리 작업이나 상태 이력 갱신이
  늦어져도 이미 해제·만료된 제재로 글·댓글·신고를 계속 막지 않는다.
- 운영자는 랜덤 이름을 내부 회원 대상으로 연결해 제재할 수 있지만 소셜 식별자·이메일은 검수 화면에 노출하지 않는다.
- 운영자는 신고가 없어도 글·댓글을 직접 조회하고 숨김·복원·삭제·작성자 제재로 진입할 수 있다. 삭제된 원문은 조회로 복원하지 않는다.
- 권리 이메일 확인 후 우선 숨김 원칙은 익게에도 적용한다. 신고 화면은 법적 권리 요청 접수를 대체하지 않는다.

## 6. 단계 수용 조건과 공개 차단

| 단계 | 설계에 따른 구현 수용 시나리오 | 별도 공개 조건 |
| --- | --- | --- |
| M1 | 네 제공자 신규/기존 인증, 동의 변경, 계정 연결 충돌, 마지막 수단 보호, 로그아웃, 탈퇴와 외부 실패 분리 | 실제 앱 등록·callback·secret, 연령 확인 법무 검토, 동의 artifact, 국외이전·수탁자 고지 |
| M1.5 | 공개 읽기, 본인 작성·수정·삭제, 글 단위 익명성, 신고 중복, 숨김·복구·제재, 탈퇴 콘텐츠 유지·계정 연결 제거 | 회원 gate, 운영자 처리 가능 여부, 보존 근거·기간과 약관 고지 검토 |

이 문서의 제한 수치는 제품 설계값이며 부하 측정 결과가 아니다. API·DB·UI 수용 시나리오를
[기술 계약](../system-design/06-member-community-design.md)과 기능 명세로 연결한다.

### 연동 해제 결과 불명확 시 운영 기준

외부 해제 결과를 확인하지 못해 재연결을 막는 최소 기록은 최대 30일로 설계한다. 만료까지 해결하지
못하면 해당 제공자의 신규 가입·연결을 중단한 뒤 기록을 파기한다. 기존 회원의 계정 종료 접근은 유지한다.
이 최소 보존의 법적 근거와 provider별 확인 방법이 확정되지 않으면 해당 provider 공개를 차단한다.

## 7. 랜덤 이름의 범위와 표현

이름은 [랜덤 이름 사전](09-random-name-catalog.md)의 장소·상황, 수식어, 명사를 조합한다.
동물·식물·음식·자연·우주·물건·음악·취미 소재를 섞고 사용자의 계정·생일·성별·위치·행동에서 추출하지 않는다.
사용자가 직접 이름을 입력하거나 다시 뽑는 기능은 없다. 최초 글/댓글 저장 성공 때 배정하고 조회 시 재생성하지 않는다.
이름은 NFC 정규화 후 공백 포함 32 Unicode code point 이내이며 긴 이름은 줄바꿈한다. 숫자·회원 ID·전역 순번을 붙이지 않는다.
사전 확대는 기존 이름을 바꾸지 않는다. 부적절한 조합 발견 시 신규 배정을 중단하고 기존 콘텐츠의
숨김·검토는 기존 운영 절차를 따른다. 특정 글에서만 이름을 바꿔 기존 대화를 혼란스럽게 하지 않는다.
