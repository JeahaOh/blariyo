# Blariyo responsive publishing prototype

- 목적: 와이어프레임 이후 실제 화면 밀도, 여백, 반응형 동작을 확인하는 정적 퍼블 파일
- 정합성 검토일: 2026-08-19
- 기준: 데스크톱·모바일 웹만 검토
- 실행: `index.html`을 브라우저에서 직접 열어 확인
- 한계: 정적 단일 HTML은 홈 metadata만 표현하며 게시글별 OG 검증물이 아니다.
- 단계 상태: M0 화면에 M1 로그인 진입과 후속 광고 위치를 함께 미리 본 혼합 단계 프로토타입
- 컬러 기준: [07-color-palette.md](../../planning/07-color-palette.md)

제품 단계와 실제 수용 기준은 [03-screen-design.md](../../planning/03-screen-design.md)가 우선한다.
현재 프로토타입은 M0 전용 검수본이 아니며, M0 구현에서는 로그인 진입과 광고 슬롯을 렌더링하지
않아야 한다.

| 파일 | 역할 |

## 현재 반영 기준

- 초기 게시판은 `짤/meme` 하나이며 `/`는 `/meme`으로 리다이렉트
- 추후 `익게/community`, `뉴스/news`와 추가 게시판을 활성 데이터로 확장
- 데스크톱과 모바일 모두 최대 760px 단일 컬럼 게시판형 레이아웃 사용
- 우측 사이드바와 중복 게시판 열 없이 제목과 메타정보를 두 줄로 표시
- 홈 목록은 고정 공지 0~3개와 일반 게시글 20개다. 후속 광고 행은 활성화하더라도 일반 게시글 개수에서 제외한다.
- 상세 하단 목록은 같은 게시판의 현재 글 주변 게시글 20개이며, 후속 광고 행은 개수에서 제외하고 홈과 같은 페이지 번호 이동을 제공한다.
- 현재 글 행은 `aria-current`로 강조하고 링크와 tab stop을 만들지 않음
- 상세 출처는 본문 하단에서 출처명 전체를 원문 링크로 1회만 표시
- 후속 상세 광고는 본문·출처 다음, 하단 목록 중간, 목록 아래의 3개만 사용
- 이전글/다음글 별도 버튼 없음
- 상세에서는 단일 게시판 tab을 숨기고 `← / 한 줄 제목 / 공유 아이콘` M0 헤더를 기준으로 하며,
  현재 정적 파일의 로그인 진입은 M1 배치 참고용이다. 뒤로가기와 공유 아이콘의 접근성 이름은
  각각 `목록으로`, `공유하기`로 제공한다.
- 게시글 로딩·오류·숨김 상태도 게시판 tab을 숨기고 `← / 상태 제목` M0 헤더를 기준으로 하며,
  빈 목록 상태는 목록 헤더를 유지한다. 현재 정적 파일의 로그인 진입은 M1 참고 요소다.
- 현재 목록·상태·상세 헤더의 `/login` 진입은 M1 시안이며 M0 화면 반영 완료 증거로 사용하지 않는다.
- 공유 메뉴는 데스크톱 floating popup·모바일 하단 share sheet로 표시하고 링크 복사·카카오톡·X·브라우저 공유와 닫기·`Escape`·바깥 클릭을 제공
- 푸터의 이용약관·개인정보처리방침·쿠키 설정은 dim modal과 직접 route를 유지하고, `권리 문의`는 짧은 링크 문구로 표시해 1차 이메일 작성으로 연결
- 이용약관·개인정보처리방침 modal은 현재 적용 본문과 `버전 / 적용 기간`만 표시하는 행 전체 클릭형 개정 이력을 제공
- 정책 modal의 소셜 가입·로그인, 탈퇴·연동 해제와 GA4 문구는 M1 이후 조항 미리보기이며,
  M0에서 활성화된 기능을 뜻하지 않는다.
- 로그인·가입 동의·계정 관리 화면의 정적 퍼블리싱은 [03-screen-design.md](../../planning/03-screen-design.md)의 화면 계약을 기준으로 다음 작업에서 추가
- 현재 정적 파일의 비차단형 하단 쿠키 배너와 분석·광고 선택은 후속 기능 UI 참고용이다.
  GA4와 광고가 모두 비활성인 M0에서는 배너를 표시하지 않는다.
- 콘텐츠 외곽과 헤더 내부 요소 밖의 여백은 `#3A4A5A`, 읽기 영역은 밝은 표면으로 유지
- 상세 하단 목록 아래 광고와 푸터 사이의 추가 여백을 제거
- 화면 선택 tab은 방향키·Home·End를 지원하고 모든 주요 터치 대상은 최소 44px

## 정적 OG 한계와 SSR 계약

이 프로토타입은 `#home`, `#detail`처럼 한 HTML 안에서 검토 화면만 바꾼다. `<head>`에는 홈 canonical과 기본 OG만 있으므로 JavaScript 전환 결과를 SNS crawler의 게시글 미리보기 계약으로 사용하면 안 된다.

실제 서비스의 `GET /:boardSlug/posts/:postId`는 요청 게시판과 게시글 소속이 일치할 때 첫 서버 응답 HTML에 아래 값을 게시글별로 렌더링한다.

- `<title>`, description, canonical `/:boardSlug/posts/:postId`
- `og:type=article`, `og:title`, `og:description`, `og:url`
- absolute HTTPS `og:image`, `og:image:alt`, image width·height
- `twitter:card=summary_large_image`, title, description, image, image alt

공개 게시글은 HTTP `200`을 반환한다. 없거나 숨김 처리됐거나 URL 게시판과 소속 게시판이 다른 게시글은 HTTP `404`, `noindex`를 반환하고 제목·본문·이미지·내부 검토 내용을 HTML에 넣지 않는다. `/meme`, `/terms`, `/privacy`, `/cookie-settings`도 route별 canonical을 가진 서버 응답 HTML을 제공한다. 권리 침해·게시 중단 문의는 푸터 이메일로 연결하고 `/`는 `/meme`으로 리다이렉트한다.
