# docs 축소와 정합성 정정 기록

- 기준일: 2026-09-07
- 상태: M0 Core 신규 개발을 위한 문서 최종 검토·정정 완료. 실제 공개·외부 기능 활성화 조건은 유지한다.
- 승인: `계획대로 진행 해`로 docs 통합을, 후속 수정 계획에 대한 `진행 해`로 계약 정정과 중복 축소를 적용했다.
- 범위: docs. 현재 기능·출시 단계·시스템 구조를 유지한다. 이 기록은 제품·기술·법무 정본을 대체하지 않는다.

<a id="적용-결과"></a>

## 적용 범위와 문서 소유권

기능별 보강서·API·D01·D08 52개를 기존 기능 문서 5개로 통합하고 47개 중복 파일을 제거했다.
API·D01·D08은 기능 문서의 절과 기존 이동 anchor로 유지한다. archive·새 보고서 파일은 만들지 않는다.
출처 20곳의 조사 근거는 유지하고 동일한 추출·임시 파일 규칙만 수집 기획으로 모았다.

| 사실 | 관리 위치 | 파생 문서의 역할 |
| --- | --- | --- |
| 제품·화면·카피·출처 범위 | planning | 기능 명세는 적용 흐름을 연결 |
| 법무 본문·실값·출시 차단 | legal | placeholder·차단 조건 보존 |
| 상태·DB 제약 | system-design 데이터 모델 | API·UI가 허용 전이를 따름 |
| Core API 타입·필수·입력 개수 | docs OpenAPI | Markdown은 처리·매핑·실패 결과 보충 |
| 인증·오류·transaction·복구 | system-design API·보안·운영 | 기능별 차이만 구체화 |
| 수집 요청·응답 | system-design API 및 수집 기능 명세 | 수집 OpenAPI가 없으므로 구체 계약 보존 |
| 동의 저장·이벤트 | 동의 저장은 analytics 명세, event allowlist는 분석 기획 | UI·loader는 담당 절 참조 |

GA4, Discord·관리자 수집, 후보 큐, cache purge와 서버 구조를 축소하지 않는다.
소스·migration·설정·루트 AGENTS·전역 스킬·worklog는 이번 정정 대상이 아니다.

## 이번에 정정한 문제

| 문제 | 변경과 근거 |
| --- | --- |
| IMAGE 21장을 허용한 생성·수정 스키마 | API 설계의 전체 1~40개·IMAGE 최대 20개를 공통 `EditBlocks`로 표현. TEXT만 있는 글도 허용 |
| 승격의 파일 크기 오류 코드 불일치 | API 설계·수집 명세를 공통 `413 UPLOAD_TOO_LARGE`로 통일 |
| retry 접수 오류와 collector 실패 혼재 | 데이터 모델대로 `FETCH_FAILED→PENDING→RUNNING→NEW/FETCH_FAILED`. 출처·robots·상한 실패는 collector 결과로 기록 |
| 정의되지 않은 수집 거부 상태 | `RUNNING→FETCH_FAILED`와 실패 코드로 명시 |
| 초안 생성의 게시판 없음 응답 누락 | 기존 관리자 기능 명세의 `404 BOARD_NOT_FOUND`를 시스템 API와 OpenAPI에도 반영 |
| 쿠키 삭제 실패와 “쿠키 0건” 기준 충돌 | 신규 요청·생성 차단과 기존 쿠키 삭제 실패를 구분. 삭제 실패 시 전송 중단·안내 계약 유지 |
| 빈 자기 참조 링크 6곳 | 관리자 API 목록 anchor 또는 같은 문서의 요구사항 참조로 교체 |
| 반복 규칙과 비어 있는 예시 안내 | 업로드 복구·예약·SSR metadata·GA4 allowlist를 담당 절로 연결. 오류 예시 반복과 본문 없는 안내 제거 |

생성·수정의 블록 제한은 같은 스키마를 참조한다. 업무 상태 판정·trim·DB 선점·외부 I/O는
스키마 검증만으로 보장되지 않으므로 처리 계약과 실행 검증을 구분한다.

## 신규 개발 전 최종 정정

사용자는 기존 애플리케이션 프로토타입을 폐기하고 새로 개발하며 오늘은 docs만 완성한다고 확정했다.

| 문제 | 최종 반영 |
| --- | --- |
| 기존 구현·생성 타입 승계 전제 | AI 안내·설계 색인·API·DB·Backlog·OpenAPI 배치를 새 구현 기준으로 정정 |
| 화면과 DB의 후보 상태 불일치 | 검수 중·만료를 별도 후보 상태로 두지 않고 여섯 DB 상태와 화면 표시를 맞춤 |
| 출처 관리 세부 계약 누락 | GET/PATCH 형식·허용값·version·오류·감사·UI 재조회 흐름을 기존 API와 기능 명세에 보완 |
| 삭제된 이미지의 관리자 응답 누락 | DELETED enum, private 삭제 중/완료 previewPath=null, preview 404와 읽기 전용 화면 반영 |
| 정책 시행 경로 충돌 | 운영 본문 seed 지시를 제거하고 승인 artifact·policies:publish로 통일. 로컬 fixture 개발과 공개 차단 분리 |
| 예약·purge 실패 경계 | 예정 시각이 지나도 미발행 SCHEDULED는 취소 가능. 이미지 삭제 대기와 목록 cache 재시도 구분 |
| 수집 호출 주체·관리자 충돌 안내 | 원격 fetch는 로컬 collector임을 화면·구조도에 명시. 관리자 동시 수정 안내 문구 확정 |

## 기능별 의미 대조

다음은 문서 사이의 정상·실패 조건을 읽고 대조한 결과다. 실제 앱 테스트 결과가 아니다.

| 기능 | 대조한 경계와 결과 |
| --- | --- |
| 공개 탐색 | 공개 목록 초과 page는 404, 관리자 검색 초과 page는 200 빈 목록. 비공개 상세는 같은 404, 조회 수·하단 목록 실패는 본문 열람 유지 |
| 관리자 게시글 | 블록·이미지 개수, source pair, 상태·version 충돌, 업로드 전체 실패, 숨김 후 공개 차단과 image 삭제 대기, 예약 복구·영구 오류 분기 확인 |
| 수집 보조 | 접수·claim·결과를 분리. FETCH_FAILED만 retry, NEW/FETCH_FAILED만 반려, NEW만 승격. 이미지 0·21건 승격 불가, 일부 저장 실패 시 NEW 유지 |
| 정책·권리 | EFFECTIVE/RETIRED만 공개. 미래·5분 초과 과거 시행 거부, DB 실패 rollback·purge 실패 재시도. mailto 실행 감지 없이 주소 복사 제공 |
| 분석 동의 | flag·scope·12개월 만료·저장 실패에서 거부 기본값, 동의 후 전송, 철회·삭제 실패·loader 실패 분기와 활성화 차단 확인 |

## 검증 결과와 한계

이전 통합 검사의 “링크 오류 0건”은 빈 링크를 검사하지 못한 결과였다. 그 검사는 정합성 완료
근거로 충분하지 않았다. 이번에는 빈 링크와 파일·anchor 존재를 함께 검사했다.

| 검사 | 이번 결과 |
| --- | --- |
| docs Markdown | 최종 작업 시작과 종료 모두 74개. 새 파일·삭제 파일 없음. 기존 task_list 2개 포함 |
| OpenAPI | 19개 operation 구조 검증, 생성·수정 경계 20건과 기존 회귀 14건: 삭제·preview 상태 조합 12건 포함 총 46건 통과 |
| 계약·링크·예시 | API 목록과 OpenAPI 19개 method/path 일치. 이미지·후보 상태값 대조 통과. 빈 링크·미존재 파일·anchor 0건, Markdown JSON 20개 문법·OpenAPI 예시 5개 스키마 정상, YAML 파싱 통과 |
| 보존 | 이번 시작점 대비 docs 밖 파일·legal·publishing·wireframes 바이트 동일. 이동 anchor와 고유 미정·출시 차단 표시 보존 |
| Git | `git diff --check` 통과. 기존 사용자 변경 보존. commit·push 없음 |

- 앞선 의미 정정: 14,420→14,278줄, 142줄 감소. 최종 신규 개발 검토에서는 누락 계약을 기존 파일에 보완했다. 별도 산출물 추가 없음.
- 앞선 통합: Markdown 119→72개, 15,893→14,420줄. 파일 수 감소가 의미 충돌 해소를 뜻하지는 않았다.
- 수집 출처 관리의 세부 계약 누락은 이번에 해소했다. 실제 출처 selector·운영 요청값·collector 배포값은 수집 단계 착수/활성화 조건이며 M0 Core에 포함하지 않는다.
- 개발 단계 검증: 새 source·migration·생성 타입·DB·R2·browser·network 테스트. 과거 프로토타입의 결과는 승계하지 않는다.
- 남은 차단: 법무·문의 실값과 기능별 운영 활성화 값. 기존 표시를 유지한다.

판정: 이 문서 집합으로 M0 Core를 새로 개발할 수 있다. 문서 검토 완료는 실제 구현·출시 완료를 뜻하지 않는다.
