# 최종 확정 준비 주 검수

- 날짜: 2026-09-08
- 상태: 검토·주 검수 완료, 보완 적용 전
- 범위: M0 Core·수집 보조·M1·M1.5의 기획·법무·기술·기능 명세·정적 화면.
- 방법: 3개 하위 모델에 영역별 검토 위임 후 주 에이전트가 실제 정본의 해당 행과 반증을 직접 대조했다.
- 이번 검토는 정본 수정·코드 구현·법률 자문·운영 공개 승인·commit·push·tag·merge를 수행하지 않았다.

## 결론

**전체 무조건 최종 확정은 아직 이르다. M0 Core는 조건부 설계 기준선에 가깝고, M1·M1.5는 구체적인 계약 보완 뒤 동결 가능하다. Spring 수집 보조는 별도 상세 설계가 더 필요하다.**

여기서 조건부 설계 기준선은 개발에 사용할 결정·계약을 고정하되, 법무 판단 등에 따라 변경할 수 있는 항목과 공개 차단 조건을 함께 기록하는 것이다. 실제 구현이 없다는 사실만으로 설계 동결을 막지는 않는다. 반대로 문서 동결은 구현 수용이나 출시 승인이 아니다.

| 범위 | 이번 판정 | 동결 전 필요한 보완 | 별도 남는 조건 |
| --- | --- | --- | --- |
| M0 Core | 조건부 동결에 가까움 | 법무 차단 목록 누락·정적 정책 검토물 표현 정리 | 운영 실값·법무·실제 구현/복구 검증 |
| M1 회원 | 계약 보완 후 조건부 동결 | 문자열 길이 계산 단위와 상태 판정 문구 통일 | 제공자 실제 연동·법무·DB·탈퇴/복원 검증 |

| 자동 수집·GA4·광고 등 | 해당 기능 별도 범위 유지 | 현재 결정 범위를 넘어 일괄 확정하지 않음 | 각각 활성화 조건 |

## 누가 결정할 것인가

- **AI가 후속 보완할 수 있는 일:** R01~R10의 계약 정리·대안·권장안·수용 시나리오, 단계별 공개 차단표, 운영 점검 절차. 현재 요청은 검토이므로 아직 반영하지 않았다.
- **사용자 또는 운영자가 제공할 사실:** 실제 운영자·담당자·접수 이메일, 실제 수탁자와 계정, 제공자 앱 등록, 시행일·정책 발행 책임자, 운영 가능한 처리 범위. secret 원문을 문서나 대화에 적지 않는다.
- **외부 검증:** 연령 확인 방식·가입 전 임시 처리·보존 기간·국외이전·권리 요청 등의 법무 적정성, 실제 제공자 계약/수집 허용 범위. 기존 문서의 법무 초안과 공개 차단은 유지한다.
- **구현 후 검증:** PostgreSQL 경쟁·제재 해제·탈퇴 worker 재시작·외부 제공자·수집 응답 유실·복원·브라우저. 오프라인 모델 통과로 대체하지 않는다.

외부 결과가 DB 보존 모델이나 인증 흐름을 바꾸면 해당 설계 기준선을 다시 검토한다. 조건부 동결은 이후 변경을 금지한다는 뜻이 아니다.

## 권장 순서

1. R01·R02·R08·R09·R10을 먼저 최소 보완하고 직접 재검수한다.
2. R03~R07을 Spring 수집 상세 설계로 작성한다. M0 Core 확정과는 분리해 진행할 수 있다.
3. 각 단계에 포함되는 공통 문서와 확장 절을 목록화하고 미정/공개 차단을 붙여 M0·M1·M1.5 설계 기준선을 검토한다. tag·merge는 이번 검토에서 실행하지 않는다.
4. 운영 실값·외부 검증·구현 증거를 단계별로 확보한 뒤 해당 기능의 공개 승인만 별도로 판단한다.

## 오탐과 과장 제거

- 관리자 제재 조회의 lockVersion은 06:289에 이미 있으므로 누락으로 판정하지 않았다.
- 익게 조회수 POST는 기존 M0 공개 API의 인증 없음 계약을 가리키므로 별도 권한 결함으로 세지 않았다.
- 백업 daily 표현은 저장 prefix/tier 약칭일 수 있다. 04:403과 05:336의 12시간·28개가 명확하므로 하루 1회와의 확정 모순으로 세지 않았다. 명료화는 가능하다.
- 정적 예시 버전 자체는 허용된다. 실제 발행처럼 보이는 표기와 선택 본문 불일치만 검토물 정확성 문제로 다룬다.
