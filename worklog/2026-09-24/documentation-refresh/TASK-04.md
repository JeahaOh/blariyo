## 작업

1. C/A/B/O 요구사항 40개와 기존 ID를 유지한다. 현재 집계 I30/P9/U1을 시작점으로 행별 증거와 잔여 조건을 대조한다.
2. 공개 본문·이미지, DB 버전/권한, CI, 원격 저장소, 배포/복원 관련 행에 새 운영 근거를 반영한다.
3. 데이터 이전·내부 service 검사를 다른 PC batch 실행, 실제 관리자 MFA 조작, Discord 실연동으로 확대하지 않는다.
4. 구현 판정과 검증 환경을 별도로 기록한다. 운영 근거가 기존 L/H/N 정의로 구분되지 않으면 범례를 먼저 보완하고 모든 행을 일관되게 적용한다.
5. 부분 항목은 모든 해당 완료 조건을 충족할 때만 변경한다. B08 보존/회수, C16 인수, 입력/source 계약, OS·차단 출처의 공백을 유지한다.
6. 실제 판정 결과로 집계와 주요 구현 확인 비율을 재계산한다. 부분 항목을 절반 인정한 약 86%는 공식 완료율로 넣지 않는다.
