## 작업

1. status에는 구현·CI·배포·인수의 완료 범위와 핵심 잔여 조건을 요약하고 운영 변동값은 운영 상태 문서로 연결한다.
2. roadmap의 다음 시작점을 운영자 인수·실제 운영 검증·수집 입력/보존 계약·실연동 중심으로 갱신한다.
3. 기존 P0/P1/P2·QD ID를 유지한다. 복합 항목 중 이미 끝난 배포·이전·복원 검사만 분리 표시하고 미완료 조건은 남긴다.
4. 수집 검수 활성과 접수/자동 실행 비활성을 구분하고, 운영 인수 미실행을 숨기지 않는다.
5. 과거 실패·대기 설명은 당시 결과로 연결한다. 현재 할 일처럼 반복되는 문장과 완료 작업의 재실행 요구를 정리한다.
6. 기존 4~6일·3~5일 목표를 현재 잔여 공수로 재사용하지 않는다. 필요하면 최초 계획 당시 추정으로 표시한다.
7. 상태 요약의 Git 정보는 확인 시점과 로컬 추적 참조 여부를 명시한다. 과거 goal blocked 기록을 현재 도구 상태로 단정하지 않는다.
