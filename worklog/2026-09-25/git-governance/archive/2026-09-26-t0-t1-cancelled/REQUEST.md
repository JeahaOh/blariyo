## 1. 목표

현재 Git governance 구현과 PR 상태를 대조하여, 기존 커밋 SHA를 보존하면서
`develop`에 통합할 실행 계획을 확정한다. **이번 goal은 T0 계획 확정까지만 수행한다.**

상위 목표는 준비한 변경을 `develop`에 통합하고 최종 통합 SHA의 필수 검증을 통과시키는 것이다.
상위 목표 전체를 이번 goal에서 실행하지 않는다. T0 완료를 구현·병합·운영 도입 완료로 보고하지 않는다.

기존의 포괄적인 “문서를 갱신하면서 타스크를 계속 진행” 요청 대신 이 문서의 범위와 종료 조건을 따른다.
이전 goal이 실제로 달성되지 않았다면 완료로 표시하지 않는다. goal 설정 변경·실행 여부는 별도로 확인한다.

## 5. 완료 조건

아래 조건이 모두 충족되면 T0를 완료로 보고하고 종료한다.

- [ ] PR별 확인 시각과 정확한 head/base SHA가 기록돼 있다.
- [ ] 완료·실행 중·실패·미검증·차단을 구분한 상태표가 있다.
- [ ] 지적된 3건의 원격 반영 여부와 검증 근거가 확인돼 있다.
- [ ] T1~T4의 순서·검사·통과 조건과 선행 관계가 명확하다.
- [ ] 각 단계가 추가 수정, 사용자 승인, 선행 통합, 외부 권한 중 무엇을 요구하는지 구분돼 있다.
- [ ] 이번 상위 목표에서 제외한 운영 도입 항목이 별도 목록으로 분리돼 있다.
- [ ] 다음에 실행할 task가 하나로 지정돼 있다.
- [ ] 변경 문서의 링크·diff 공백·변경 범위를 확인했고 근거 없는 완료 주장이 없다.

CI가 실행 중이면 그 상태와 실행 URL을 기록한다. 계획 확정을 위해 완료를 계속 기다리거나
재실행하지 않는다. 결과 대기 자체는 T0 미완료 사유가 아니며, 해당 통합 task의 선행 조건으로 남긴다.
반면 필수 원문이나 SHA를 확인하지 못했다면 추측으로 완료 조건을 채우지 않는다.

## 6. 실행 제한과 중단 기준

- **Scope Lock:** 위 범위 밖 작업을 수행하지 않는다. 새 요구·결함은 후속 목록에만 기록한다.
- **Done Criteria:** 시작 때 완료 조건을 확인하고, 실행 중 임의로 추가하거나 낮추지 않는다.
- **Retry Budget:** 동일 문제 해결 시도는 최초 시도를 포함해 최대 2회다.
  명령 표현이나 도구를 바꿔 같은 실패를 반복하는 것도 횟수에 포함한다.
- **Progress Guard:** 새로운 근거·산출물·해결이 없는 작업 주기가 2회 연속이면 중단한다.
  상태 문구만 바꾸거나 같은 상태를 다시 조회한 것은 진전으로 계산하지 않는다.
- **Hard Stop:** 완료, 외부 조건 차단, 사용자 판단 필요 중 하나로 판정하면 작업을 종료한다.
  중단 이유·완료한 일·필요한 다음 행동을 보고하고 자동 continuation하지 않는다.
- 사용자의 승인과 실행 환경의 허용 여부를 구분한다. 실행 전 거절은 실제 실행 실패나 hook 실패로 쓰지 않는다.
- 동일 SHA·환경·검사 조건의 기존 성공 증거는 재사용한다. 변경이나 새로운 실패 근거 없이 검사를 반복하지 않는다.
- 문서는 T0 결과를 모아 한 번에 정리한다. 상태를 여러 문서에 반복 복제하지 않는다.
- **T0 완료 후 T1을 자동 시작하지 않는다.** 다음 실행 범위를 사용자가 정한 뒤 별도 goal로 진행한다.

## 7. T0에서 확정할 후속 task 초안

아래는 실행 계획을 검토하기 위한 초안이다. 완료 조건은 실제 구현·CI와 대조해 T0에서 확정한다.

| Task | 작업 | 제안된 종료 지점 |
| --- | --- | --- |
| T1 | 기존 기능 PR #4 통합 | 기존 8개 SHA와 #3 보존, 정확한 후보 CI 통과, 승인된 병합 SHA 기록 |
| T2 | 정책·cleanup PR #5·#6 통합 | 등록 선행, checksum 수정 포함, migration·해당 CI 통과, 승인된 통합 완료 |
| T3 | harness PR #7 활성화 | 선행 CI 수정 포함, 올바른 PR 방향·task 범위·필수 gate 통과, 승인된 통합 완료 |
| T4 | PR #8·#9 후속 정리·최종 수용 | 중복 정리, 최종 develop SHA의 필수 CI·해당 복원·증거 확인과 문서 정리 |

한 번에 task 하나만 실행한다. 선행 PR이 통합되지 않았는데 대상만 바꾸거나,
실패한 gate를 무시하거나, 허용 경로·정책을 넓혀 통과시키지 않는다.
새 기능 개발이나 운영 강제가 완료 조건에 필요하다면 해당 부분을 별도 목표로 분리해 보고한다.
