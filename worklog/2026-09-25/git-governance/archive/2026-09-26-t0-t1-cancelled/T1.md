## 3. 실제 차단: T1 worktree의 hook 실행 파일 부재

- 읽기 전용 확인: T1 전용 `config.worktree`의 `core.hooksPath`가 기본 저장소 `.git/harness-hooks`를 가리킨다.
- 이 wrapper는 실행 중인 worktree의 `scripts/harness/cli.mjs`를 호출한다. H4에는 `.githooks`, `.harness`, `scripts/harness`가 추적되어 있지 않으며 T1 gitdir의 `harness-hooks.json`도 없다.
- 따라서 현재 연결로 정상 commit 검사를 수행할 준비가 되어 있지 않다. **실제 commit 실패나 자동 승인 거절이 발생한 것은 아니다.** commit 시도 전에 발견했다.
- PLAN 공통 계약의 hook 우회 금지·준비 방법 승인 조건과 새 worktree hook 설치 제외 범위가 적용된다.
- 추가 승인 요청: **T1 worktree에만 기존 고정 SHA의 검사기·정책·HARN-08 manifest를 비추적 보조 파일로 준비하고, 해당 worktree의 hook을 정상 연결한다.** 정책·허용 경로와 기본/delivery worktree·공용 hook은 변경하지 않는다. 보조 파일은 테스트 수정 commit에 포함하지 않는다.
- 구체 고정 원본, 파일 hash, 기존 설정과 wrapper 보존을 확인한 뒤 연결한다. hook 비활성화나 검사 생략으로 처리하지 않는다. 현재는 보조 파일 배치·hook 설정 변경을 실행하지 않았다.
