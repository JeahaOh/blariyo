## 수행 순서

1. 333개 경로별 변경 분류 표를 만든다: 순수 표기 변경 후보, 의미 변경, 분야 담당 인계, 유지 제품과 중첩, 미판정. 하나의 파일 안에 여러 변경이 있으면 hunk(차이 묶음)로 나눈다.
2. 각 행에 이전/이후 blob, 선택, 근거, 담당 세션을 기록한다. API/Web/Collector·배포 스크립트·문서·SQL·fixture를 폴더 이름만으로 순수 포맷으로 확정하지 않는다.
3. S02 보호 목록 및 S04의 실제 lint 결과를 받은 뒤 잔여 경로의 선택안을 적용한다. SQL/helper·browser·원문 HTML 등 다른 담당의 수정은 직접 덮어쓰지 않는다.
4. 제품·법무 문서는 의미 변경을 새로 제안하지 않는다. 필요한 표기 변경은 S11에 경로와 diff를 전달한다. JSON fixture와 raw HTML은 별도 데이터로 취급한다.
5. 333개 전체의 행 수와 누락/중복을 확인하고, 미판정은 이유와 담당자를 남긴다. 미판정인 파일을 철회 실행에 자동 포함하지 않는다.
