- 작업 ID: `AI-WORKFLOW-DESIGN`
- 요청: `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` 재검토.
- 범위: 대상 3개 파일과 연결된 AI 안내·harness·스킬의 문구 정합성, 공식 import 문법, 상대 링크.

## 발견 사항

### R1 — Medium: 검토와 수정의 경계를 단어·파일 분류로 판단하게 되어 있음

- 근거: [AGENTS.md](../../../AGENTS.md)의 12~13행.
- 확인: `정리`가 금지 조건에 포함되고, 변경 금지 대상은 `제품 파일`로 한정돼 있다.
- 영향: '이 문서를 정리해서 수정해줘' 같은 변경 요청을 검토로 오해할 수 있다. 반대로 검토 요청에서
  AI 지침·CI 설정 등 비제품 파일은 수정해도 된다는 잘못된 해석이 가능하다. 실제 오작동을 재현한 결과는 아니다.
- 최소 수정: 키워드 대신 사용자 의도로 구분한다. '검토·설계만 요청된 경우 worklog 외 파일을 변경하지 않는다.
  특정 파일의 수정·재작성 요청은 그 범위의 변경 작업으로 본다'처럼 기록 예외와 쓰기 범위를 명확히 한다.

### R2 — Medium: 필수 작업 기록과 연결된 스킬의 무변경 안내가 불일치

- 근거: `AGENTS.md:57`, `AGENTS.md:76`; [착수 스킬](../../../docs/ai/skills/blariyo-task-start/SKILL.md)의 20·25행,
  [감사 스킬](../../../docs/ai/skills/blariyo-docs-audit/SKILL.md)의 43행.
- 확인: 루트는 사용 스킬과 관계없이 모든 작업 기록을 요구하지만, 착수 스킬은 기록 생성을 조건부로 설명하고
  감사 스킬은 감사 요청만 받으면 파일을 변경하지 말라고 한다. 감사·착수 스킬의 전역 사본에도 같은 안내가 있다.
- 영향: 사용자의 명시적 기록 요구와 루트 G05를 우선하면 이번 작업은 기록할 수 있다. 다만 함께 읽는 문서가
  다른 지시를 하므로 도구·세션에 따라 기록 생략이나 불필요한 재확인이 생길 수 있다.
- 최소 수정: 프로젝트 스킬 정본에 '검토 대상은 수정하지 않으며 작업 기록은 루트 G05를 따른다'고 맞춘다.
  전역 배치본은 원본과 대조한 후 동기화하고 규칙을 별도로 복제하지 않는다.

### R3 — Medium: worktree 생성 허용 조건에 제외 설정의 선행 확인이 없음

- 근거: `AGENTS.md:71`~75; [harness 설계](../../../docs/ai/harness.md)의 68~71행; [.gitignore](../../../.gitignore).
- 확인: G04는 복잡한 작업의 `.worktree/<주제영역>/` 생성을 허용하지만 제외 설정은 아직 미적용이라고 harness에 적혀 있다.
  가상 경로 `.worktree/review-example/probe.txt`와 `.worktree/review-example/.git`에 대한
  `git check-ignore --no-index -v`는 모두 exit 1, 일치 규칙 없음이었다. 실제 파일·worktree는 생성하지 않았다.
- 영향: 규칙에 맞게 생성하더라도 기본 작업 폴더에서 미추적 경로로 나타나거나, 도구 설정에 따라 재귀 검사 범위에
  포함될 수 있다. 일반 `rg`가 기본으로 숨김 경로를 탐색한다는 뜻은 아니다.
- 최소 수정: '기본 프로젝트의 Git 추적·검색·검사 제외 설정을 확인하기 전에는 신규 worktree를 생성하지 않는다'는
  선행 조건을 G04에 연결한다. 실제 제외 설정은 후속 적용 범위이며 이번 검토에서는 변경하지 않는다.

### R4 — Medium: 브랜치 흐름을 실제 금지 행동으로 해석할 최소 조건이 없음

- 근거: `AGENTS.md:85`~86, `AGENTS.md:94`~97; `docs/ai/harness.md:77`~84.
- 확인: 흐름과 역할은 있지만 일반 작업의 main/release 직접 commit·push 허용 여부, 기본 PR 대상,
  전환 전 기존 브랜치에서 허용할 작업 범위가 지침에 명확히 정해져 있지 않다.
- 영향: '이 변경을 commit해줘'라는 요청에서 현재 release에 직접 commit해도 되는지 AI마다 판단이 달라질 수 있다.
  G08의 작업 권한만으로는 브랜치 정책 예외 여부가 정해지지 않는다.
- 최소 수정: 일반 변경의 작업 브랜치와 PR 대상, main/release 직접 반영 금지, 명시적 예외·전환 범위를 짧게 정한다.
  기존 변경을 자동으로 다른 브랜치에 이동하지 않는다. 원격 보호 적용 여부는 별도 확인 대상이다.
- 한계: 지침이 원격 강제 적용을 이미 완료했다고 주장하는 문제는 아니다. 현재 문서는 미적용 상태를 명시하고 있다.

### R5 — Low: 수정 담당 단일화 규칙에 담당 확인·인계 방법이 없음

- 근거: `AGENTS.md:68`~70; `docs/ai/harness.md:28`.
- 확인: 동시 수정 금지는 있으나 담당·진행 상태를 확인할 위치나 인계 기준은 없다.
- 영향: 두 세션이 동시에 시작하면 각각 다른 작성자가 없다고 판단할 수 있다. Git status만으로 세션 소유권을 알 수는 없다.
- 최소 수정: 기존 주제별 worklog에 담당·진행/인계/종료를 간단히 기록하거나 사용자가 지정한 작업 순서를 따르도록 한다.
  기록만으로 원자적인 잠금이 구현됐다고 주장하지 않는다. 별도 복잡한 잠금 시스템 도입은 이번 권고에 포함하지 않는다.

## 문제가 없었던 부분과 검증 범위

- 루트의 공통 규칙과 얇은 Claude·Gemini 진입 문서로 나눈 구조는 유지 가능하다.
- 3개 파일의 상대 링크 11개가 모두 존재한다. Claude·Gemini의 `@AGENTS.md`는 각각 1회이며 대상 파일이 존재한다.
- [Codex 공식 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)는 `AGENTS.md` 탐색을 설명한다.
- [Claude Code 공식 안내](https://code.claude.com/docs/en/memory)와
  [Gemini CLI 공식 안내](https://geminicli.com/docs/cli/gemini-md/)에 해당 import 문법이 있다.
- 지정된 절대 worktree 경로와 모든 작업 기록 의무는 사용자 결정이므로 재설계 대상으로 삼지 않았다.
- 문서·공식 방식 검토와 실제 도구에서 로딩·준수를 확인한 결과는 다르다. CLI 세션 기동·런타임 검증은 하지 않았다.
- 제품 source·migration·DB·외부 서비스·원격 보호 상태를 변경하거나 검증하지 않았다.

## 변경 보존과 종료

- 대상 3개와 기존 변경 파일 5개의 SHA-256을 시작·종료 시 비교했고 8개 모두 동일했다.
- 이 검토 기록의 상대 링크 6개에 누락이 없고, `git diff --check`와 신규 기록의
  `git diff --no-index --check`에서 공백 오류가 없었다.
- commit·push·merge·브랜치 전환·worktree 생성은 수행하지 않았다.

## 후속 조치

사용자의 현재 Changes 보완·정정 요청에 따라 [정정 결과](DECISIONS.md#정정-결과)에 후속 작업을 기록했다.
R1~R5의 문구·설정 보완은 위 과거 발견을 지우지 않고 해당 지침·스킬·harness에 반영했다.
문서·설정 조치는 완료했으며 링크·규칙 대응·스킬 배치본 일치·Git 제외 설정을 확인했다.
원격 보호·자동 검사·실제 AI 동작의 수용 완료를 뜻하지 않으며 미검증 범위는 정정 기록에서 구분한다.
