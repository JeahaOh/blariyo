# M0 구현 실행용 goal 프롬프트

이 문서는 **다음 구현 요청에 사용할 명령 프롬프트**다. 작성·커밋만으로 구현을 시작하지 않는다.
전체 task·순서·검증·실제 운영 잔여는 [IMPLEMENTATION-TASKS.md](IMPLEMENTATION-TASKS.md)에 있다.
기존 설계 전용 프롬프트 대신 아래 블록을 새 요청으로 전달하거나 이 파일의 실행을 명시적으로 요청한다.

```text
목표: Blariyo M0 확정 설계와 기존 구현을 대조해 남은 로컬 구현·검증을 완료하고,
실제 운영 인수에 필요한 실행 절차와 잔여 항목을 인계한다.

이 목표를 goal로 수행해줘. 다음 파일을 먼저 읽어줘.
worklog/2026-09-26/m0-implementation-plan/IMPLEMENTATION-TASKS.md

설계 보완 M0-D01~D06은 완료됐어. 설계 기준 커밋은 5ab6dc1이지만 착수 시 현행
정본과 source·migration·test·Git 상태를 다시 확인해줘. 이미 충족한 코드를 다시
만들지 말고 실제 잔여를 구현해줘. 계획·예시 코드·빈 adapter만 남기고 끝내지 마.
기존 UX/COL/OPS/CON 17개 ID를 유지하며 제품 전체를 새로 설계하지 마.

1. 시작과 작업 권한

- AGENTS.md와 docs/ai/README.md를 읽고 담당·브랜치·기존 변경·release 기준을 확인해줘.
  다른 담당과 충돌하면 그 경로의 쓰기/Git 작업을 멈추고 소유권부터 확인해줘.
  보호 브랜치 직접 변경, 임의 stash/reset/clean, 다른 작업의 프로세스/자원 종료는 금지야.
- 실제 작업일 KST의 worklog에 담당·폴더·브랜치·변경 범위·상태·완료 조건을 기록해줘.
  이전 설계·계획 기록은 연결하고 과거 결과를 소급 고치지 마.
- 앱/Collector source, 추가 migration, 실행 OpenAPI·생성 타입, 테스트, 관련 운영 도구와
  문서 변경을 수행해줘. 필요한 격리 로컬 DB/object/합성 인증·브라우저 시험도 포함해.
  대상 소유권을 확인하고 이 task가 만든 임시 자료만 생성·변경·삭제·정리해줘.
- 이 프롬프트만으로 실제 계정/secret 접근, 출처 사이트 요청, 운영 DB/R2/Drive 변경,
  Discord 전송, 서버 설치·증설, 정책 발행·활성화·배포는 실행하지 마.
  해당 외부 단계는 구체적 실행안·대상·되돌리기를 먼저 완성해 후속 인수로 남겨줘.
- stage·commit·push·merge는 이 구현 실행의 별도 사용자 지시가 있을 때만 해당 범위에서
  수행해줘. 문서 작성 세션에서 받은 commit 지시를 새 구현의 push/배포 권한으로 쓰지 마.

2. 유지할 정책과 기술 계약

- 수집 원본 HTML·본문·이미지·첨부는 최초 승인/반려 확정 후7일, 미검수는 최초 수집 후28일.
  재검수로 연장하지 않고 정각에 만료로 판정해줘. 최소 중복 hash 키는 무기한이며
  전체 URL/원문을 영구 보관하지 마. API 게시글 사본은 기존 콘텐츠 정책을 유지해줘.
- D01의 제한 함수/역할·만료 접근 차단·삭제 worker·부분 실패·사본 보호·복원을 구현해줘.
  기존 적용 migration/checksum·불변 trigger·일반 runtime 삭제 거부를 보존해줘.
- D02는 API 소유 mailbox를 batch가 DB pull/ack하는 방식이야. API/Web은 원문을 fetch하지
  않고 batch queue/item에 일반 쓰기를 하지 않아. 실제 source 설정은 안전한 읽기 전용이야.
- DB는 PostgreSQL, 이미지/첨부는 R2, DB 백업만 Drive야. D03의 선택 dump→age→SHA-256
  manifest, 03:30/15:30 KST, snapshot+7일을 유지해줘. 복원 후 원문 재생성·자동 재수집 금지야.
  선택 백업 검증→기존 full snapshot 대체→실제 회수 활성화 순서를 지켜줘.
  Drive 실다운로드·독립 복원·인증/실패 시험 전 정상 R2 백업을 중단하지 마.
- D04는 사용자 OWNER, 친구 EDITOR야. 게시물/이미지/검수 협업은 허용하고 서버·DB 관리·
  백업/복구는 사용자만 담당해. 권한을 화면 숨김만으로 구현하거나 credential을 공유하지 마.
- 검증된 출처만 M0에 포함해. 21개 adapter·과거17개 로컬 성공을 운영 통과로 간주하지 마.
  COL-REANALYZE-01의 세 출처는 대기, PGR21 추가·차단 우회 금지야.
- 청록 #00A19B를 유지하고 GA4/광고·M1·legacy 활성화·새 권한 관리 화면은 추가하지 마.
  장비/사설 연결·VM 동거·공급자 관련 다른 세션의 권고를 새 확정 정책으로 추정하지 마.

3. 수행 순서

- task list §2~5와 현행 docs/implementation-tasks/README.md의 D06 인계표를 따라줘.
- COL-04의 저장 모델·dedup·기한 검사와 OPS-01/02/04의 역할 검사를 먼저 구현해줘.
- OPS-03 선택 백업/Drive/복원 도구와 COL-04 회수 worker를 구현·격리 검증해줘.
  실제 자원 전환 없이도 합성 파일·격리 DB·전송 adapter로 실패/재개 분기를 검증해줘.
- CON-02의 mailbox/runtime·4개 API·BFF/UI·계약 사본/생성 타입과 COL-01/02 요청 통제를

  CON-01은 재활성화 결정 전 조건부 보류이며 임의 구현·활성화하지 마.

4. 검증과 증거

- task list §6의 명령과 docs/testing/README.md를 읽고 현행 package/runner를 확인해줘.
  문서 OpenAPI와 실행 사본의 현재 차이는 구현할 대상이며 생성 검사를 완화할 이유가 아니야.
- D01-T1~T7, D02-T1~T6, D03-T1~T6, D04-T1~T6의 로컬 실행 가능한 모든 분기를 검증해줘.
  실제 PostgreSQL 잠금/권한/transaction, dump·암호화·격리 복원, 브라우저가 필요한 시험을
  대역만으로 통과시키지 마. 외부 API 실패는 합성 서버로 재현하되 실수신과 구분해줘.
- 각 영역의 타입/lint·단위·실DB·Collector·browser·Docker 검사를 실행해줘.
  새 테스트가 runner에 실제 포함되는지, skip/미실행이 있는지도 확인해줘.
  관련 검사가 통과하면 같은 검사를 이유 없이 반복하지 말고 통합 검증으로 진행해줘.
- task별 코드 경로·명령·환경·기준 SHA/미커밋 hash·결과·실패/잔여를 남겨줘.
  DB/object는 응답뿐 아니라 저장 내용·개수·hash·원문 부재/보호 사본을 직접 재조회해줘.
  UI는 실제 브라우저 재현·assertion·화면 근거를 남겨줘.
- 적용된 migration 수정, assertion 약화·skip, hook/CI 해제, 비밀값 기록은 금지야.
  검증 후 관련 status/roadmap/requirements·정본·운영 안내를 실제 증거 수준으로 갱신해줘.

5. 진행·중단·완료

- Scope Lock: task list의 로컬 구현과 검증·인계 범위를 유지해줘.
- Done Criteria: task list §8을 착수 전에 실제 산출물/시험에 연결하고 마지막에 항목별 감사해줘.
- Retry Budget: 동일 문제는 최초 포함 최대2회까지 시도해줘. 원인/시도를 기록하고 명령만
  바꿔 횟수를 초기화하지 마. 미해결 항목을 숨기지 말고 필요한 입력·재개 조건을 남겨줘.
- Progress Guard: 산출물·검증 증거·차단 해소가 없는 상태를 반복하지 마. 독립적으로 가능한
  허용 작업을 진행하고, 더 진행할 수 없으면 실행 환경의 goal 차단 판정 규칙을 따라줘.
  계정값 대기는 로컬 구현 전체 차단이 아니지만 필수 로컬 시험 미실행은 완료가 아니야.
- 새 정책 충돌·범위 확대가 필요하면 영향과 구체적 선택안을 먼저 제시해줘. 답변 전에는
  그 결정에 의존하는 변경을 진행하지 마. 이미 확정한 정책을 반복 확인받지 마.
- Hard Stop: 로컬 goal의 모든 완료 조건을 충족하면 완료 처리하고 멈춰줘.
  실제 운영7일·계정/장비 인수를 끝냈다고 표현하거나 미실행 항목을 통과로 닫지 마.
  사용자 판단/환경 차단은 완료로 바꾸지 말고 적용되는 goal 도구 규칙대로 보고해줘.

최종 답변은 구현한 기능, 변경 범위, 수행한 검사와 결과, 미검증/차단,
실제 운영 인수의 입력·담당·다음 순서를 간결하게 구분해줘.
이 goal의 완료는 로컬 구현·검증·운영 인계 완료이며 M0 전체 운영 완료가 아니야.
```
