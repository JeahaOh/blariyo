## 후속 검토 — 실행 제어 조건과 테스트 반복 상한

- 요청: Scope Lock·Done Criteria·Retry Budget·Progress Guard·Hard Stop 및 최대3회 테스트 cycle 조건의 필요성 검토.
- 담당·작업 폴더·브랜치: 위와 동일. 상태: 종료. 갱신: 2026-09-27 00:03 KST.
- 범위: 이 후속 검토 기록만 추가. 앞의 시작 요청문·기존 상세 프롬프트를 변경하거나 goal을 실행하지 않았다.
- 현재 확인: 상세 프롬프트 §5에 5개 제어의 취지와 동일 문제 최초 포함2회는 있다. 무진전2회라는 수치, 테스트 수정 최대3 cycle, 중단 시4개 보고 항목은 명시되지 않았다. 짧은 시작 요청문은 상세 파일 참조에 의존한다.
- 판단: 시작 요청문에도 실행 제어를 명시하는 것이 적절하다. 같은 대상에 동일 문제2회와 테스트3 cycle을 동시에 쓰면 해석이 충돌하므로 적용 단위를 먼저 정한다.
- 권장 단위: 동일 원인의 수정 시도 최대2회, 착수 때 고정한 검증 단위별 테스트→수정→재테스트 최대3 cycle. 같은 원인이면 2회에서 먼저 멈춘다. 새 원인을 해결하는 cycle이 있더라도 검증 단위 총3회 상한은 유지한다. 파일·명령·오류명 변경으로 예산을 초기화하지 않는다.
- cycle 정의: 최초 실패를 확인한 뒤 원인 분석·수정·동일 검증 재실행까지1회. 직전 재테스트 결과를 다음 cycle의 입력으로 사용하며 이미 실행 중인 정상 검사를 기다리는 시간은 수정 시도나 실패 cycle로 세지 않는다.
- 무진전: 연속2회 작업 시도에서 검증 가능한 산출물 변경, 새 원인 증거, 실패 범위 축소, 차단 해소가 모두 없으면 중단한다. 설명·계획 재작성·동일 명령 반복은 진전이 아니다. 진전이 있어도 반복 상한을 넘기지 않는다.
- 중단 보고: 현재 실패/명령/실제 결과, 수정 시도별 내용과 cycle 수, 확인된 원인과 추정 원인의 구분, 필요한 사용자 판단·입력과 재개 조건. 사용자가 결정할 일이 없다면 없음이라고 쓰고 기술 실패를 임의 승인 요청으로 바꾸지 않는다.
- Hard Stop의 작업 규칙: 범위 전체 완료, 반복 상한·무진전 상한 도달, 실제 사용자 판단 필요 시 새 구현·수정·다른 task로의 확대를 중단하고 보고한다. 검증 실패를 goal 완료로 바꾸지 않는다.
- 도구 경계: 작업을 중단하는 조건과 goal 도구의 blocked 상태 전환 조건은 다르다. 현재 제공된 도구는 같은 진짜 차단이 최소3개 연속 goal turn에서 확인되고 독립적인 유의미한 진행이 불가능해야 blocked를 허용한다. 테스트3 cycle은 goal3 turn과 같지 않다. 프롬프트만으로 첫 실패 turn의 blocked 또는 자동 continuation의 완전 차단을 보장한다고 설명하지 않는다. 재호출돼도 실패 수정 예산을 초기화하지 않고 상태 전환 요건만 재확인한다.
- 검증: 상세 요청문의 실제 §5와 현재 goal 도구의 상태 전환 조건을 직접 대조했다. 제품 테스트·구현·Git 변경은 실행하지 않았다.
