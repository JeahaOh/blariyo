## 1. 사용자 결정과 입력

현재 결정 목록의 정본은 [로드맵 결정 항목](../../../docs/roadmap.md#5-추가로-확정할-항목)이다.

2. 사용할 Drive 계정·종류·잔여 용량·전용 폴더와 비운영 DB/R2/Drive 시험 대상 지정. 공급자 선택은 재결정하지 않는다.

5. direct 수집·Drive 계약/처리 항목 대조와 고지 검토 후 시행 시점 확정. 기존 Core 정책·연락처를 다시 입력받지 않는다.

보존 7일/28일·최소 중복 키 무기한, OWNER=사용자/EDITOR=공동 운영자, DB 백업만 Drive·이미지는 R2, 검증된 출처만 M0, Core 우선 운영은 이미 확정됐다. identity·credential·복구키는 기존 비공개 설정의 준비 여부부터 확인하며 원문을 이 기록에 남기지 않는다.

## 3. 갱신과 검증

- 변경 전 구현 산출물 `FINAL-FILES.sha256`의 231개 파일을 직접 재해시했다. 불일치 0개. manifest SHA-256: `fa8a5f22abe75cf175ce74452efddf206989661a5039dab64230aeb408cf11dd`.
- 기존 구현 검사는 재실행하지 않았다. 위 해시는 직전 검증본과의 파일 동일성 증거이며 운영 실행 증거가 아니다.
- `FILES.sha256`/`FINAL-FILES.sha256`와 과거 완료 감사는 당시 기록으로 보존한다. 이번 문서 갱신 이후의 문서 해시·검증은 이 폴더에서 따로 기록한다.
- 내용 동기화: Web mailbox·권한·보존 회수·요청 통제·선택 백업의 로컬 완료와 실제 인수를 분리, I32/P8/U0 동기화, 21개 전부 통과 조건 제거(기존 제품 결정 적용), dry-run 콘텐츠/object 무저장과 quota 쓰기 구분, operator 설정에 필수 role 반영.
- 새 잔여 구현: `scripts/local/prepare-batch-review.mjs:74`의 일괄 함수 권한 회수 후 구2개 함수만 재허용, `:96`의 구버전 고정 출력. 최신 제한 역할/함수 SQL·실제 budget 호출과 대조해 CON-02 후속/O05로 기록했다. 해당 도구 실행/실패 재현 없이 정적 차이로 판정했고 source 수정은 하지 않았다.
- 이전 manifest는 과거 결과로 유지한다. 이 작업에서 바뀐 Markdown을 이전 해시와 같다고 보고하지 않으며 source·migration·배포 도구·과거 기록은 별도 보존 검사한다.
- 문서 형식 문제 1건: 파일 끝의 추가 빈 줄을 diff 검사에서 발견→수정1회. 다른 문제와 반복 횟수를 합산하지 않는다.
- 최종 검사: 기존 관련 문서25개+신규 기록1개, 상대 링크863개·anchor313개 오류0. `git diff --check` 통과. 요구사항40개는 I32/P8/U0, 기존 task17개 유지, 신규 API4개와 retention schema의 implemented-local 상태·두 OpenAPI 사본 동일성 확인.
- 보존: 시작 기준1426개 중 문서25개만 변경, 나머지1401개 동일. 직전 구현 manifest의 Markdown 제외201개도 전부 동일. 기존 worklog·법무 본문·migration·앱·운영 도구 변경0. HEAD 동일·index 비어 있음, branch/commit/push/배포 미실행.
- 실제 테스트·브라우저·DB·운영/API/외부 계정 재실행 없음. 이번 PASS는 문서·파일 보존 검사에 한정한다.
- 검증 수치와 파일 목록은 `VALIDATION.json`, 링크 검사는 `DOCUMENT-LINK-AUDIT.json`, 이번 산출물 해시는 `FILES.sha256`에 보관한다.
