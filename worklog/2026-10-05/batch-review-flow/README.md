- 브라우저: 새 로컬 탭에서 개발 로그인 후 `/admin/batch`의 목록·검수 전 항목을 조회했다. 수집 완료/검수 전 상태에서 검수 시작만 활성, 승인·반려·초안 만들기 비활성인 실제 화면을 확인했다. 수집·승인·반려·초안 생성·발행 버튼은 실행하지 않았다.
- 현행 순서: 수집 완료 항목 선택 → 검수 시작 → 원문/수집 본문·이미지·링크 대조 → 승인 또는 반려 → 승인 항목의 제목 확인 및 게시글 초안 만들기 → 게시글 관리에서 열기 → 편집·발행. 검수 시작은 자동 품질 검사 실행이 아니라 검수 상태 전환이다. 수집 상태와 검수 상태는 별개이며 초안 생성도 공개 발행이 아니다.
- 혼동 근거: 상태 두 종류와 모든 단계의 버튼을 동시에 표시, 비활성 사유 설명 부족, 출처 검색에 내부 key 요구, 검수 중 반려만 주 작업 CSS 적용·승인은 보조 모양, 원문을 열어 확인했는지와 무관하게 FETCHED면 단계표의 원문 확인 완료 표시.
- 제안: 업무 기준 목록(검수 대기/검수 중/초안 생성 가능/초안 연결)과 현재 단계 설명·다음 버튼을 우선 배치. 승인 의미와 발행 위치를 명시하고 본문 확인 후 판단하도록 화면 순서 정리. 정책상 승인·초안·발행 분리는 유지하는 개선안을 우선 검토한다. 제안은 구현 완료나 제품 결정으로 기록하지 않는다.
- 검증: 기획의 사람 검수·별도 발행 흐름과 source의 상태 조건을 대조하고 실제 로컬 화면에서 확인. 운영 화면 검증·자동 회귀 시험은 이번 안내에서 수행하지 않음.
