수집 결과를 전용 Discord 채널에 글별 헤드와 문장·이미지 스레드로 보내고, 등록 검수자의 반응을 관리자 화면과 같은 검수·발행 명령으로 처리합니다. 04:30·15:30 수집 이후 메시지를 준비하며, 07:30·17:00에 무승인 글을 다시 확인하고 준비 완료 후 48시간이 지난 글을 반려합니다.

- 관리자 처리 우선권, 본문 제외, 권한·버전·원문 재확인, 승인/발행 단계별 중복 방지를 적용했습니다.
- Discord 삭제는 DB commit·연결 반환 이후 비동기로 실행하고 삭제만 재시도합니다. 두 번 이상 실패하면 스레드에 실제 처리 상태를 남깁니다.
- V014와 API 전용 DB 권한, 별도 Java REST worker·복구 예약, 로컬·운영 실행 도구를 추가했습니다. 기능은 기본 비활성이며 실제 credential은 Git에서 제외했습니다.

검증: 품질 검사 14개(CI 16·공통 단위 88 포함), API 통합 149건, Docker 브라우저 88건, Collector 304건과 DB readback 20건 통과. 실제 로컬 Discord 전송(문장 2·이미지 1)·관리자 반려·삭제 재시도 완료를 확인했습니다. 최종 입력의 검증 receipt와 운영 반영 증거는 구현 worklog에 기록합니다.
