## 결론과 확실성

- **확인:** 운영 오전 미결정 52건 전부 오후에 재확인됐다. 1건 반려, 51건 UNAPPROVED. 오전 글을 대상에서 제외하는 오류는 확인되지 않았다.
- **확인:** 개발 채널의 승인 7건은 로컬에 발행됐다. 운영 승인 8건과 별도이며 로컬 승인 글을 운영으로 복제하는 흐름이 아니다.
- **확인:** 운영 오후 작업은 통신 오류로 중단됐다가 재개됐다. 최종 서비스 성공만으로 실행 중 오류가 없었다고 판단하면 안 된다.
- **미확정:** 현재 운영 헤드 👍 14건이 오후 조회 당시에도 👍 단독이었는지는 남아 있는 자료로 복원할 수 없다. 다음 배치 대기 구조만으로 사용자 클릭이 늦었다고 단정할 수 없다.
- **확인된 진단 한계:** 무승인 판정 시 반응 상세를 지우므로 당시 무반응/양쪽 반응을 구분할 증거가 없다. 현재 반응과 당시 UNAPPROVED의 차이를 설명하는 원인은 확정하지 못했다.

## 현재 Discord 읽기 전용 확인

- 최초 점검에서 운영 남은 헤드 126개를 DB와 대조했고, 19개 헤드에 등록 검수자 반응이 있었다. 👍 14, ❌ 5; 모두 READY/UNAPPROVED. 사용자 목록 GET으로 봇 기본 반응을 제외했다.
- 이번 재검토에서 운영 오전 미결정 51개 스레드의 DB 등록 본문 message ID를 GET 결과와 전수 대조했다. 51/51 스레드의 대상 본문 모두 조회, 누락 0, 봇 기본 반응 외 추가 반응이 있는 스레드 0.
- 따라서 오전 잔여 51건은 현재 본문에만 사람이 반응한 경우도 아니다. 오후 71건의 본문은 이번 전수 조회 대상이 아니며, 👍 14건의 최종 발행 가능 여부를 재판정하지 않았다.
- Discord GET의 현재 반응에는 실제 클릭 시각이 없다. 과거에 반응을 추가/제거한 이력까지 입증하지 않는다. 429 발생 시 retry_after를 준수하도록 조회했다.

## 운영 실행 중 오류와 복구

- 17:00:00 scan.service는 DISCORD_WORKER_ALREADY_RUNNING으로 종료했다. 중복 실행 잠금 때문에 생략된 것이며 이 서비스의 exit 0은 실제 검수 완료 증거가 아니다.
- maintenance가 17:01:11 검수를 시작했다.
- 17:04:04 DISCORD_HTTP_UNAVAILABLE / DISCORD_WORKER_DEFERRED로 실패했다. 이 로그에는 실패 endpoint가 없어 Discord/API 중 어느 요청의 통신 실패인지 확정하지 않는다.
- 이후 maintenance가 재개해 DB scan은 17:08:51 COMPLETED, 17:08:55 마지막 프로세스는 UNAPPROVED 32건 처리 결과를 기록했다. 이 32는 마지막 프로세스 처리량이고 전체 회차 집계 123건과 다르다.
- 운영 collector.jar SHA-256은 배포 manifest와 일치했고 sourceSha는 f8067abd757d404599d6f00e00239a7ab3afff43이었다.

## 코드·정책 대조 및 권장 후속

- [대상 조회](../../../apps/api/src/persistence/discord-review.repository.ts): READY·미처리·DISCORD 권한이고 회차 cutoff 이전이면 수집 회차와 무관하게 재확인한다. cursor는 해당 회차의 진행 위치다.
- [판정](../../../apps/api/src/features/collection/discord-review-policy.ts): 헤드에 등록 검수자 👍 단독이면 승인, ❌ 단독이면 반려. 양쪽/무반응은 UNAPPROVED다. 본문 반응은 제외 여부에 사용한다.
- [관찰 종료](../../../apps/api/src/persistence/discord-review.repository.ts): finishObservation에서 결과/시각/회차 집계를 남기고 observation_chunks를 비운다. 이 때문에 무반응과 상충 반응의 사후 구분이 안 된다.
- [현행 설계](../../../docs/system-design/10-discord-review.md): 정시 07:30/17:00, maintenance는 미완료 회차만 복구하고 완료 회차를 다시 판정하지 않는다.
- 우선 권장: 미결정 판정에도 환경·회차·검수번호·헤드 사람 반응 수·무반응/상충 구분·읽기 성공 여부의 최소 근거를 보존하는 계약을 검토한다. 사용자 ID/본문 원문을 장기 보존할 필요는 없다. 이 변경은 이번 요청에서 구현하지 않았다.
- 현재 👍 14건을 배치 이후 추적하면 현행 상태의 처리 여부는 확인할 수 있으나 과거 반응 시각을 소급 증명하지는 못한다.
