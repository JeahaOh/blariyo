- 담당: Codex / 상태: 종료(추가 식별 정보 대기) / 갱신: 2026-10-09 KST.
- 작업 폴더: `/Volumes/MicroVault/iCloudDrive/git/private/blariyo` / 브랜치: `feature/discord-review`.
- 요청: 오후 검수는 늦었을 수 있지만 오전 승인 8건은 사용자 기억과 불일치한다는 이의 확인.
- 범위: 운영 명령 판정 증거 SELECT, 로컬 승인 글과 운영 처리 글의 canonical_url 대조, 이 후속 기록 작성. 이전 [재검토](README.md)의 사실은 소급 변경하지 않는다.

## 확인·정정

- 운영 DB의 오전 APPROVE_PUBLISH/PUBLISHED 8건은 시스템이 처리한 수량이다. 사용자가 오전에 실제 승인 반응을 누른 수량이 8건뿐이라는 증거가 아니다.
- 오전 명령 24건은 DISCORD 승인 8건/반려 16건. 각각 reviewer_ids 1명, participants 1명으로 저장됐다. SYSTEM 만료 반려로 집계된 것은 아니다.
- 승인 번호: #57/#58/#61/#62/#63/#64/#65/#69.
- 오전 반려 번호: #51/#52/#53/#55/#56/#60/#67/#68/#70/#71/#72/#73/#74/#75/#76/#77. 오후 반려 #54는 별도다.
- 승인·반려 명령 evidence도 scanId/deliveryId/observedAt/participants만 보관하고 당시 헤드 emoji별 사용자/반응 수를 보관하지 않는다. 앞선 기록에서 설명한 무승인 이외에도 실제 반려 반응 자체를 사후 재검증할 수 없는 한계가 있다.
- 판정 소스상 등록 검수자 헤드 ❌ 단독은 반려다. 다만 반려 결과와 reviewer_ids 저장만으로 당시 Discord 원본 반응이 올바르게 관찰됐음을 독립 검증할 수는 없다. 시스템 오판이 확인된 것은 아니며 정상 판정이라고 확정하지도 않는다.

- 운영·로컬 읽기 전용 DB 대조, 소스 확인, 작업 전후 Git 상태 및 whitespace 확인.
