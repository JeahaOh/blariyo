# 수집처별 복수 게시판 관리 검토

- 담당: Codex / 상태: 종료 / 작업일: 2026-10-09 KST.
- 폴더: `/Volumes/MicroVault/iCloudDrive/git/private/blariyo` / 브랜치: `feature/discord-review`.
- 요청: 사이트마다 수집할 게시판이 달라지는 경우의 구성 방안 설명.
- 범위: 현재 planning/system-design/source 확인과 설계 제안. 기존 정본·코드·DB·실행 설정 변경 없음.
- 확인: source JSON은 charts map과 defaultChart를 가지고 CLI는 --chart로 한 항목을 선택한다. 현재 예제 구성은 목록 수집처당 URL 1개이며 DETAIL_ONLY 2곳은 목록이 없다. 로컬/운영 예약 실행기는 source당 선택된 기본 목록 1개를 처리하며 여러 게시판을 자동 순회하지 않는다.
- 확인: 관리 화면 sourceUrl은 표시 메타데이터로 수집 대상 편집 기능이 아니다. 배치는 charts[chart]에서 실제 URL을 읽는다.
- 추천(미확정): 수집처와 수집 게시판을 1:N으로 나누고 수집 게시판에 안정된 키·이름·목록 URL·수집 여부를 둔다. 단일 대상 URL 수정과 복수 게시판 추가/중지를 같은 구조로 관리한다. 기존 source별 수집 여부는 상위 전체 중지, 자동 발행 정책은 현행 source별 유지. 게시판별 발행 차이가 필요할 때만 별도 변경을 검토한다.
- 추천 화면: 수집처 행 아래 게시판 목록, 게시판 행마다 URL/수집 여부/저장. 동일 사이트 parser를 재사용할 수 있는지 게시판별 목록/상세 구조와 허용 경로를 검증한다.
- 추천 실행: DB에서 수집처 ON 및 게시판 ON 대상을 읽고 사이트 내 게시판을 순차 처리한다. 요청 간격·일일 예산은 사이트 단위로 공유하고 실패를 게시판 단위로 기록한다. 사이트 접근 차단·공유 요청 예산/DB/소유권 실패에는 기존 사이트 중단을 적용한다. 글 중복 식별은 해당 사이트의 게시판 범위·고유 글 ID 의미를 보존한다.
- 검증: 현행 source/CLI/예약 runner 대조, git diff --check. 구현/실제 수집/브라우저 테스트는 수행하지 않았다.
- 미확정: 실제 대상 게시판 URL 목록, 게시판별 발행 정책 필요 여부. 실제 주소를 제안 예시에 추측해 넣지 않는다.
