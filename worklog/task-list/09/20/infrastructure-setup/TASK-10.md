# TASK-10 — 공개 연락처 검사 확인과 M0 정책 발행 검토 준비

- 기록일: 2026-09-20, KST
- 이전 기록: [공개 연락처 입력 준비](TASK-09.md)
- 상태: **공개 연락처 로컬 검사 사용자 PASS. 정책 검토표 준비, 본문 확정·DB 발행·앱 배포 미완료**

## 1. 사용자 실행 증거

사용자가 `prepare-blariyo-public-config.cjs` 기본 검사 결과를 제공했다.

- 기존 `~/.config/blariyo/public-contact.json` 유지, 본인 소유·권한 600·항목 형식 PASS
- 실제 앱 `LEGAL_CONFIG` 파서로 필수 공개 연락처 5개 형식 PASS
- 이메일 수신·담당자 적정성·정책 확정/발행·앱 기동은 미검증

에이전트가 해당 파일의 실값을 다시 읽거나 검사를 재실행한 것으로 기록하지 않는다.
연락처·개인정보 원문을 저장소에 복사하지 않았다.

## 2. 다음 단계 준비

[M0 정책 발행 전 검토표](../../../../../deploy/application/policy-release-review.md)에
법무 초안의 이번 적용 범위, 후속 기능, 실제 처리 사업자·시행일·보유 기간 등 남은 확인을 정리했다.
제품 기획, 법무 정본, 보안·운영 설계와 실제 정책 기동 검사 코드를 대조했다.

- production Core는 유효한 약관·개인정보처리방침 두 종류가 필요하다.
- 법무 초안의 로그 90일 묶음과 운영 설계의 일반 로그 14일/보안 로그 90일 분리 사이에
  대조가 필요하다. 어느 쪽도 실제 서버 보존 검증으로 취급하지 않았다.
- 국외이전 검토는 소셜·GA4뿐 아니라 실제 쓰는 인프라·이메일의 처리 흐름도 확인해야 한다.
- 실제 이메일 서비스 이름과 개인용/업무용 여부를 사용자에게 질문했다. 이메일 주소는 요청하지 않았다.
- 법무 초안의 미확정 항목을 제거하거나 처리 근거·계약 법인·시행일을 추정하지 않았다.

## 3. 변경·검증 경계

검토표, 앱 준비 README의 연결, 이 기록과 task 색인을 작성했다.
변경 문서의 상대 파일 링크 36개 존재, `git diff --check`, 작업 전후 Git 상태를 확인했다.
현재 단계는 문서와 source 대조이며 별도의 앱 테스트 통과나 법률 적합성 확인을 주장하지 않는다.

사용자 답변 후 실제 운영 정보에 맞는 공개 본문을 검토한다. 정책 DB 변경, 서버 배포,
네트워크 호출, commit·push는 수행하지 않았다. 기존 사용자 변경과 과거 작업 기록은 보존했다.
