## 1. 사용자 요청과 반영

사용자는 `blariyo.com` 도메인 메일을 Gmail로 받는다고 확인했고, 기존 연락처 검사를 반복하지
않고 진행하도록 요청했다. 이어 작은 사이트에 맞게 간결하게 쓰되 운영자의 책임 범위를
명확하게 정하도록 요청했다. 실제 메일 주소와 개인정보는 기록하지 않는다.

## 2. 준비한 산출물

- [M0 공개 초안](../../../../../docs/legal/m0-core/README.md): 이용약관 8개 항목,
  개인정보처리방침 6개 항목, 권리 요청·쿠키 안내.
- 약관에 특정 게시 일정·영구 보관·무중단 제공을 별도 약정 없이 보장하지 않는다는 내용,
  귀책사유 없는 장애·외부 사이트 책임의 구분, 법령에 따른 손해배상 범위를 반영했다.
- 전체 면책, 손해배상 상한 0원, 출처 표시·신고 후 삭제만으로 책임이 없어진다는 표현은 넣지 않았다.
- 전체 법무 원문은 유지하며 M0 공개본 후보를 연결했다. 개인정보 원문의 일반 로그 14일·보안
  기록 90일 구분을 운영 설계에 맞추고, M0 인프라·메일의 실제 국외이전 확인 항목을 명시했다.
  2026-09-11 시행 규정의 오래된 '시행 예정' 문구를 갱신했다.
- [생성 도구](../../../../../deploy/application/prepare-policy-review.cjs)는 기존 연락처 5개를
  읽어 새 로컬 검토 폴더에 HTML 5개를 생성한다. 폴더 700·파일 600, 기존 파일 보존,
  외부 리소스 로드 차단, 입력값 콘솔 비출력이다.
- 진입점: `/Users/zeaha/task_list/prepare-blariyo-policy-review.cjs --open`

시행일·계약 법인·국가·처리 근거를 추정하지 않았다. Gmail 사용 확인과 Workspace 가입 유형·
전달 경유 여부는 구분한다. 이 도구는 발행 artifact나 체크섬·시행 시각을 생성하지 않는다.

## 3. 검증

[격리 검사](../../../../../deploy/application/test-policy-review.cjs)를 합성 연락처로 실행했다.

- 새 폴더·파일 권한, 연락처 HTML 이스케이프, 내부 링크 대상, 기존 입력·검토본 보존 PASS
- 부적절한 파일 권한·symlink·알 수 없는 템플릿 항목 거부 PASS
- 실제 앱 production 파서의 미확정 정책 본문 발행 거부 PASS
- Node 구문 검사·CLI help PASS
- 현재 공식 법령 원문을 조회해 책임 제한·개인정보 고지 관련 기준 확인. 근거 링크는 초안 README에 수록
- 문서 상대 파일 링크·공백 및 `git diff --check` 확인

Playwright로 PC·모바일 렌더링을 시도했으나 macOS sandbox의 Mach port 권한 오류로 Chromium이
실행 전에 종료됐다. **브라우저 화면·가로 넘침·런타임 외부 요청 0건은 미검증**이며 통과로 기록하지
않는다. CSP와 HTML은 source 수준에서 확인했다. 실제 사용자 연락처로 생성한 결과도 아직 미검증이다.

## 4. 다음 실행


기존 연락처 파일로 개인 PC에 새 검토본을 만들고 연다. 본문·시행일과 표시된 운영 확인 사항을
검토한 뒤 정책 발행을 준비한다. 연락처를 다시 입력할 필요는 없다.

실제 비공개 연락처 파일, 서버·DB·Cloudflare 설정은 변경하지 않았다. 정책 발행·배포·commit·push는
수행하지 않았고 기존 사용자 변경을 보존했다. 법률 적합성이나 개별 분쟁의 면책을 확정하지 않는다.
