# M0 Core 관리자 마감 — 실행 기록

## 범위와 기준선

- 요청: `docs/implementation/m0-interim-2026-09-23/next-plan.md`의 P0-01~04. 기존 API/DB/편집기 사용, 수집 신규 기능·자동 승인/발행·운영 변경 제외.
- 시작: `main...origin/main`, tracked/untracked 변경 없음. 과거 보고서는 현재 PASS로 승계하지 않음.

## 구현 중 발견

- 화면 업로드 후 글당 이미지 상한20과 현행 계약200 불일치:200으로 정정. 업로드 요청10개/100MiB·파일10MiB는 유지.
- 저장 응답 유실 뒤 사용자가 제목을 바꾸면 새 멱등 키로 초안을 중복 생성할 여지: 결과 불확실 상태에서 입력과 원래 요청을 잠그고 동일 키·본문으로 복구.
- 실제 운영자 Access 인증과 사용성 인수는 로컬 합성 인증·개발자 브라우저와 별도. 아직 수행하지 않음.

검증은 완료 시 [결과 보고서](RESULTS.md)에 기록한다. 이 단계는 진행 중이며 전체 완료가 아니다.

## 현재 작업 트리에서 재개한 검증 — 2026-09-23

앞 절은 이전 착수 기록으로 보존한다. 이번 재개 시 `main...origin/main`에 관리자 Vue·planning·개발
명세·render/browser test 5개 수정과 `admin-workflow.test.ts`, 이 폴더의 미추적 파일이 있었다.
기존 변경을 기준선으로 보존하고 현재 코드·실행 상태를 다시 확인했다.

- P0-01: 기존 화면 계약 보강은 있었지만 검토물 링크의 대상 파일과 실행 근거가 없었다. 화면 검토물·결과를 작성하고 D04~06의 시점/검증 경계를 정정했다.
- P0-02/03: 기존 구현을 검증했다. 실제 추가 수정은 상태 필터에서 빠진 글의 모바일 목록 복귀 포커스다. 선택 행이 없으면 `새 초안`으로 복귀한다.
- Node20 기본 환경에서 첫 build가 실패했다. `.nvmrc`의 Node24.18.0으로 전환 후 통과했다.
- 첫 브라우저 검사: 12건 업무는 통과했지만 테스트 Origin 누락과 이전 상태 문구 기대값이 실패했다. 정상 Origin과 한국어 상태로 정정했다. 이후 모바일 필터/포커스 결함을 수정하고 최종 21개 전체 통과했다.
- 전체 Nest 검사에서 Java 환경 미설정, direct parser fixture와 legacy payload 차이, V008 추가 전 rollback 기대가 드러났다. JDK25를 지정하고 첨부가 빈 fixture만 legacy로 전달하며 V007 rollback 보호를 별도로 검사하도록 보강했다.
- 작업 분리는 서브에이전트 1개만 사용했다. 문서 충돌 두 파일과 이후 독립된 회귀 테스트 수리만 지정하고 재위임하지 않았다.
- 현재 3000 서버를 현재 빌드로 재시작했다. 기존 개발 글은 조회만 했고 12건 업무는 무작위 격리 DB/임시 object에서 수행했다.

최종 상태·명령·수량·잔여는 [결과](RESULTS.md)를 따른다. 운영자 수동 인수나 배포로 확대하지 않는다.
